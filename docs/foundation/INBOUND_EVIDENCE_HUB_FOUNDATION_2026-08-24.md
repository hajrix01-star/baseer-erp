# Baseer ERP — أساس البريد والأدلة

**الحالة:** موصل Gmail للقراءة فقط منفذ برمجياً؛ يتطلب إعداد مشروع Google ومفاتيح الخادم قبل تفعيله حياً. التحليل الذكي ما زال غير مفعّل.
**الاسم الظاهر:** البريد والأدلة
**الاسم التقني:** Inbound Evidence Hub

## الغرض

هذا المركز يجمع لاحقاً الأدلة الواردة من Gmail ثم مصادر منفصلة مثل رسائل SMS المصرفية وTelegram. وهو ليس برنامج بريد تقليدياً ولا نظاماً مالياً بديلاً: وظيفته فرز الدليل، تلخيصه لاحقاً، واقتراح روابطه فقط.

## حدود المرحلة المنفذة

- الوصول للمالك فقط. لا يظهر الموديول لغير المالك، ويتحقق الخادم من ملكية المستأجر في كل طلب.
- Labels داخلية قابلة للتعديل، ويمكن للرسالة مستقبلاً أن تحمل أكثر من Label.
- قواعد فرز بسيطة قابلة للتعديل: المرسل/النطاق، عنوان الرسالة، ووجود مرفق، ثم Label مستهدف وأولوية وحالة تفعيل.
- Labels الأساسية المحمية: يحتاج مراجعتي، فواتير ومصروفات، تحويلات واردة، تنبيهات مهمة، مكتمل.
- RLS وFORCE RLS على كل جداول الموديول، مع tenant-only composite foreign key وسجل تدقيق وidempotency receipts.

## Gmail والمرفقات المنفذة

- يبدأ المالك التفويض من الواجهة، ويمر Authorization Code + PKCE وstate أحادي الاستخدام قصير العمر عبر الخادم فقط.
- النطاق الوحيد هو `gmail.readonly`. لا ينقل Baseer رسالة Gmail ولا يحذفها ولا يضيف لها Label.
- يقرأ الموصل الرسائل والمرفقات التي تعلنها Gmail مباشرة؛ لا يحتاج `mailparser` أو `PostalMime` لأن Gmail API يقدم أجزاء MIME ومعرفات المرفقات بشكل منظم.
- يسحب PDF وJPEG وPNG وTXT وCSV المدعومة، ويتحقق من الحجم والنوع الفعلي والبصمة، ثم يخزنها مشفرة محلياً. لا تصبح قابلة للتنزيل قبل الفحص؛ في الإنتاج بلا ماسح ملفات تظل `QUARANTINED`.
- المرفق محفوظ كدليل مع معرف Gmail، بصمة SHA-256، نوع الملف، وقت السحب وحالة الفحص. لا يُفسر كمحتوى موثوق أو حقيقة مالية.

## ما لا تنفذه هذه المرحلة

- لا Gmail Labels أو نقل أي رسالة، ولا مزامنة كتابة إلى Gmail.
- لا تحليل ذكاء أو استخراج حقول أو OCR تقليدي؛ سحب المرفق وقراءته الآمنة يسبقان محلل المستندات البصري الموحد.
- لا إنشاء فاتورة، سند، قيد، تحصيل، صرف أو مطابقة مالية تلقائياً.
- لا تغيير في الشركة النشطة: المركز ملك للمالك على مستوى المستأجر، لا صندوق بريد مكرر لكل شركة.

## قرار المصدر والفرز

عند تفعيل Gmail لاحقاً يبدأ الموصل بقراءة فقط. تطبق Labels وقواعد Baseer داخلياً. أي مزامنة اختيارية إلى Gmail Labels تحتاج موافقة منفصلة وصلاحية كتابة ضيقة؛ لا تُفترض من هذا الأساس.

## المسار اللاحق المعتمد

```text
Gmail read-only / SMS / Telegram
  -> بوابة ملف آمنة + بصمة ومنع تكرار
  -> محلل مستندات بصري موحد (استخراج + فهم + تصنيف)
  -> تحقق خادمي حتمي + أدلة لكل حقل
  -> اقتراح ربط فقط
  -> مراجعة المالك/المخول
  -> أمر مالي قائم ومدقق عند الحاجة
```

المحلل البصري لا يصبح حقيقة مالية ولا يحمل أدوات أو SQL أو صلاحية تنفيذ. كل محتوى وارد يعد بيانات غير موثوقة، ويُفحص ضد حقن التعليمات.

## معايير القبول للمرحلة التالية

قبل التفعيل الحي: أضف redirect URI إلى مشروع Google Cloud، فعّل Gmail API، ضع متغيرات `BASEER_GMAIL_*` ومفاتيح تشفير 32-byte base64 في الخادم فقط، واضبط ماسح الملفات للإنتاج. الموصل الحالي يسحب نافذة يدوية صغيرة بأمان؛ قبل الجدولة الدورية يجب إضافة worker موزع/lease وincremental History API مع fallback عند انتهاء history ID.

## محلل المستندات البصري الموحد

المرفق الآمن فقط يسير في خطوة واحدة: **فحص الملف وتخزينه المشفر → نداء بصري واحد للذكاء لا يملك أدوات → JSON منظم صارم → تحقق خادمي → نتيجة تحتاج مراجعة**. لا توجد طبقة OCR تقليدية مستقلة في الإصدار الأول. يدعم PDF وJPEG وPNG وTXT وCSV بعد فحص النوع والحجم والبصمة والماسح.

يحفظ Baseer النسخة المنظمة المتحققة فقط مع بصمة المرفق، نسخة المهارة/السياسة/المخطط، النموذج، checksum، وقت الطلب وتحذيرات التحقق. لا يحفظ prompt أو transcript خاماً أو أسرار الموفر. النتيجة append-only؛ إعادة التحليل تنشئ نسخة لاحقة بدلاً من تعديل التاريخ.

الذكاء لا ينشئ قيداً أو فاتورة أو سنداً أو دفعة ولا يربط شركة أو مورداً تلقائياً. أي مبلغ أو تصنيف أو مرجع هو اقتراح دليل يراجعه الإنسان داخل مسار المالية القائم. كل نص في الرسالة أو المستند بيانات غير موثوقة ولا يُعامل كتوجيه.

قبل التفعيل الحي يلزم: قرار خصوصية/منطقة/تكلفة، موفر OpenAI-compatible نشط ومراجع من الإدارة، والمفتاح الخادمي `BASEER_INBOUND_DOCUMENT_INTELLIGENCE_ENABLED=true`. لا يوضع مفتاح AI في متغيرات البريد أو المتصفح. تتميز أخطاء الموفر وحالات انخفاض الثقة أو تعارض المبالغ أو حقن التعليمات بأنها `NEEDS_REVIEW`.
