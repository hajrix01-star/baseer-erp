# معيار واجهة بصير والفلاتر الموحدة

**الحالة:** معتمد
**التاريخ:** 2026-08-16
**النطاق:** جميع واجهات Baseer ERP الجديدة أو المعدّلة.

## الهدف

تستخدم بصير لغة واجهة واحدة قابلة للتوسع: مكوّنات مركزية، أرقام قابلة للمقارنة، وفلاتر لا تغيّر معنى البيانات. لا تنشئ أي واجهة جديدة زرًا أو بطاقة أو جدولًا أو فلترًا محليًا إذا كان المكوّن المركزي يغطي الحاجة.

## قواعد العرض المختصرة

- عنوان القسم يعرّف المكان فقط؛ لا نكرر في كل صفحة شرحًا عامًا عن الخادم أو الصلاحيات أو طريقة النظام.
- تبقى الرسائل المهمة فقط: الحالة الفارغة، خطأ قابل للتصرف، تحذير غير قابل للعكس، نقص البيانات، أو مساعدة لا يمكن استنتاجها من الحقول.
- تسميات الحقول والأزرار مباشرة وقصيرة. المساعدة التفصيلية تكون في تلميح أو صفحة مساعدة عند الحاجة، لا في رأس كل قسم.
- اتجاه العربية RTL والإنجليزية LTR. النصوص بمحاذاة بداية القراءة، الأرقام بمحاذاة النهاية وبأرقام tabular.
- المبالغ تعرض أعدادًا صحيحة ما لم يوجد كسر فعلي؛ عند وجوده تستخدم خانة عشرية واحدة. النسب المئوية لها تنسيقها الخاص.

## المكوّنات المركزية

| الحاجة | المكوّن/المعيار |
| --- | --- |
| زر | `BaseerButton` أو أنماطه المركزية: أساسي، ثانوي، خطر، أيقونة. |
| بطاقة | `BaseerCard` مع حالات padding وtone المعتمدة. |
| جدول | `DataTable`؛ لا عمود إجراءات افتراضيًا. يفتح رقم السجل أو صفه تفاصيله، وتعيش الإجراءات داخل التفاصيل. |
| نافذة | معيار `WEB_DIALOG_INTERACTION_STANDARD.md`: زر × في الرأس **أو** زر إلغاء في التذييل، لا الاثنين؛ حفظ واحد في التذييل. |
| فترة زمنية | `BaseerPeriodFilter` من `apps/web/src/baseer-period-filter.tsx`. |

لا يقرر المكوّن المرئي أي صلاحية؛ صلاحية البيانات والفعل تفحص خادميًا في كل طلب.

## الفلتر الزمني المركزي

الفلتر نافذة تقويم واحدة تستخدم `Asia/Riyadh`: يختار المستخدم نوع الفترة من رأس النافذة، ثم يتحول محتواها إلى شبكة الأيام أو الأشهر أو الأرباع أو السنوات أو النطاق. يعيد دائمًا نطاقًا صريحًا `from` و`to` إلى الـAPI؛ وعند اختيار أشهر غير متجاورة يرسل قائمة الأشهر الصريحة أيضًا. خياراته:

- **اليوم:** تاريخ الرياض الحالي.
- **شهر:** شهر وسنة يحددهما المستخدم من المنتقي.
- **أشهر متعددة:** يضيف المستخدم أشهرًا صريحة، حتى لو لم تكن متجاورة مثل أبريل ويونيو؛ الخادم لا يدخل الأشهر الواقعة بينهما.
- **ربع سنة:** ربع وسنة يحددهما المستخدم.
- **سنة:** سنة كاملة يحددها المستخدم.
- **نطاق:** تاريخ بداية ونهاية يختارهما المستخدم.

يقبل كل قسم مجموعة الخيارات التي تناسب مصدره. المبيعات والتقارير والتقويم تستخدم المجموعة كاملة. الإعدادات، المستخدمون، والأدوار لا تعرض فلترًا زمنيًا لأنها ليست تقارير زمنية؛ الشركة الحالية تبقى سياقًا عالميًا من الجلسة ولا تتكرر كفلتر داخل كل صفحة.

النطاق يصف العرض فقط ولا يغير تاريخ عملية مالية أو يقبل تاريخًا مستقبليًا. قواعد تاريخ العمل والتحقق المحاسبي تبقى في الخادم.

## معيار الإغلاق لكل قسم

قبل إغلاق أي واجهة أو موديول:

1. يستخدم المكوّنات المركزية بدل إنشاء نسخة محلية منها.
2. يستخدم `BaseerPeriodFilter` إذا كان يعرض بيانات زمنية، أو يوثق سبب عدم وجود فلتر.
3. لا يحتوي رأسه شرحًا عامًا مكررًا.
4. يراعي RTL/LTR، الجوال، لوحة المفاتيح، ومحاذاة الأرقام.
5. يجتاز فحص TypeScript وبناء الواجهة وميزانية الحزمة.

## حالة التحويل الحالية

تم توصيل فلتر الفترة الموحد بالمبيعات اليومية وتقويم مركز القيادة. الجداول المركزية متاحة في المبيعات والإدارة، والكروت والأزرار المركزية هي المسار الإلزامي للأعمال الجديدة. تحويل الواجهات القديمة المتبقية تدريجي؛ لا تدّعي هذه الوثيقة أنها استبدلت كل CSS تاريخي في دفعة واحدة.
