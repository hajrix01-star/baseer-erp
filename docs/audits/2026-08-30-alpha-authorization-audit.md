# تدقيق فريق ألفا للصلاحيات والجلسات — 2026-08-30

## النطاق

فحص تسجيل الدخول والجلسات وسياق الشركة وكتالوج الصلاحيات وحراسة مسارات الواجهة وواجهات API. لا تُعد الواجهة مصدراً للقرار؛ يظل `CompanyContextService` وقاعدة البيانات السلطة النهائية.

## السبب المؤكد لرسائل المنع

حساب `mohammad.alhajri@gmail.com` يملك تعيين **مالك المستأجر** فعالاً. لم تكن الرسائل التي ظهرت عند إنشاء مسير أو عملية مالية ناتجة من نقص ملكية الحساب: شركتا **ARZ** و**مشويات المعلم الشامي** كانتا مقفلتين لوضع مراجعة الترحيل. هذا القفل يمنع التغييرات التشغيلية عمداً حتى للمالك.

عُدلت دلالة هذه الحالة من `403` إلى `409 Conflict` كي لا تظهر للمستخدم كأنها مشكلة صلاحية. تبقى القراءة والتدقيق متاحين، وتظهر العمليات غير المتحولة صراحة ضمن السياسة.

## الإصلاحات المنفذة

| الخلل | المعالجة |
|---|---|
| صلاحيات واجهة قديمة بعد تجديد access token أو تبديل الشركة | حدث مركزي للجلسة يعيد تحميل capabilities والمالك للشركة الحالية. |
| قائمة الشركات كانت تكتب grants عند القراءة | أزيلت الكتابة الجانبية؛ قالب مدير الشركة يحسب في الذاكرة مثل `CompanyContextService`. |
| قراءة تاريخ المبيعات الكامل محجوبة أثناء قفل الترحيل لأن الاسم لا ينتهي بـ`.read` | سياسة قراءة صريحة لقفل المراجعة تشمل `finance.daily_sales.history.read_all` والعمليات غير المتحولة المعتمدة. |
| كتالوج/ملخص العمليات يطلبان `operations.catalog.manage` للـGET | صارت القراءة تطلب `operations.catalog.read` فقط. |
| قدرات الموردين والتصنيفات مستخدمة لكنها غير قابلة للإسناد | أضيفت `finance.suppliers.write` و`finance.categories.write` إلى الكتالوج وقالب مدير الشركة. |

## حدود مقصودة وليست أعطالاً

- وظائف مركزية حساسة مثل الإدارة المركزية أو الاستعادة أو عكس عمليات منتقاة قد تتطلب **مالك المستأجر** إضافة إلى capability؛ لا يكفي أن يكون الشخص مدير شركة. يلزم أن تشرح الواجهة هذا الفرق في دفعات UX اللاحقة بدلاً من عرضه كمنع عام.
- عندما يكون قفل مراجعة الترحيل فعالاً، لا يجوز إنشاء أو اعتماد أو سداد أو تعديل بيانات تشغيلية. يجب إنهاء المطابقة وفك القفل بإجراء إداري موثق قبل ذلك.
