# سجل فريق ألفا — توحيد قراءات الإدارة المركزية المالية

**الحالة:** مكتمل — بوابة الإصدار اجتازت التحقق في 30 أغسطس 2026.
**النطاق:** تحويل الكروت والجداول المركزية المالية إلى receipts خادمية شاملة الضريبة وقابلة للمطابقة، ومنع الحساب المالي في الواجهة.

| المرحلة | شرط الدخول | التنفيذ الفعلي | الدليل | الحالة | شرط الخروج |
| --- | --- | --- | --- | --- | --- |
| 0 — جرد العقد | تدقيق الكروت والسياسات مكتمل | ثبت عدم وجود عقد مركزي موحد لـ basis/VAT/quality/coverage | `CENTRAL_MANAGEMENT_FINANCIAL_CARD_AUDIT_2026-08-29.md` ونتيجة بحث العقود | مكتمل | عقد جديد وموافقة TypeScript |
| 1 — المبيعات والتحليلات | عقد موحد وتصميم تغطية | `daily-sales/analytics` يعيد المتوسطات والعملاء والنسب والتغيرات وقيم العرض من الخادم | contracts + `verify:daily-sales-http` | مكتمل | لا حساب/نسبة/متوسط مالي في React |
| 2 — التسويق والحركة | Gross-first وتعريف للتصنيفات | التقويم والرسم الزمني والتقرير النقدي يعيدون Gross وقيم الرسم والترتيب والنسب خادمياً | `verify:marketing-gate-a1` + `verify:reports-http` | مكتمل | كل واجهة غير تقريرية تعرض Gross فقط؛ التقارير تحتفظ بزر فصل الضريبة القائم |
| 3 — المالك والتشغيل | تعريف يوم التشغيل وحالة النقص | receipts المالك والتشغيل تضيف التغطية والأساس و`null` عند Pending/Partial/Closed | `verify:operations-purchase-cycle` | مكتمل | لا متوسط أو توقع مع تغطية ناقصة |
| 4 — الواجهة والقبول | وصول العقود إلى الواجهة | أزيلت عمليات المال من أسطح الإدارة وربطت لوحة المالك؛ أضيف حارس ساكن موسع | web/API checks, HTTP, RLS, static boundary | مكتمل | نجاح جميع البوابات ومراجعة عربية/إنجليزية |

## سجل تحقق الإغلاق

| البوابة | النتيجة |
| --- | --- |
| `npm run check --workspace @baseer-erp/contracts` | ناجح |
| `npm run check --workspace @baseer-erp/api` و`@baseer-erp/web` | ناجح |
| `npm run check:web-financial-boundaries` | ناجح؛ يشمل مركز القيادة والتحليلات والمالك والتشغيل والرسم |
| `npm run verify:daily-sales-http` | ناجح؛ يغطي صلاحيات التاريخ الكامل، الضريبة، التغطية والعملاء |
| `npm run verify:marketing-gate-a1` | ناجح؛ gross timeline و`null` بدلاً من الصفر |
| `npm run verify:reports-http` و`npm run check:reports-rls` | ناجحان |
| `npm run verify:operations-purchase-cycle` | ناجح؛ مصدر/ضريبة/تغطية الرسم التشغيلي |

## المطابقة والقرار

- لا توجد كتابة بيانات أو فتح شركة أو ترحيل بيانات في هذه الرحلة؛ التغيير يقتصر على read models والعقود والاختبارات.
- لا تغلق المرحلة إلا عندما تكون كل نتيجة مالية: **مكتوبة ومطابقة** لعقد خادمي واختبار قبول، أو مسجلة كعائق صريح.
- المصدر المرجعي للمبيعات: تقفيل مثبت → دفتر مختوم → `FinanceDailyFinancialSummary` → read model مركزي.
