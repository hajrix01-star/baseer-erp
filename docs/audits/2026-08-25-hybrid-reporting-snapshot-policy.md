# سياسة النموذج الهجين للقراءات واللقطات — 25 أغسطس 2026

## القرار المستهدف

يعتمد Baseer ERP نموذجاً هجيناً:

| السطح | السياسة | السبب |
| --- | --- | --- |
| بطاقة تشغيلية أو شاشة تقرير عادية | قراءة حية خادمية، بلا `ReportRun` | تعكس آخر البيانات عند التحديث ولا تدّعي أنها مستند تدقيقي ثابت. |
| فتح تفصيل دليل أو مصدر قيد | `ReportRun` قصير العمر ينشأ عند بدء التفصيل | يثبت صف الدليل وصفحاته ومصدره حتى ينتهي التدفق. |
| طباعة أو Excel أو حفظ تقرير | `ReportRun` قصير العمر ينشأ عند بدء الإجراء | يبني الخادم المخرج من حد دفتر ثابت، لا من صفوف المتصفح أو قراءة حية متغيرة. |
| مستند حفظه المستخدم أو تقرير معتمد لاحقاً | لقطة مستند دائمة مستقلة (`ReportDocument`) | لا تتأثر بانتهاء `ReportRun` وتفحص بصمة محتواها عند العرض. |
| دفتر المالك اليومي | لقطة يومية مستقلة (`OwnerDailyBriefSnapshot`) | ملخص تاريخي متعدد الشركات، لا تقرير دفتر أستاذ ولا بديل لـ`ReportRun`. |

في هذا الهدف لا تنشئ القراءة العادية `ReportRun`. ويظل مطلوباً عند التحول إلى دليل أو مخرج قابل للتدقيق. وهو ليس تخزيناً دائماً لكل صفوف التقرير: يحفظ حدود القراءة (الإصدار والمرشحات والسياسة والبصمة) ثم تعيد الخدمة قراءة القيود المختومة الواقعة ضمنها.

## جرد مركز القيادة والبطاقات

| السطح | الوضع المكتشف قبل الترحيل | سياسة الهدف |
| --- | --- | --- |
| مركز القيادة — المال | ينشئ حالياً تقريري الأداء النقدي للفترة الحالية والمقارنة؛ تفصيل البطاقة ومصدرها يستخدمان `reportRunId` للفترة الحالية | قراءة حية للبطاقات والمقارنة. عند ضغط المستخدم على صف/مبلغ قابل للتفصيل ينشأ run واحد للمرشحات الحالية، وتستخدمه كل صفحات الدليل ومصدر القيد. |
| مركز القيادة — التسويق والتقويم | `/marketing/calendar` و`/finance/operational-calendar`، ولا `ReportRun` | يبقى حياً/تشغيلياً. لا تمنحه واجهة التدقيق صفة تقرير مالي أو تصدير مالي حتى يضاف عقد تقرير مستقل. |
| الأداء النقدي وميزان المراجعة والضريبة الداخلية | التقرير وevidence/source والمخرجات مرتبطة حالياً بالـrun منذ قراءة الشاشة | تعرض النتيجة العادية حية. ينشأ run فقط عند **تفصيل** أو **طباعة/Excel/حفظ**، ويمرر المعرف نفسه إلى كل طلب تابع للإجراء. |
| النظرات التشغيلية/المبيعات/القرار | قراءات تشغيلية أو تحليلية منفصلة، بلا `ReportRun` | تبقى حية. إن أضيف تفصيل مالي قابل للحفظ أو للتصدير، ينشأ `ReportRun` مخصص عند بدء الدليل/المخرج، لا عند تحميل البطاقة. |
| دفتر المالك اليومي | `OwnerDailyBriefSnapshot` مجدول بحد أقصى لقطة واحدة لليوم المكتمل، JSON مع SHA-256، وليس `ReportRun` | يبقى مساراً مستقلاً؛ لا يربط تلقائياً بـ`ReportRun` لأنه لا يقدم دليل قيد أو تصديراً مالياً. |

**تنبيه تسمية:** `mode="snapshot"` في `BaseerCompanyReadQuery` هو إعداد cache للمتصفح يمنع التحديث التلقائي؛ لا يعني وحده إنشاء لقطة خادمية أو حد دفتر أستاذ. في الهدف الجديد لا تستخدم شاشة التقرير العادية هذا الوضع كبديل عن قراءة حية. الإنشاء الخادمي الحقيقي هنا هو `ReportRun` أو `OwnerDailyBriefSnapshot` فقط.

## الضمانات التي لا تتغير

- ختم القيد أو عكسه يزيد `FinanceLedgerRevision` في المعاملة نفسها؛ وكل `ReportRun` يثبت هذا الإصدار ويحسب SHA-256 من السياسة والمرشحات والتغطية والإصدار.
- يقرأ كل دليل أو مخرج مالي من القيود المختومة إلى `ledgerRevision <= ReportRun.ledgerRevision`؛ لذلك لا يستطيع عكس أحدث أن يغير الدليل أو المخرج الذي بدأ بالفعل.
- `ReportRun` ينتهي تشغيلياً بعد 24 ساعة. انتهاءه ليس حذفاً ولا تصريحاً بإعادة كتابة تاريخ مالي؛ أما الشاشة الحية فتقرأ آخر البيانات عند تحديثها.
- `ReportDocument` يبني JSON خادمياً من الـrun، يحفظ بصمته، ويعرض لاحقاً من المستند المحفوظ لا من الـrun الحي.

## قواعد البدء والتجديد الآمنين

1. ضغط التفصيل أو الطباعة/Excel/الحفظ ينشئ run واحداً من مرشحات الشاشة المعروضة في تلك اللحظة؛ لا تقبل الخدمة rows أو totals من المتصفح.
2. يستخدم الدليل وصفحاته ومصدره run نفسه إلى أن يغلق المستخدم التدفق. ويستخدم كل مخرج run نفسه إلى أن يكتمل إنشاؤه.
3. التجديد التلقائي مرة واحدة فقط، وفقط عند رمز `REPORT_RUN_EXPIRED`؛ لا يعاد المحاولة عند `404` أو `403` أو خطأ شبكة عادي.
4. بعد التجديد تعرض الواجهة بوضوح: «تم تحديث التقرير؛ قد تكون الأرقام قد تغيرت»، مع وقت الإنشاء و`ledgerRevision` وchecksum حيث يظهر وصف الدليل أو المخرج.
5. يلغى التفصيل المفتوح وصفحاته السابقة عند الانتقال إلى run جديد؛ لا تدمج عناصر دليل من run قديم وجديد.
6. لا يستبدل التجديد تلقائياً مستنداً محفوظاً أو معاينة طُبعت أو نسخة مُعتمدة. هذه تنشئ نسخة جديدة مرتبطة بـrun جديد مع أثر تدقيقي ظاهر.
7. لا يعلن التقرير الضريبي الداخلي إقراراً نظامياً أو مستند امتثال قانوني. إن أضيف اعتماد/إيداع مستقبلاً، يلزم مسار احتفاظ واعتماد وصلاحية منفصل.

## قائمة تحقق قبل اعتماد التطبيق

- [ ] يثبت اختبار أن فتح التقرير والبطاقات المالية العادية لا ينشئ `ReportRun`، وأن زر التحديث يعيد قراءة خادمية حية.
- [ ] يثبت اختبار أن فتح تفصيل أو طباعة/Excel/حفظ ينشئ run واحداً فقط بالمرشحات الظاهرة، ولا يقبل أرقاماً أو صفوفاً من المتصفح.
- [ ] تعرض واجهة الدليل/المخرج، لا البطاقة الحية بالضرورة، `reportRunId` و`ledgerRevision` وchecksum ووقت الإنشاء ووقت الانتهاء للمستخدم المخول.
- [ ] يثبت اختبار تكامل: إضافة قيد أو عكسه بين فتح التقرير الحي وفتح الدليل، ثم أن الدليل والتصدير يبقيان عند الإصدار الذي أنشأه الإجراء.
- [ ] يثبت اختبار الواجهة: انتهاء run، تجديد واحد، تنبيه واضح، وعدم مزج الدليلين.
- [ ] يثبت اختبار عدم تجديد: `403` و`NOT_FOUND` و`INTERNAL_ERROR` لا تستدعي إعادة إنشاء تقرير.
- [ ] يثبت اختبار المخرجات: print وExcel والحفظ يتصرفون بالسياسة نفسها؛ المستند المحفوظ يبقى قابلاً للعرض بعد 24 ساعة وتتحقق بصمته.
- [ ] تحدد سياسة retention للـ`ReportRun` المنتهي، ولـ`ReportDocument`، ولمستندات الاعتماد/الضريبة مستقبلاً مع مالك سياسة واضح.
- [ ] لا تضاف بطاقة أو Dashboard مالية قابلة للتفصيل أو للتصدير إلا بعقد يحدد: المصدر، نطاق الشركة، صلاحيات القراءة، نقطة إنشاء `ReportRun`، تعريف المقياس وإصداره، وطريقة الدليل.
