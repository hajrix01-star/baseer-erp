# مستندات وخطابات الموظف — تشغيل آمن

## النطاق

توفر وحدة الموارد البشرية سجل مستندات الموظف وخطابي تعريف الراتب والخدمة.

- المستند قد يكون سجلاً وصفياً بلا ملف، أو ملفاً مرفوعاً بإصدار قابل للاستبدال.
- الأنواع المقبولة للملف: PDF وJPEG وPNG، وبحد أقصى 5 MiB.
- لا تشمل هذه الوحدة الحضور والانصراف أو مشاركة الملفات بروابط عامة.
- خطابات الموظف تصدر من لقطة خادمية ثابتة، بالعربية أو الإنجليزية، مع معاينة وطباعة A4 مركزية.

## إعدادات الإنتاج الإلزامية

| الإعداد | المطلوب |
| --- | --- |
| `BASEER_EMPLOYEE_DOCUMENT_ENCRYPTION_KEY` | قيمة Base64 تمثل 32 بايتاً تماماً. تحفظ في مدير أسرار الإنتاج ولا تضاف إلى المستودع. تستخدم لتشفير كل ملف بـ AES-256-GCM. |
| `BASEER_EMPLOYEE_DOCUMENT_STORAGE_ROOT` | مسار تخزين خاص ودائم ومشترك بين جميع مثيلات API عند التشغيل المتعدد. لا يكون مساراً عاماً أو قابلاً للخدمة عبر HTTP. |
| `BASEER_DOCUMENT_SCANNER_ENDPOINT` | نقطة فحص موثوقة تستقبل محتوى الملف وتعيد قراراً واضحاً: `READY` أو `QUARANTINED`، مع اسم الفاحص والنتيجة. |

غياب مفتاح التشفير أو عدم صلاحيته يوقف رفع الملفات بصورة آمنة. وغياب الفاحص، أو مهلة الاتصال به، أو رده غير الصالح يجعل الملف `QUARANTINED`؛ فلا يمكن تنزيله. يظل إنشاء سجل مستند بلا ملف متاحاً.

للتطوير المحلي فقط يمكن تفعيل:

```text
BASEER_DOCUMENT_DEV_SCANNER=deterministic-content-validator
```

هذا يتحقق من صيغة الملف فقط، وليس مضاد فيروسات ولا بديلًا عن فاحص الإنتاج.

## ضوابط الحماية

- يتحقق الخادم من الامتداد وـmagic bytes والحجم، ثم يحسب SHA-256 قبل التشفير.
- لا توجد روابط تخزين أو تنزيل عامة. التنزيل يتطلب صلاحية الشركة والموظف، والملف بحالة `READY`.
- استجابة التنزيل تستخدم `Content-Disposition: attachment` و`nosniff` و`no-store`.
- الاستبدال ينشئ إصداراً جديداً، والإلغاء لا يحذف سجلاً أو ملفاً بصمت.
- يسجل التدقيق الرفع والاستبدال والتنزيل والإلغاء كبيانات وصفية فقط، من دون نسخ محتوى المستند إلى سجل التدقيق.
- لا يوجد حذف نهائي أو purge تلقائي في الإصدار الأول؛ يدار الاحتفاظ و`legal hold` بقرار حوكمة لاحق.

## الخطابات

- شهادة الراتب لا تصدر إلا عند وجود اتفاق تعويض فعّال في تاريخ العمل.
- شهادة الخدمة وشهادة الراتب لا تقبلان نصاً حراً؛ يُحفظ رقم تسلسلي وإصدار قالب ولقطة وhash للبيانات.
- الخطاب الملغى يبقى في سجل التدقيق، لكنه لا يقبل المعاينة أو الطباعة أو التصدير.
- يستخدم العرض المركزي التقرير `hr.employee-letter` وفلتره الوحيد هو `letterId`.

## تحقق التسليم التشغيلي

قبل فتح الميزة في الإنتاج:

1. خزّن مفتاح التشفير في مدير الأسرار واضبطه في جميع مثيلات API.
2. وفّر مساحة تخزين خاصة مشتركة ومشفرة بالنسخ الاحتياطي، وتحقق أن صلاحية حساب API وحده تسمح بالوصول إليها.
3. اربط فاحصاً موثوقاً، واختبر ملفاً آمناً وملفاً مرفوضاً وحالة مهلة الفاحص.
4. اختبر عزل شركتين مختلفتين، وعدم ظهور زر التنزيل قبل `READY`، وسجل تدقيق التنزيل.
5. اختبر معاينة وطباعة خطابي الراتب والخدمة بالعربية والإنجليزية، ثم إلغاء خطاب والتأكد من حجب مخرجاته.
