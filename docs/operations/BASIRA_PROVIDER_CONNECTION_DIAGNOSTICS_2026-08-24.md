# بصيرة — تشغيل وتشخيص اتصال مزود الذكاء

## سبب هذا السجل

ظهر في واجهة الإعداد سابقاً تنبيه عام: «تعذر التحقق من المزود حالياً». لم يكن التنبيه يفرّق بين رفض المفتاح، منع صلاحية المشروع، نقص الفوترة، حدّ الطلبات، أو تعذر الوصول. كما كانت الصفحة تطلب فحصاً خارجياً تلقائياً عند فتحها، وهذا غير مناسب لمسار محكوم بالتكلفة والطلب الصريح.

لا يدل التنبيه القديم وحده على أن المفتاح خاطئ. لا يجوز استبدال المفتاح أو تفعيل Pilot اعتماداً عليه.

## القرار المنفذ

1. فحص المزود يدوي فقط عبر «فحص الاتصال الآن»؛ فتح صفحة الحوكمة لا يرسل طلباً إلى OpenAI.
2. الفحص يستدعي استرجاع معلومات النموذج فقط؛ لا يرسل prompt أو حقائق ERP أو بريد أو مرفقات، ولا يولد مخرجات نموذجية.
3. تحفظ النتيجة الآمنة في `AuditEvent` بالحدث `platform.ai.provider_connection_checked`، متضمنة الملف المشفّر الذي فُحص، النتيجة، رمز السبب الآمن، حالة HTTP إن وجدت، والوقت. لا تحفظ الاستجابة الخام أو المفتاح أو معرف طلب المزود.
4. تقرأ الواجهة آخر فحص محفوظ للملف المعروض، وتظهر رسالة عملية ورمز HTTP الآمن عند الحاجة.
5. لا يغير فشل فحص عابر ملف المزود النشط تلقائياً، ولا يشغل Pilot ولا يرسل تفسيراً مدفوعاً.

## خريطة الأسباب والإجراء

| السبب الظاهر | المعنى | الإجراء المسموح |
| --- | --- | --- |
| `CREDENTIAL_REJECTED` / HTTP 401 | رفض OpenAI مفتاح API | أنشئ أو صحح مفتاح مشروع OpenAI ثم احفظ ملفاً جديداً. لا ترسل المفتاح في المحادثة أو السجل. |
| `PROJECT_ACCESS_DENIED` / HTTP 403 | للمشروع أو المفتاح منع للوصول إلى النموذج | راجع مشروع المفتاح والصلاحيات والفوترة في OpenAI. |
| `MODEL_UNAVAILABLE` / HTTP 400 أو 404 | النموذج غير متاح للمشروع أو الاسم غير صحيح | اختر نموذجاً متاحاً للمشروع، ثم احفظ ملفاً جديداً. |
| `BILLING_OR_QUOTA_REQUIRED` / HTTP 402 أو 429 مع سبب فوترة/حصة | رصيد أو فوترة أو حصة مشروع غير كافية | عالج الفوترة/الرصيد في OpenAI. سقف Baseer الداخلي ليس بديلاً عن فوترة OpenAI. |
| `PROVIDER_RATE_LIMITED` / HTTP 429 | حد مؤقت من OpenAI | انتظر ثم افحص مرة واحدة. |
| `PROVIDER_UNREACHABLE` | لم يصل الخادم إلى OpenAI | راجع الشبكة وDNS والجدار الناري للخادم. |
| `PROVIDER_UNAVAILABLE` / HTTP 5xx | عطل مؤقت لدى المزود | لا تغيّر المفتاح؛ أعد الفحص لاحقاً. |
| `PROVIDER_RESPONSE_REJECTED` | استجابة مرفوضة لا تحمل تصنيفاً آمناً أدق | استخدم رمز HTTP المعروض مع سجل التدقيق؛ لا تفترض أن المفتاح خاطئ. |

## ترتيب التشغيل

1. يحفظ المالك ملف OpenAI مشفراً مع حد الطلبات وسقف USD.
2. يضغط المالك «فحص الاتصال الآن» مرة واحدة.
3. يعالج السبب المحدد إن فشل الفحص، أو يفعّل الملف صراحةً عند النجاح.
4. يجتاز فحص المهارة غير المتصل (`OFFLINE`) للشركة.
5. فقط بعد اعتماد الخصوصية والسقف ومفتاح Pilot الخادمي يبدأ Pilot محدود. اتصال المزود الناجح لا يفعّل Pilot بنفسه.

## التحقق ومنع الرجوع

نفّذ:

```powershell
npm run verify:basira-provider-diagnostics
```

التحقق يغطي التصنيف الآمن لحالات 401 و403 و404 و429 والفوترة والاتصال و5xx، وتوافق الإيصال مع عقد الواجهة. لا يتصل بأي مزود ولا يحتاج مفتاح API.

السجلات العامة القديمة التي حفظت الرسالة العامة لا يمكن تصنيفها بأثر رجعي؛ الفحص اليدوي التالي هو المصدر المعتمد للنتيجة الجديدة.
