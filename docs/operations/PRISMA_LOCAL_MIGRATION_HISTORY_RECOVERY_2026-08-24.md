# إصلاح سجل ترحيلات Prisma المحلي — 24 أغسطس 2026

## النطاق والنتيجة

هذا الإجراء يخص فقط قاعدة الاختبار المحلية المعتمدة `127.0.0.1:5433/baseer_erp_test`.
لا يغيّر أي قاعدة تشغيلية أو إنتاجية.

بعد الإصلاح: 116 ترحيلاً مطبقاً، صفر محاولات فاشلة غير مسوّاة، وصفر اختلافات بين بصمات ملفات الترحيل وسجل Prisma. أمر Prisma الرسمي يؤكد أن المخطط محدث.

## السبب الجذري

1. تكرار محاولات قديمة نفذت ببعض هويات قاعدة بيانات غير المالكة أضاف صفوفاً فاشلة إلى `_prisma_migrations`، رغم أن لكل ترحيل منها صفاً ناجحاً لاحقاً.
2. تغير محتوى ملفي ترحيل قديمين بعد تطبيقهما محلياً، فصارت بصمة الملف لا تطابق البصمة المسجلة. تحققت النتيجة البنيوية قبل التسوية: العمود والمفتاح والفهرس الخاصان بالعهدة موجودة، وقيود تسليم النقد القديمة غير موجودة.
3. كانت أوامر التشخيص اليدوية تمرر قيمة `DATABASE_URL` مع علامات اقتباس حرفية من ملف البيئة، فتظهر Prisma رسالة عامة `Schema engine error` بدلاً من اتصال صالح. علامات الاقتباس في ملف `.env` صحيحة؛ الخطأ كان في طريقة استخراج القيمة في PowerShell.

## ملكية أنواع PostgreSQL وmigrator المحلي

حساب التطبيق المحلي مقيد عمداً ولا يملك أنواع PostgreSQL مثل
`AiProviderKind`. لذلك لا يجوز أن ينفذ `ALTER TYPE` حتى لو كان له حق قراءة
وكتابة بيانات الأعمال. اعتباراً من 2026-08-24 يشغّل
`npm run prisma:test:deploy` migration على قاعدة الاختبار المحلية فقط بحساب
الـmigrator داخل الحاوية `baseer-erp-postgres`، أو عبر
`BASEER_DB_MIGRATOR_URL` المكافئ. تستمر API والاختبارات العادية باستخدام
`DATABASE_URL` المقيد.

لا يطبع السكربت كلمة مرور الحاوية ولا يكتبها في ملف. يرفض كلا المسارين أي
هدف غير `127.0.0.1:5433/baseer_erp_test`. إذا فشلت migration سابقة بسبب
الملكية، تعالج أولاً بـ`prisma migrate resolve --rolled-back` بحساب الـmigrator
ثم تعاد `prisma:test:deploy`؛ لا تغيّر مالك النوع إلى حساب التطبيق ولا تعدل
سجل `_prisma_migrations` يدوياً.

يحفظ Prisma صف المحاولة المسحوبة (`rolled_back_at`) للتدقيق. فاحص السلامة
ومسار التسوية يعدان فقط المحاولات غير المنتهية **وغير المسحوبة** مشكلة قائمة؛
لا يحذفان السجل المسحوب ولا يخلطانه بترحيل فاشل يحتاج معالجة.

## ما نُفذ بأمان

- `recover:local-prisma-migration-history` ينشئ نسخة احتياطية من المحاولات الفاشلة ثم يحذف فقط المحاولة الفاشلة التي لها مقابل ناجح وبصمة مصدر مطابقة.
- `recover:local-prisma-migration-checksums` محصور في الملفين المتحققين بنيوياً، ويحتفظ بالبصمة السابقة في جدول النسخ الاحتياطي `_baseer_prisma_migration_checksum_backup_20260824` قبل التسوية.
- تم تسجيل ترحيل `20260824230000_marketing_campaign_stop_context` رسمياً كـ applied، لأن أثره كان مطبقاً ومتحققاً مسبقاً في قاعدة الاختبار.

## التشغيل الوقائي

استخدم دائماً الأوامر التالية لقاعدة الاختبار؛ فهي تقرأ ملف البيئة بطريقة صحيحة وترفض أي قاعدة ليست قاعدة الاختبار المحلية:

```powershell
npm run prisma:test:status
npm run prisma:test:deploy
npm run check:local-prisma-migration-history
```

لا تعدّل جدول `_prisma_migrations` يدوياً، ولا تعدّل ملف ترحيل سبق تطبيقه. عند ظهور اختلاف جديد: أوقف النشر، افحص المخطط الفعلي، احتفظ بنسخة من السجل، ثم أنشئ ترحيلاً جديداً أو نفّذ تسوية موثقة ومحددة بعد مراجعة مستقلة.
