# عقد بناء: سلطة صلاحيات التنقل

## G0 — مقفل للمراجعة

- **المستخدم:** مالك الشركة ومدير الصلاحيات ومستخدم الدور المحدود.
- **المشكلة:** تظهر في التنقل أقسام مالية/تشغيلية لأن صلاحية واحدة عامة
  تمنح صفحات مستقلة، وتعرض الشاشة التبعيات التلقائية كاختيار يدوي.
- **القبول:** لا يظهر قسم إلا بصلاحية صفحته الخادمية؛ يظهر فرق واضح بين
  المعين مباشرة والتبعي التلقائي؛ لا تمسح صلاحيات قائمة تلقائياً.
- **خارج النطاق:** تغيير الأرصدة أو القيود أو بيانات المستندات أو منح وصول
  استثنائي للمالك.
- **رحلة ERP:** منح دور → استخراج صلاحيات فعالة خادمياً → فتح صفحة مسموحة
  أو رفضها → إظهار القائمة. لا تنشئ الرحلة قيداً أو حركة مالية.

## G1 — مقفل للمراجعة

هذه قراءة صلاحيات محدودة (حد الدور 120 رمزاً، والشركات 250 في العقد القائم).
لا استعلام جديداً كبيراً ولا عملية طويلة. معيار الرحلة: نتيجة التفويض أو
تصفية القائمة محلياً من receipt الحالي؛ لا اختبار حمل إنتاجي مطلوب.

## G2 — مقفل للمراجعة

مصدر الحقيقة هو `RolePermission` والخدمات في `company-context`؛ المتصفح لا
يمنح وصولاً. العقد يفصل `direct` من `effective` في عرض الإدارة، والتوافق
للأدوار السابقة يتم خادمياً. تفويض كل endpoint الخاص بالشراء/المصروف/السجل
يرتبط برمز مستقل. يضيف migration متوافق رمز قراءة السجل المالي إلى الأدوار
النظامية المالية فقط، ولا يوسّع أي دور مخصص.

## G3 — مقفل للمراجعة

لا مكتبات أو رصة جديدة. تستخدم React/Nest/Zod وPlaywright الموجودة. المسار
المباشر هو تعديل مالك التفويض والسجل لا CSS أو استثناءات في drawer.

## G4 — مقفل للمراجعة

يعاد استخدام مكونات Baseer القائمة. العربية والإنجليزية وRTL/LTR والجوال
مطلوبة؛ عنصر التبعية التلقائية يجب ألا يبدو مربع اختيار مباشر.

## G5 — مقفل للمراجعة

- تفصل `finance.ledger.read` شرط صفحة السجل المالي وendpoint الخاص به.
- صلاحيات القراءة التابعة لا تُحفظ بجانب action الأم، وتظهر في بطاقة الدور
  كتفعيل تلقائي بدل صلاحية اختارها المدير.
- تمت إضافة ترحيل idempotent للأدوار النظامية المالية فقط.

## G7 — قيد المراجعة

الدليل المحلي: `check:permissions` (142 قدرة)، و
`check:authorization-consistency`، وفحص TypeScript للـAPI والواجهة. شُغلت
اختبارات Playwright المعزولة للدور، وخريطة السجل المالي على سطح المكتب والجوال.
يبقى قبول التسليم وCI قبل النشر.

## سجل القرار

| القرار | البديل المرفوض | السبب |
|---|---|---|
| فصل صلاحيات الصفحات | إخفاء الروابط في الواجهة فقط | الإخفاء لا يحمي endpoint ولا يحل تداخل الصلاحيات |
| تسوية read المكررة عند الحفظ | إبقاؤها كصلاحيات مباشرة ظاهرياً | وجود action يمنح read فعلياً يجعل التخزين مكرراً ومضللاً بلا أثر صلاحية إضافي |
| إبقاء التبعية فعالة وقت التشغيل | تخزينها كاختيار مباشر | يحافظ على الرقابة ويعرض مصدرها بصدق |
