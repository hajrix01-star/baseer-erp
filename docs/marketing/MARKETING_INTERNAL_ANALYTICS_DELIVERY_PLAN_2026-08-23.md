# خطة تسليم الربط الداخلي والتقويم التسويقي — 2026-08-23

## قرار المالك والنطاق

بعد اكتمال Gate A1، يفعّل المالك المرحلة **P2 — الربط الداخلي والقراءة
الموحّدة**. الغرض هو أن يفهم مدير الشركة علاقة *فترة الحملة* بالمبيعات
الرسمية، والمصروفات المثبتة المرتبطة بها، والسياق المنشور؛ من دون ادعاء أن
الحملة أو الحدث سبب التغير.

هذه المرحلة لا تمنح Google OAuth أو SDK أو HTTP أو مزامنة أو حقائق مزود أو
نشر أو بصيرة حية. ولا تنشئ مالياً فاتورة أو مورداً أو قيداً من التسويق.

## نتيجة المنتج

```text
حملة ذات فترة معتمدة
   + مبيعات يومية رسمية متصالحة
   + مستندات مصروف/شراء POSTED مرتبطة صراحةً
   + مناسبات وأحداث منشورة متداخلة
       ↓
قراءة الحملة الموحدة + التقويم الحراري
       ↓
«ارتباط زمني، لا سببية» + جودة/تغطية/دليل
```

## الملكية والحدود

| الطبقة | تملك | لا تملك |
| --- | --- | --- |
| التسويق | الحملة، رابطاً صريحاً للمستند أو للسياق، وقراءة التقويم | دفتر الأستاذ أو المورد أو الضريبة أو ترحيل المستند |
| المالية | `FinanceDailyFinancialSummary` والمستند المالي وحالته | تعريف الحملة أو سياقها |
| مركز القرار والسياق | أحداثه المنشورة، جودة قراءة المبيعات، التنبيهات والأدلة | تكرار أحداث في التسويق |
| بصيرة | لاحقاً تفسير حزمة دليل مصرح بها فقط | قراءة الجداول أو إنشاء علاقة أو أمر مالي |

الرابط المالي أحادي الاتجاه: التسويق يشير إلى مستند مالي موجود ومثبت؛ لا ينسخ
قيمة أو مورد أو ضريبة ولا يغير المستند. المستند الواحد يربط بحملة واحدة في
هذه المرحلة؛ التقسيم بين حملات يؤجل إلى سياسة توزيع مستقلة.

## نموذج البيانات والعقود

1. `MarketingCampaignFinancialLink`: حملة + مستند مالي POSTED، مع مرجع
   المستند وتاريخ الإنشاء وسجل تدقيق. يرفض الرابط مستند شركة أخرى أو مستنداً
   ملغى أو رابطاً مكرراً.
2. `MarketingCampaignContextLink`: حملة + نسخة مناسبة عامة منشورة أو حدث
   شركة منشور. يثبت المراجعة العامة نفسها، لا اسم الحدث؛ لذلك لا يتغير دليل
   الحملة إن تغير كتالوج المناسبة لاحقاً.
3. `MarketingCampaignAnalysisRead`: عقد خادمي يتضمن الفترة، ملخص مبيعات
   رسمي، ملخص المستندات المرتبطة، تغطية وجودة القراءة، السياق المتداخل،
   والمراجع. لا يحوي conversion أو ROAS أو سبباً.
4. `MarketingCalendarRead`: قراءة شركة/فترة تجمع **نقطة خادمية لكل يوم**:
   صافي المبيعات الرسمي أو `null`، وحالة اليوم (`READY` أو `PENDING` أو
   `PARTIAL` أو `MISSING`)، والمصروف المثبت المرتبط وعدد مستنداته والحملات
   النشطة والسياق المنشور. الغياب أو اليوم الجزئي يظهر جودة، لا صفراً.
5. `MarketingSalesTarget`: هدف مبيعات شهري مملوك للشركة، مؤرخ بالشهر ومدقق
   وقابل للتعديل بصلاحية الحملة. لا يغير أي عملية أو ملخص مبيعات. الخادم
   يوزع الهدف على أيام الشهر ويعيد لكل يوم حالة تقدم (`BELOW`/`NEAR`/`MET`/
   `EXCEEDED`)؛ لا تحسب الواجهة النسبة أو تلون اليوم من تلقاء نفسها.

## رحلة المستخدم

1. ينشئ المدير حملة بفترة ومنصة وتكلفة *مخططة* اختيارية.
2. من تفاصيل الحملة يختار «إصدار فاتورة/مصروف للحملة» أو «ربط مستند مالي
   موجود». خيار الإصدار ينقله إلى نموذج المشتريات والمصروفات المركزي مع اسم
   الحملة وفترتها والتكلفة المخططة، ثم يبقي المورد والتصنيف والضريبة والسداد
   والتحقق والترحيل في المالية. بعد ترحيل المستند يربطه النظام بالحملة؛ إن
   فشل الربط لا يخفي نجاح المستند بل يطلب ربطه يدوياً. وتظهر قائمة الربط فقط
   للمستندات المثبتة وبصلاحية القراءة المالية.
3. يضيف مناسبة/حدثاً من القائمة المنشورة أو يترك السياق الزمني التلقائي
   للقراءة؛ لا يمكنه اعتماد مرشح بحث من شاشة التسويق.
4. يفتح المدير التقويم أو تفاصيل الحملة ويرى الأرقام والفترة والسياق وحالة
   الجودة، وقراءة الصرف: المخطط والمثبت والمبيعات الرسمية ونسبة وصفية عند
   اكتمال البيانات. كما تظهر حالة Google Ads بوضوح. هذه ليست ROI أو سبباً.
   زر «كيف وصلنا؟» يعرض المراجع ولا ينفذ أمراً.

## واجهة مركزية

- فرع **التقويم التسويقي** جديد بين النظرة والحملات، باستخدام مرشح الفترة
  المركزي ومكوّنات Baseer فقط.
- أعلى الصفحة: الجودة، إجمالي المبيعات الرسمي، المصروف المرتبط المثبت، وعدد
  الحملات المتداخلة؛ لا تعرض KPI عند `NO_DATA` أو `INCOMPLETE` كصفر.
- في مركز القيادة: بطاقة خط زمني واحدة تتبدل بين **اليومي** و**الشهري** و**الحملات**؛
  تعرض خط المبيعات الرسمية وأعمدة المصروف الفعلي المرتبط وخط الحملات النشطة
  عند ملاءمته. لا تكرر خريطة الحرارة فيها.
- قسم **التقويم** مستقل: شبكة شهرية، هدف الشهر القابل للحفظ، تلوين تقدمه
  الخادمي، والمناسبة أو الحملة المتزامنة داخل يومها. يدعم تقليل الحركة ولا
  يحسب أرقاماً مالية في React.
- تفاصيل الحملة تضيف بطاقات «المبيعات في الفترة»، «المستندات المرتبطة»،
  «السياق المتزامن» و«حدود هذه القراءة»، وزر إصدار مالي مركزي عند امتلاك
  صلاحيتي التسويق والمالية. لا يظهر زر Google أو بصيرة كتفعيل وهمي.

## خطة التنفيذ والبوابات

| الخطوة | التسليم | بوابة القبول |
| --- | --- | --- |
| P2.0 | قرار التسليم، سلطة العمل، شجرة الموديول | لا تعارض مع Finance/Decision أو Google المؤجل |
| P2.1 | Prisma migration + RLS/FORCE RLS + contracts + idempotency/audit | شركة أخرى، مستند ملغى، حدث غير منشور، ورابط مكرر مرفوضة |
| P2.2 | قراءة موحدة للحملة والتقويم | المالية من server projection، الأيام الناقصة ليست صفراً، التوقيت Riyadh |
| P2.3 | UI مركزي، تفاصيل وربط مرجعي وتقويم | RTL/LTR، لوحة مفاتيح، شاشة صغيرة، لا حساب في React |
| P2.4 | اختبارات DB/HTTP/العقود/البناء وتوثيق النتيجة | لا أثر على journal، لا Google egress، لا ادعاء سببي |

## معايير القبول

- CompanyContext وRLS وRBAC لكل أمر وقراءة، مع اختبار عابر لشركتين.
- المستند المالي `POSTED` فقط هو الذي يضاف إلى المصروف المرتبط؛ أما
  `CANCELLED` فلا يظهر كمصروف للحملة.
- المبيعات تقرأ فقط من `FinanceDailyFinancialSummary` وبنفس سياسة الجودة
  المعتمدة؛ `PENDING` أو `PARTIAL` أو stale لا يتحول إلى صفر.
- الحدث المنشور فقط يظهر أو يربط، والأحداث العامة AREA تحترم موقع الشركة.
- كل إنشاء/فك رابط idempotent ومدقق، ولا يغير journal أو المستند أو الحدث.
- الرسم والبطاقات لا تخلط تكلفة مخططة مع مصروف مثبت ولا تنسب Google/مبيعات.

## مؤجل صراحةً

Google Ads/Business، ربط ذاتي، OAuth، مزامنة، حقائق موفر، إسناد أو ROAS،
توزيع مستند واحد على حملات متعددة، تنبيهات تسويقية آلية، بصيرة حية، وتعديل
أو نشر خارجي.

## تحديث التنفيذ — قراءة الحملة v2

تم تطوير القراءة الموحدة للحملة إلى `marketing.campaign_analysis_read.v2`:

- تقارن المبيعات الرسمية مع فترة سابقة مساوية بسياسة
  `PREVIOUS_EQUAL_PERIOD / previous_equal_period.v1`.
- تظهر النسبة فقط إذا كانت الفترتان `READY` وخط الأساس غير صفر؛ وإلا تبقى
  النتيجة غير متاحة ولا تتحول البيانات الناقصة إلى صفر.
- يدخل في نتيجة الصرف فقط المستند المالي `POSTED` المرتبط صراحةً **والواقع
  داخل فترة الحملة**. المستندات المرتبطة خارج المدة تبقى ظاهرة كدليل وتحذير
  لكنها لا تدخل المبلغ.
- التكلفة المخططة `null` عند عدم تعريفها؛ لا تُعرض كأنها صفر أو مصروف فعلي.
- أنشئ مسار داخلي لحفظ `DecisionEvidenceSnapshot` عند طلب تحليل محتفَظ به؛
  فتح شاشة الحملة العادي يبقى قراءة حية ولا يضخم قاعدة البيانات باللقطات.

المرحلة التالية المقصودة هي مهارة بصيرة `marketing.performance_analyst` فوق
هذه الحزمة المجمدة فقط. لا تتصل بصيرة بالجداول أو Google، ولا تتفعل قبل
بوابة مزود الذكاء والخصوصية والتقييم.

## تحديث التنفيذ — تفسير بصيرة للحملة (S2 Pilot)

أضيف مسار محدود لتفسير الحملة، ولا يغيّر معنى «التحليل أولاً»:

1. المتصفح يرسل `campaignId` واللغة ومفتاح idempotency فقط إلى
   `/administration/ai/runtime/marketing-campaign-explanations`.
2. الخادم يستنتج الشركة والصلاحيات الحية، ويشترط `marketing.insights.read`
   و`platform.ai.use`، ثم ينشئ حزمة `DecisionEvidenceSnapshot` غير قابلة
   للتعديل من قراءة الحملة v2.
3. لا يمكن التفسير قبل فترة حملة محددة ومبيعات حالية ومقارنة مكتملة
   (`READY`). لا تتحول البيانات الناقصة إلى إجابة أو صفر.
4. بصيرة تستقبل الحزمة المجمدة فقط، بلا `campaignId`، بلا SQL أو أدوات، وبلا
   اتصال Google. مخرجها JSON منضبط: خلاصة، أدلة، قيود وخطوات مراجعة آمنة.
5. تسجل العملية إيصال تنفيذ وتدقيق؛ فشل المزود لا ينفذ أي فعل ولا يعيد المحاولة
   كأمر خارجي. الحزمة تبقى دليلاً للمراجعة.

المهارة `marketing.performance_analyst` في حالة `PILOT` فقط، وتبقى مقفلة
افتراضياً إلى أن يعتمد مالك النظام المزود والخصوصية والتكلفة ويضع:
`BASEER_BASIRA_MARKETING_PILOT_ENABLED=true`. لا تعني هذه البوابة أن Google
متصل أو أن هناك إسناداً أو ROI/ROAS؛ فعند غياب حقائق الموصل تذكر بصيرة هذا
الحد صراحةً ولا تخمّن.

### التقييم والتعلّم المنضبط

بعد ظهور التفسير يستطيع المستخدم الذي يملك قراءة التسويق اختيار أحد التصنيفات:
`مفيد`، `غير مناسب`، `البيانات ناقصة`، `المقارنة غير عادلة`، أو `السياق مختلف`.
يحفظ الاختيار مع معرف الحملة ولقطة الدليل فقط في
`MarketingCampaignAnalysisFeedback` تحت RLS وAudit وidempotency. لا يعدل هذا
التقييم الحملة أو المبيعات أو قواعد المقارنة، ولا يدرّب نموذجاً تلقائياً؛ إنه
مادة تقييم عربية منظمة لاختبار إصدارات المهارة وتحسينها في Pilot لاحق.

## بوابة Google قبل الاتصال الحي

تبقى واجهة «اتصالات Google» في مرحلة طلب الإعداد فقط. مسار إنشاء رابط موافقة
OAuth، الموجود استعداداً للموصل، محجوب افتراضياً خلف بوابة إصدار منفصلة
`BASEER_MARKETING_OAUTH_EXPERIMENT_ENABLED`. لا تضاف إلى بيئة تشغيل عادية ولا
تُفتح قبل اعتماد سجل قرار مزود مستقل يشمل callback آمن، خزان رموز مشفر، اختياراً
صريحاً للحساب/الموقع، فك الربط، حدود الاحتفاظ، kill-switch، وPilot محدود. لا
توجد بيانات Google أو مزامنة أو نشر في هذا التسليم.
