# شجرة موديول الأداء التسويقي والسمعة

**الحالة:** شجرة المنتج المعتمدة قبل بناء التفعيل الذاتي للموصلات.

اسم الموديول الظاهر هو **الأداء التسويقي والسمعة**. لا تصبح فروع Google أو
بصيرة شاشات وهمية: لا يظهر الفرع التشغيلي إلا بعد أن يملك حقائق موثقّة أو
رحلة عمل حقيقية. لذلك تقسم الشجرة إلى ما يعمل الآن وما يفتح تدريجياً.

```text
الأداء التسويقي والسمعة
│
├─ 1. النظرة
│  ├─ أهم 3 ملاحظات للفترة
│  │  ├─ ماذا تغير؟
│  │  ├─ ما الدليل؟ وما جودة البيانات؟
│  │  ├─ ما السياق المتزامن؟
│  │  └─ ما الخطوة المقترحة للمراجعة؟
│  ├─ الحملات النشطة والمواعيد القريبة
│  ├─ ملخص الفترة وحالة بيانات التسويق والسمعة
│  ├─ قراءة الصرف والنتيجة
│  │  ├─ المخطط مقابل المصروف المثبت المرتبط
│  │  ├─ المبيعات الرسمية ونسبة وصفية للفترة
│  │  └─ حالة Google Ads وحدود «ليس ROI أو سببية»
│  ├─ التقويم الحراري والرسم الزمني المختصر
│  ├─ حالة الاتصال لكل موصل
│  └─ اسأل بصيرة عن هذه الفترة              [بعد بوابة المهارة]
│
├─ 2. التقويم التسويقي                    [منفذ: قراءة يومية ورسم تفاعلي]
│  ├─ خريطة حرارية للمبيعات الفعلية        ← قراءة مالية رسمية
│  ├─ المصروفات التسويقية المثبتة          ← قراءة مالية رسمية
│  ├─ الحملات والعروض والمنصات في كل يوم
│  ├─ المناسبات والأحداث المستوردة
│  │  ├─ الإجازات والمواسم المعتمدة
│  │  ├─ الطقس والمباريات والأحداث العامة المعتمدة
│  │  └─ أحداث الشركة المحلية المعزولة
│  └─ لا يقرر سبباً أو ROI أو مبيعات منسوبة
│
├─ 3. الحملات والعروض
│  ├─ الحملات النشطة                         ← بطاقات
│  ├─ الحملات المجدولة
│  ├─ السجل والأرشيف                         ← منتهية / ملغاة / مؤرشفة
│  ├─ إنشاء وتعديل الحملة
│  │  ├─ الاسم والوصف والمنصة والفترة
│  │  └─ التكلفة المخططة الاختيارية
│  └─ تفاصيل الحملة
│     ├─ أيام الظهور في التقويم والسياق المتزامن
│     ├─ المستندات المالية المرتبطة          ← روابط للمالية فقط
│     └─ إصدار مصروف أو فاتورة للحملة        ← يفتح النموذج المالي المركزي
│
├─ 4. السمعة وGoogle
│  ├─ سياسة الردود للشركة                    [منفذ]
│  │  ├─ 4–5 نجوم: تلقائي عند استيفاء السياسة
│  │  ├─ 3 نجوم: تلقائي آمن أو مراجعة
│  │  └─ 1–2 نجمة: مسودة ثم «نشر الآن» يدوي
│  ├─ حالة الربط                              [منفذ: غير متصل بصدق]
│  ├─ Google Business                           [بعد الربط والقراءة]
│  │  ├─ الملف التجاري والمواقع
│  │  ├─ التقييمات وطابور الردود والمسودات
│  │  ├─ المنشورات وسجل النشر والتدقيق
│  │  └─ نشر يدوي أو آلي محكوم بإيصال
│  └─ Google Ads                                [بعد الربط والقراءة فقط]
│     ├─ جودة المزامنة والتغطية والحداثة
│     ├─ أداء الحساب والحملات
│     ├─ عبارات البحث وفرص الهدر المحتمل
│     └─ حدود القياس: لا conversion = مبيعات ERP
│
└─ 5. المصادر والسياسات
│  ├─ حدود المصدر والحقيقة المالية             [منفذ]
│  ├─ سياسة الاحتفاظ والخصوصية
│  ├─ حالات الجودة والحداثة والصلاحيات والتدقيق
│  ├─ اتصالات Google                            [آخر خطوة]
│  │  ├─ مركز طلب التهيئة للشركة                [منفذ: لا اتصال حي]
│  │  ├─ Ads: ربط ذاتي وقراءة فقط              [بعد PDR/OAuth]
│  │  └─ Business: ربط ذاتي ثم نشر محكوم       [بعد PDR/OAuth]
│  └─ قواعد بصيرة والمهارات
│     ├─ شرح حزمة أدلة أو صياغة مسودة فقط
│     └─ لا SQL حر، لا token، لا نشر أو إنفاق مباشر
```

## ما يظهر للمستخدم الآن

تظهر الآن الأقسام المنفذة فقط: **النظرة، التقويم التسويقي، سجل الحملات، السمعة
وGoogle، المصادر والسياسات**. يعرض التقويم اختيار الفترة المركزي والملخص الرسمي
للمبيعات والمصروف المرتبط المثبت والحملات المتداخلة، مع رسم يومي تفاعلي وخريطة
حرارية تقرآن من عقد خادمي واحد. اليوم المفقود أو المعلّق أو الجزئي فجوة معلّمة،
لا قيمة صفرية. يعرض قسم السمعة سياسة الردود وحالة `غير متصل` ولا يعرض صفراً أو
طابور تقييمات مصطنعاً. لا تظهر قدرات Business أو Ads التفصيلية إلا بعد أول
مزامنة موثقة، وبحسب capability الموصل الفعلية.

## المناسبات والأحداث في التقويم

قسم التسويق **لا يستورد مناسبة ثانية ولا يملك سجل أحداث موازياً**. يقرأ فقط
السياق المنشور والمعتمد من مركز القرار والسياق: الإجازات والمواسم، أحداث الطقس
والمباريات بعد اعتمادها، والأحداث المحلية التي تخص الشركة النشطة. لا يظهر
مرشح بحث أو مراجعة معلقة كأنه حقيقة في تقويم التسويق.

يمكن للحملة أن ترتبط صراحةً بمناسبة أو حدث متزامن، مع حفظ مرجع النسخة المعتمدة؛
لا يسمح بالربط بالتشابه الاسمي. هذا الرابط يشرح السياق في التقويم والتحليل
لاحقاً، ولا يثبت أن المناسبة أو الحملة سببت تغير المبيعات.

## الربط المالي للحملة

التكلفة المخططة في الحملة قيمة تخطيطية وليست مصروفاً فعلياً. لا ينشئ التسويق
فاتورة أو قيداً أو مورداً خاصاً به. زر «إصدار مصروف/فاتورة للحملة» يفتح مسار
المصروفات أو المشتريات المركزي مع اسم الحملة وفترتها ومبلغها المخطط؛ يظل المورد والضريبة والتصنيف
والاعتماد والترحيل والإلغاء ملكاً للمالية. ولا يدخل إلى خريطة حرارة المصروفات
إلا المستند المثبت وفق السياسة المالية.

## خريطة البيانات الموحّدة

الهدف من الموديول هو جمع البيانات ذات الصلة بالحملة في قراءة واحدة قابلة
للمراجعة، لا تخزين نسخ متفرقة أو حَشْو لوحة أرقام. لكل قيمة مصدر وتاريخ
وحداثة وتغطية صريحة:

| الطبقة | ما يجمعه القسم | المصدر المالك | متى يظهر |
| --- | --- | --- | --- |
| الحملة والعرض | الاسم، الوصف، المنصة، الفترة، الحالة المحسوبة، التكلفة المخططة، العرض، الجمهور الوصفي، رابط الوجهة ومرجع UTM اختياري | التسويق | عند إنشاء الحملة |
| التقويم والسياق | أيام الحملة والمنصة، الإجازات والمواسم والطقس والمباريات وأحداث الشركة المعتمدة | مركز القرار والسياق | بعد نشر/اعتماد السياق |
| المالية | المبيعات اليومية، عدد المعاملات عند إتاحته، المصروفات والفواتير المثبتة المرتبطة بالحملة، المورد والتصنيف عبر رابط المستند | المالية | بعد تثبيت المستند أو إسقاط المبيعات |
| Google Ads | الحساب والحملة، الإنفاق المبلّغ، الظهور، النقرات، CTR/CPC، التحويلات وقيمتها، عبارات البحث، الجودة والتغطية وتأخر التحويل | Google Ads | بعد الربط الذاتي وأول مزامنة موثقة؛ قراءة فقط |
| Google Business | الملف وحالة التحقق، ظهور Search/Maps، نقرات الموقع والاتصال والاتجاهات، كلمات البحث الشهرية، التقييمات والردود والمنشورات | Google Business | بعد الربط الذاتي وأول مزامنة موثقة |
| الأصول والمحتوى | رابط/نوع الإعلان أو العرض، نص مختصر، وجهة وUTM، وملف اختياري لاحقاً | التسويق/الملفات المركزية | مع الحاجة؛ لا نظام DAM كامل في البداية |
| القياس والتعلّم | مقارنة الفترة، التغطية، القيود، السياق المتزامن، وملاحظة ختامية منظمة | مركز القرار وحزمة الأدلة | بعد وصول حقائق رسمية |

**حدود المعنى:** تكلفة الحملة المخططة ليست مصروفاً فعلياً؛ Google Ads
conversions ليست مبيعات ERP؛ نقرات Google Business أو طلبات الاتجاه ليست زيارة
أو عميلاً مؤكداً؛ والتزامن بين حملة أو حدث وتغير المبيعات ليس سببية مثبتة.

تظهر البيانات بالتدرج. لا نضيف صفراً أو بطاقة أداء فارغة قبل وصول مصدرها؛ بل
تظهر حالة `غير متصل` أو `بيانات ناقصة/قديمة` وسببها. بعد اكتمالها يجمع التقويم
والتفاصيل هذه الطبقات حول الحملة والفترة نفسها، وتقرأ بصيرة لاحقاً حزمة الأدلة
المقيدة بدلاً من الجداول الخام.

## الرسوم البيانية الحية والتفاعلية

تكون الرسوم جزءاً من **النظرة** و**التقويم التسويقي** و**تفاصيل الحملة**؛ لا
تتحول إلى شاشة تقارير منفصلة. يعتمد التطبيق على `ECharts 6.1` المثبتة بالفعل
وعلى عقود series خادمية، ولا يضيف مكتبة رسوم جديدة لهذه المرحلة.

### الرسم الزمني الرئيسي

يعرض الرسم الشهري أو اليومي بحسب الفترة المختارة:

- أعمدة للمبيعات الفعلية من قراءة المالية الرسمية.
- أعمدة أو مساحة للمصروف التسويقي **المثبت**، مع إظهار التكلفة المخططة كطبقة
  منفصلة اختيارية لا كتكلفة فعلية.
- خطاً لعدد الحملات النشطة؛ له محور مستقل لأنه عدد وليس مبلغاً.
- علامات زمنية للحملات والعروض والمناسبات والأحداث المعتمدة والطقس عند توفره.
- فترات قبل/أثناء/بعد داخل تفاصيل الحملة، مع تعريف المقارنة والتغطية.

المبيعات والمصروفات تستخدم محور مبلغ واحد وعملة واحدة؛ لا تخلط عملات، ولا
تخلط عدد الحملات بالمبلغ. كل نقطة تحمل مصدرها ووقت حسابها وحالة تغطيتها.

### التفاعل والحركة

- حركة دخول هادئة للأعمدة والخطوط، وانتقال سلس عند تغيير الشركة أو الفترة أو
  وصول مزامنة جديدة؛ لا حركة تزيينية متواصلة تشتت المدير.
- tooltip واضح عند التمرير يعرض: الفترة، المبيعات، المصروف المثبت، عدد
  الحملات، التكلفة المخططة إن وجدت، الأحداث المتزامنة، وحالة الجودة.
- تكبير وسحب زمني للفترات الطويلة، مع مرشحات لإظهار أو إخفاء طبقات المبيعات
  والمصروفات والحملات والسياق.
- الضغط على شهر أو يوم أو علامة حملة يفتح القراءة أو الحملة أو المستندات
  المرتبطة ضمن الصلاحيات، ولا ينفذ أمراً مالياً أو خارجياً.
- ألوان موحدة: المبيعات أخضر، المصروفات برتقالي، الحملات أزرق، والسياق
  رمادي/بنفسجي؛ لا تستخدم الألوان وحدها لنقل المعنى.

### الصدق والإتاحة

- اليوم أو الشهر الناقص أو القديم يظهر فجوة أو شارة `بيانات غير مكتملة/قديمة`،
  ولا يرسم صفراً أو خطاً موصولاً يوهم باكتمال الحقيقة.
- يعرض أسفل كل رسم جدولاً بديلاً مكافئاً، وتبقى tooltip والمرشحات قابلة
  للاستخدام بلوحة المفاتيح.
- يحترم الرسم إعداد تقليل الحركة؛ في هذه الحالة تظهر النتائج مباشرة بلا
  انتقالات مطولة.
- بصيرة تشرح ما يظهر في الرسم عبر حزمة الأدلة، ولا تحسب الأرقام أو تنشئ
  استنتاجاً سببياً من شكل الرسم.

## النتيجة المبسطة وبصيرة للتسويق

لا يرى المدير الجداول الكبيرة أولاً. تظهر **النظرة التسويقية** بعد توفر الحقائق
المعتمدة بهذا الترتيب:

```text
النظرة التسويقية
├─ أهم 3 ملاحظات للفترة
│  ├─ ماذا تغير؟
│  ├─ ما الدليل؟
│  ├─ ما السياق المتزامن؟
│  └─ ما الخطوة المقترحة للمراجعة؟
├─ التقويم الحراري والرسم الزمني
├─ الحملات النشطة
│  └─ قراءة مبسطة لكل حملة
└─ اسأل بصيرة عن هذه الفترة              [بعد بوابة المهارة]
```

كل بطاقة قرار تفصل دائماً بين:

1. **الحقيقة:** مثل تغير المبيعات أو المصروف المثبت ضمن فترة محددة.
2. **جودة البيانات:** التغطية والحداثة والأيام المستبعدة أو الناقصة.
3. **السياق المتزامن:** الحملة والطقس والمناسبة أو حدث الشركة.
4. **الفرضية والخطوة المقترحة:** صياغة احتمالية للمراجعة، وليست سبباً مثبتاً
   أو أمراً بتنفيذ أو إنفاق.

مثال العرض المقصود:

> انخفضت المبيعات 12% خلال حملة «خصم الظهر». التغطية مكتملة، وكانت الحرارة
> مرتفعة، والمصروف الفعلي للحملة 3,200 ر.س. لا يمكن إثبات السبب من هذا
> التزامن. راجع مدة العرض وتوقيته، وقارن أيام الأسبوع المماثلة قبل تمديده.

زر **«كيف وصلنا لهذه القراءة؟»** يفتح حزمة الأدلة المقيدة: قراءة المبيعات،
المستندات المالية المرتبطة، الحملة، السياق، الفترة، سياسة المقارنة، الأيام
المستبعدة، وحداثة كل مصدر. لا يعرض prompt مخفياً أو استعلام قاعدة بيانات حراً.

### مهارات بصيرة المقترحة

| المهارة | الدور | مستوى الصلاحية |
| --- | --- | --- |
| `marketing.performance_analyst` | يفسر الحملة والمبيعات والمصروفات وGoogle والسياق عبر الأدلة | S2 قراءة وتحليل فقط |
| `marketing.campaign_advisor` | يقترح فكرة عرض أو توقيتاً أو منصة للمراجعة | S2 توصية فقط |
| `marketing.campaign_draft_writer` | ينشئ مسودة اسم ووصف وفترة وUTM مقترح للحملة | S3 مسودة داخلية |
| `marketing.reputation_draft_writer` | ينشئ مسودة رد أو منشور وفق سياسة الشركة | S3 مسودة فقط |
| `google_business_publisher` | ينفذ عبر policy وموافقة وإيصال منفصلين | ناشر محكوم؛ ليس بصيرة مباشرة |

حالة المهارات في هذه المرحلة `PLANNED`. لا تفعل قبل قرار مزود الذكاء والخصوصية
والتكلفة، عقود القراءة، حزمة الأدلة، تقييمات عربية، وقبول Pilot محدود.

### المسار الحاكم

```text
مالية + حملات + تقويم/سياق + Google
                 ↓
   قراءة خادمية موحدة + جودة + حزمة أدلة
                 ↓
      قواعد حتمية: مقارنة وتنبيه وملاحظة
                 ↓
        بصيرة تشرح بلغة بسيطة وتقترح
                 ↓
       المستخدم يراجع ويقرر أو ينشئ مسودة
```

بصيرة لا تجمع البيانات من الجداول مباشرة ولا تخمّن. تستلم حزمة جاهزة فيها
الأرقام والمصادر والجودة، ثم تبسطها وتعرض فرضيات واقتراحات. تغذية المستخدم
منظمة: `مفيد`، `غير مناسب`، `البيانات ناقصة`، `المقارنة غير مناسبة`، أو
`سبب مختلف` مع ملاحظة اختيارية. تحفظ هذه التغذية في ذاكرة تعلّم معزولة للشركة
وتحسن التقييمات والقواعد بإصدار ومراجعة بشرية؛ لا يوجد تعلم تلقائي أو نقل
معرفة بين الشركات.

## ترتيب فتح الفروع

1. توسيع سجل الحملة إلى بطاقة بيانات موحدة: تكلفة مخططة وعملة، عرض وجمهور
   وصفي ووجهة/UTM اختياري، حالة محسوبة بالتاريخ، تفاصيل الحملة وسياقها.
2. بناء التقويم التسويقي وربط مستندات المالية بالحملة من دون تكرار المالية أو
   السياق.
3. بناء بوابة الربط الذاتي المشتركة كآخر خطوة، ثم تفعيل شركة من الواجهة
   باختيار صريح للحساب أو الموقع.
4. Google Ads للقراءة فقط: لا تظهر قدرات الأداء قبل وصول أول مزامنة موثقة.
5. Google Business للقراءة أولاً، ثم طابور الردود والنشر المحكوم.
6. بصيرة زر سياقي يشرح حزمة أدلة القسم؛ لا تتجاوز أي فرع أو سياسة نشر.

## حدود الملكية

- هذا الموديول يملك الحملات وسياقها، حقائق Google المستقبلية، السمعة، وسياسة
  الرد. التقويم يستهلك الأحداث المعتمدة ولا يملك استيرادها أو اعتمادها.
- **مركز القرار والسياق** يملك المناسبات والأحداث والتنبيهات وحزم الأدلة؛
  التقويم التسويقي يقرأها فقط ولا يغيرها.
- **المالية** تبقى المصدر الوحيد لمبيعات ERP والمشتريات؛ لا تظهر تحويلات Ads
  أو نقرات Google على أنها مبيعات أو إيراد محاسبي.
- **بصيرة** مفسر ومسودات محكومة، وليست فرعاً تنفيذياً أو موصلاً عاماً.
