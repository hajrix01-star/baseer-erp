# عقد MKT-02C — ربط Google Business بخطوة واحدة لـ ARZ

**الحالة:** G0–G4 معتمدة للتنفيذ المحلي؛ لا تشغيل حي للمراجعات أو مزامنة أو نشر في هذه الشريحة.
**المرجع:** `BASEER-ARCH v1.0` / `BASEER-IMPACT-2026-09-05-MARKETING-REPUTATION-MIGRATION-PROGRAM` / ADR-MKT-001.
**المالك:** شركة ARZ فقط في تجربة واحدة؛ يكرر المعلم الشامي العقد والدليل لاحقاً باتصال مستقل.

## G0 — النطاق ومعيار القبول

المستخدم ينفذ إجراءً واحداً في Baseer: **«ربط Google Business»**، ثم يمنح موافقته في
صفحة Google الإلزامية. بعد عودة callback، يقرأ الخادم الحسابات والمواقع ضمن grant نفسه؛ إذا
وجد زوجاً وحيداً فقط (حساب واحد وموقع واحد) يحفظه ذَرّياً ويحوّل الاتصال إلى
`AUTHORIZED_READ_ONLY_SELECTED`، ثم يعيده callback تلقائياً إلى صفحة الاتصالات. لا تظهر
للمستخدم شاشة اختيار أو زر تأكيد إضافي أو صفحة JSON.

لا يختار النظام بالاسم أو «أول نتيجة»: إذا وجد أكثر من حساب أو أكثر من موقع، يبقى الاتصال في
`AUTHORIZED_AWAITING_SELECTION` مع حالة واضحة **«لم يُحفظ مورد تلقائياً»**. قد يكون السبب تعدد
الموارد أو تعذر قراءة Google مؤقتاً. لا توجد رحلة عميل ثانية ولا اختيار يدوي في Baseer؛ هي منع آمن
من ربط فرع خاطئ حتى يضاف قرار موارد متعددة صريح. لا تدخل شركات
أخرى أو Google Ads. لا تبدأ مزامنة تقييمات أو أداء، ولا نشر أو رد آلي؛ سياسة الرد التلقائي لا
تتغير.

لا يعاد إلى المتصفح refresh/access token أو client secret أو raw provider payload. النتيجة
بعد الحفظ هي `selectedReadOnly=true` فقط، لا دليل على وصول التقييمات أو تشغيل الردود.

## G1 — السعة والاستمرارية

- رحلة حرجة: OAuth → اكتشاف حساب/موقع وحيد → حفظ ذَرّي؛ حتى 3 طلبات Google متسلسلة بعد callback و`12s` لكل طلب.
- حد أولي: `100` حساب و`100` موقع للحساب. لا تخزين cache لنتائج discovery أو عناوينها؛ يحفظ mapping المختار فقط.
- لا retry أعمى. اختيار الشركة يقفل transactionally؛ النقر المكرر آمن. تسجل قياسات الفشل 401/403/429/5xx والمدة لاحقاً.

## G2 — البيانات والعقود والعزل

- يفك الخادم فقط `MarketingProviderCredentialEnvelope` الموجود مع AAD tenant/company/provider؛ access token مؤقت في الذاكرة فقط.
- يستخدم `MarketingGoogleBusinessLocationMapping` القائم، ويحدّث mapping واحداً مقيداً بالشركة أو ينشئه؛ وتصبح حالة `MarketingProviderConnection` هي مرجع القراءة العام. يضيف الترحيل قيمة enum فقط ثم backfill idempotent للاختيارات المحفوظة المطابقة لنفس tenant/company/connection/provider؛ لا ينقل token أو secret أو بيانات Google.
- لا توجد endpoints عامة لـ `resources` أو `locations` أو `selection` في هذه المرحلة. أي تجربة موارد متعددة تحتاج قراراً معمارياً جديداً ومساراً مستقلاً.
- تتحقق الخدمة من allowlist ARZ، الصلاحية، حالة الاتصال وenvelope قبل egress. تقبل فقط `accounts/{id}` و`locations/{id}` وتثبت أن الموقع جاء من الحساب قبل الحفظ.
- العقد يعرض resource name واسم الحساب/نوعه وعنوان الموقع المختصر فقط؛ لا HTML أو raw payload. audit لا يسجل معرف Google أو عنواناً أو token.

## G3 — التقنية والمسار المباشر

لا SDK ولا حزمة جديدة. يعيد الخادم استخدام `fetch` وvault وplatform service القائمة، ويقصر egress على:

- `https://oauth2.googleapis.com/token` لتحديث access token.
- `https://mybusinessaccountmanagement.googleapis.com/v1/accounts` للحسابات.
- `https://mybusinessbusinessinformation.googleapis.com/v1/accounts/*/locations` للمواقع.

لا يستدعي المتصفح Google مباشرة ولا يسمح بأي host/method إضافي. هذا يعيد استخدام vault وmapping بدلاً من cache أو worker جديد.

## G4 — تجربة المدير

تعرض الواجهة إجراءً واحداً: «ربط Google Business». تستخدم `BaseerCard` و`BaseerButton` و`BaseerStatusBadge` المركزية، عربي/إنجليزي، RTL/LTR، جوال/سطح مكتب. بعد العودة تعرض إما «تم الربط واختيار الموقع للقراءة فقط» أو «يلزم تعيين مورد افتراضي». تظهر دائماً عبارة: «الربط لا يبدأ مزامنة التقييمات ولا الرد الآلي» مع حالات تحميل وفراغ وخطأ.

## التحقق وتكرار المعلم الشامي

اختبارات mock ترفض شركة غير ARZ قبل egress، وتثبت allowlist، حد المورد الوحيد، عدم اختيار اسم أو أول نتيجة، عدم تسريب token/raw payload، والكتابة الذرية للحالة والموقع. اختبار الواجهة يثبت إجراء Baseer واحداً وعدم ظهور التجربة للمعلم الشامي أو Ads. بعد نشر ARZ: موافقة Google ثم تحقق من الحالة المركزية والموقع المحفوظ؛ لا يفتح sync أو الردود أو حذف القديم.

للمعلم الشامي لا ينسخ token أو mapping أو UUID: allowlist مستقل → OAuth مستقل/مخوّل → اكتشاف مورد وحيد → لقطة دليل → مطابقة. عند تعدد الموارد، يحدد مسؤول المنصة المورد الافتراضي قبل تشغيل الاتصال؛ لا يختار النظام فرعاً بالتخمين.
