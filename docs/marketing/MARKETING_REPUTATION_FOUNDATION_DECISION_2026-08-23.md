# قرار تأسيس الأداء التسويقي والسمعة — 2026-08-23

## السلطة والنطاق

اعتمد المالك بداية نطاق واحد نشط: **الأداء التسويقي والسمعة**
(`Marketing & Reputation`). هذا القرار هو المرجع الحالي للمرحلة الأولى ويكمل
قرار نطاق الأداء التسويقي السابق وملحق ناشر Google Business. عند التعارض،
يتقدم هذا القرار ثم ملحق 2026-08-21 على أي نص تاريخي يجيز الرد أو النشر الآلي.

المرحلة المفعلة هي **Gate A1 — سجل الحملات الداخلي** فقط. ليست ربط Google،
ولا تحليلاً آلياً، ولا نظام إنفاق، ولا امتداداً للمالية.

## الملكية والحدود

| المكوّن | يملك | لا يملك |
| --- | --- | --- |
| الأداء التسويقي والسمعة | سجل الحملات وسياقها، وحقائق الموفر بعد بوابة مستقلة | دفتر الأستاذ، مبيعات ERP، أو تنفيذ Google في A1 |
| المالية والعمليات | الحقيقة المالية والمبيعات والمشتريات | حقائق أو مزامنة التسويق |
| مركز القرار والسياق | قراءات Marketing الرسمية لاحقاً | حملة، مزامنة، أو كتابة Google |
| بصيرة | شرح مقيد ومسودة مستقبلية | SQL حر أو نشر أو إنفاق أو تعديل موفر |
| الإدارة | الأدوار والعضويات | أسرار Google أو تفويض النشر |

`Company.contextLocationCode` سياق جغرافي فقط. ليس فرعاً مالياً ولا
`googleLocationId` ولا يثبت مبيعات موقع Google.

## ما نُفذ في A1

- موديول ظاهر باسم **الأداء التسويقي والسمعة** بأقسام: النظرة، سجل الحملات،
  السمعة وGoogle، المصادر والسياسات.
- سجل حملات معزول بالشركة: عنوان عربي/إنجليزي اختياري، منصة، مرجع خارجي وصفي
  غير موثوق، فترة، حالة، هدف وملاحظة.
- دورة حياة صغيرة: `DRAFT → PLANNED → ACTIVE → COMPLETED/CANCELLED` ثم أرشفة
  محكومة بلا حذف. كل أمر يستخدم idempotency وسجل تدقيق.
- قراءة حالة صادقة: `Google Ads` و`Google Business` هما `NOT_CONNECTED`؛
  لا يعني ذلك صفراً أو غياب تقييمات أو انعدام إنفاق.
- عقود Zod مرقمة بالكود، وRLS/CompanyContext/RBAC في الخادم.
- نماذج إنشاء وتعديل وأرشفة الحملة تستخدم بوابة Baseer الموحدة فوق
  React Hook Form وZod؛ ويظل التقويم والاختيارات ضمن مكونات Baseer المركزية.

الصلاحيتان المستخدمتان الآن فقط هما `marketing.insights.read` و
`marketing.campaign.write`. الصلاحيات الخاصة بـGoogle تبقى محجوزة ولا تنشئ
اتصالاً أو حق وصول بذاتها.

## ممنوعات A1 الصريحة

- OAuth أو مفاتيح أو SDK أو HTTP إلى Google أو worker أو webhook.
- استيراد يدوي مزعوم كحقائق Google، أو تخزين تقييمات/محتوى ملف/منشورات.
- ميزانية أو bid أو pause/resume أو إنفاق أو ROAS.
- ربط بالحقيقة المالية أو مبيعات ERP أو ادعاء سببية أو أثر مبيعات.
- بصيرة، مسودات ردود، نشر يدوي أو تلقائي.

## البوابات اللاحقة

1. **P2 Ads read-only:** Provider Decision Record مستقل، OAuth خادمي مشفر،
   حقائق يومية غير قابلة للتكرار، إيصالات مزامنة، جودة/حداثة. تحويل Google
   ليس مبيعات ERP ولا يملك الموصل أي endpoint تعديل.
2. **P3 Google Business read ثم ناشر يدوي:** موافقة Google وPDR منفصل؛
   المعاينة → تأكيد صريح من ناشر مخول → outbox/idempotency → receipt →
   resync/audit. لا نشر تلقائي، بما فيه ردود التقييمات.
3. **P4 القراءة التحليلية وبصيرة:** فقط بعد حقائق الموفر وقراءة مبيعات رسمية
   وسياسة مقارنة/إسناد وتقييمات عربية وقرار مزود الذكاء والخصوصية والتكلفة.
   الناتج يصف ارتباطاً زمنياً لا سبباً.

## قبول A1

- لا يستطيع مستخدم أو شركة قراءة أو تعديل حملة شركة أخرى.
- replay لنفس idempotency يعيد نفس الإيصال، واختلاف الطلب يرفض.
- كل تعديل أو أرشفة يكتب AuditEvent؛ لا حذف صلب للحملة.
- لا يتغير Journal أو خزينة أو وثيقة مالية من أي أمر Marketing.
- لا يظهر `NOT_CONNECTED` كرقم تسويق أو حكم على السمعة.
- تستخدم الواجهة مكونات Baseer المركزية فقط، بما فيها بوابة RHF/Zod للنماذج،
  وتنجح في العربية والإنجليزية.
- يحرس `npm run check:marketing-gate-a1` نطاق A1: عزل الشركة وRLS وAudit/
  idempotency، ومنع أي OAuth أو SDK أو egress للموفر.

## سجل اللجنة

شارك في القرار: معماري النظام، مختص القياس والتحليل، مختص الحوكمة/Google،
ومختص تجربة المساعد. اتفقوا على بناء الحقائق والحدود قبل الذكاء أو الموصلات؛
ولا توجد في A1 أي بيانات مزود أو سر أو تنفيذ خارجي.
