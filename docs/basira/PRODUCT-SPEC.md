# مواصفات منتج بصيرة التلقائية

**المرجع:** `BASIRA-AUTO v1.0` · **حالة المواصفات:** مقترحة للتنفيذ المرحلي، وليست ميزة منفذة.

## 1. المشكلة والهدف

الواجهة الحالية تجمع مهارات مخططة وتجريبية ومتحققاً منها، وتعرض فحصاً وتفعيلاً وحدوداً لكل مهارة. المستخدم يريد الاستفادة داخل القسم، ولا يريد إدارة دورة اعتماد برمجية. بعض البطاقات غير قابلة للتفعيل لأن مسار تشغيلها الموحد غير مكتمل، وليس بسبب إعداد يستطيع المستخدم تصحيحه.

الهدف: إعداد بسيط للشركة، اختيار تلقائي للقدرة المناسبة، تفسير واضح مرتبط بالدليل، تكلفة مضبوطة، وتدخل الإنسان فقط عند إعداد أولي أو قرار فعلي يحتاجه.

## 2. معنى «تلقائية وديناميكية»

- **تلقائية الاختيار:** القسم والإجراء يحددان المهمة، والخادم يختار المهارة والإصدار المعتمدين.
- **تلقائية الجاهزية:** النظام يقرأ دليل اعتماد الإصدار وفحص الشركة وحالة المزود والبيانات؛ لا يطلب من المالك الضغط على «فحص الجاهزية» لكل مهارة.
- **تلقائية الإتاحة:** المهارة المستقرة الجديدة تصبح قابلة للاستخدام ضمن سياسة الشركة القائمة إذا بقيت داخل نطاق البيانات والأفعال والمزود والتكلفة المعتمد. التغيير خارج النطاق يحتاج اعتماد سياسة جديداً، ولا يعامل كتحديث عادي.
- **تلقائية إعادة الاستخدام:** يعرض النظام تفسيراً صالحاً مطابقاً دون اتصال جديد بالمزود.
- **التشغيل الاستباقي:** مرحلة لاحقة مستقلة لأحداث محددة ومصرح بها. الإعداد الأول لا يمنح مراقبة خلفية غير محدودة.
- **ليست التلقائية** إنشاء مهارات أو تعديل prompts أو اعتماد نتائج الجودة بواسطة النموذج أثناء التشغيل. إضافة مهارة عملية تطوير وإصدار مختبرة.

## 3. المستخدمون والتدخل الأدنى

| المستخدم | ما يفعله |
|---|---|
| مالك المستأجر/مخوّل إدارة المزود | يجهز اتصال المزود المركزي الموجود ويعالج انتهاء الاعتماد أو تغيير المزود |
| المسؤول المخوّل عن سياسة الشركة | يشغّل بصيرة للشركة ويحدد ميزانيتها ويستطيع إيقافها؛ حدود الدور تعتمد على كتالوج الصلاحيات الخادمي |
| مستخدم القسم | يطلب شرحاً أو تحليلاً في سياق بيانات يملك حق قراءتها |
| فريق التشغيل والتطوير | يدير جاهزية الإصدار، التقييمات، إعدادات الخادم، الرصد وحل الأعطال الفنية |

إعداد المزود الحالي يخص المستأجر، وليس لكل شركة اتصال مستقل بالضرورة. تستخدم الشركة الاتصال المعتمد المتاح لها؛ لا تطلب الواجهة إدخال المفتاح مرة أخرى لكل شركة.

## 4. الإعداد الأول

1. إذا كان مزود معتمد متاحاً، تعرض الواجهة اسمه وحالته وتستخدمه. عند غيابه تعرض خطوة اتصال واحدة لصاحب الصلاحية المناسب.
2. يحدد المسؤول سقف الإنفاق الشهري بالدولار من خلال إدخال واضح. لا نخترع ميزانية مدفوعة ولا نملأ رقماً يجعل الحفظ موافقة مالية غير مقصودة.
3. يعرض ملخص: «شرح وتحليل ضمن صلاحيات المستخدم، دون تعديل السجلات أو نشر محتوى». التشغيل الاستباقي مغلق في الإصدار الأول.
4. يضغط «تشغيل بصيرة». ينفذ الخادم عملية إعداد مترابطة ومنع تكرار، ويهيئ المهارات المؤهلة في الخلفية.
5. إن كانت القدرات المتاحة تجريبية فقط، يظهر ضمن الخطوة نفسها خيار واضح للمشاركة في تجربتي القرار والتسويق. لا يسمح التشغيل العام وحده بتجاوز شرط موافقة التجربة القائم.

إعداد الشركة لا يرفع حدود المزود أو المستأجر؛ تعرض الواجهة إذا كان الحد الفعلي أقل من الميزانية المطلوبة. لا توجد ميزانية منفصلة يلزم المالك إدخالها لكل مهارة في الرحلة المعتادة.

## 5. واجهة الإدارة المقترحة

بطاقة رئيسية: حالة بصيرة، الاتصال المستخدم، الاستهلاك والرصيد المتاح لهذا الشهر، موعد تجدد الفترة، زر إيقاف/استئناف، ورابط «إعدادات متقدمة». الحسابات والحالات نصوص/قيم من الخادم.

| الحالة | النص الأساسي المقترح | الإجراء |
|---|---|---|
| جاهزة | بصيرة تعمل | عرض الاستخدام أو إيقاف |
| موقوفة بقرار المسؤول | بصيرة موقوفة | استئناف بواسطة مخوّل |
| المزود غير مهيأ | أكمل اتصال الذكاء الاصطناعي | إعداد الاتصال لصاحب الصلاحية |
| مشكلة اتصال | تعذّر الاتصال مؤقتاً | حالة واضحة؛ لا مطالبة المستخدم بفحص مهاراته |
| الميزانية مستنفدة | تم بلوغ سقف الإنفاق | تعديل السقف بواسطة مخوّل أو انتظار الفترة التالية |
| لا توجد قدرات مؤهلة | لا توجد قدرات جاهزة حالياً | يراجع فريق التشغيل السبب؛ لا زر تفعيل وهمي |
| قدرات جزئية متاحة | بصيرة تعمل؛ بعض القدرات غير متاحة | عرض المتاح، والتفاصيل اختيارية |

الإعدادات المتقدمة تعرض القدرات المتاحة/التجريبية/القادمة وأسباب التعطيل والسجل. معرفات المهارات وS1–S4 ومتغيرات الخادم تخص التفاصيل التقنية. لا تعرّف للمستخدم زر «كل المهارات» يعيد فتح المهارات الموقوفة.

## 6. داخل الأقسام

| القسم/المهمة | التجربة المطلوبة | نطاق أول إصدار |
|---|---|---|
| تنبيه في مركز القرار | «اشرح التنبيه» يعيد تفسيراً محفوظاً صالحاً أو يطلب واحداً من الدليل الخادمي | نعم، ضمن شروط التجربة |
| حملة في التسويق | «حلّل النتائج» مع الفترة والمصادر وفجوات البيانات، دون ادعاء السببية | نعم، ضمن شروط التجربة |
| دليل الإدارة | شرح الإعدادات المسموحة دون تغيير المستخدمين أو الصلاحيات | لاحقاً بعد بناء المسار |
| التقفيل والمحاسبة | شرح قراءات مالية رسمية متصالحة؛ لا حسابات من النموذج | لاحقاً لكل شريحة قبول |
| دفتر المالك | جواب من الملخص الخادمي المحدد | لاحقاً بعد توحيد التشغيل |
| المستندات | تلخيص/استخراج/تصنيف كمسودة للمراجعة | لاحقاً؛ نطاق بيانات مستقل |
| نشر ردود Google | يبقى مسار النشر البشري القائم؛ ليس قدرة تلقائية لهذا البرنامج | خارج البرنامج الحالي |

إذا فتح المستخدم الصفحة، تظهر البيانات والتفسير المحفوظ الصالح إن وجد. لا استدعاء مدفوع بسبب mount أو polling أو تبديل tab أو الفترة. الطلب الأول زر سياقي؛ لا حاجة لاختيار المهارة.

المحادثة الحرة العابرة لكل ERP ليست في الإصدار الأول. توجيه `module + action + subject` الحتمي يحقق الحاجة بأقل تعقيد. إذا أضيف سؤال حر لاحقاً، لا يسمح النص بتمرير SQL أو اختيار مورد بلا صلاحية أو تجاوز نطاق القسم.

## 7. متى نسأل المستخدم؟

| الموقف | التعامل |
|---|---|
| اختيار مهارة أو تحديثها داخل النطاق المعتمد | دون سؤال |
| تشغيل فحص داخلي غير مدفوع/إعادة استخدام تفسير | دون سؤال |
| نقص معلومات يعرفها الخادم مثل الفترة الحالية | يستخرجها من السياق الموثوق |
| سؤال يحتمل مصدرين مؤثرين مختلفين | سؤال واحد قصير للمستخدم؛ لا تخمين لمصدر مالي |
| رفع سقف مالي/تغيير مزود أو نطاق بيانات/أفعال جديد | قرار مسؤول مخوّل مرة واحدة عند التغيير |
| مشكلة خادم فنية | مهمة تشغيل وتنبيه قابل للتصرف؛ لا تطلب اختيار flags من المالك |
| فعل نشر أو تعديل مالي | لا ينفذه AI؛ يسير عبر إجراء العمل القائم وموافقاته |

«أقل تدخل» لا يعني أن سؤال «هل وافقت؟» يتكرر بعد كل عملية تحليل عادية ضمن النطاق المعتمد.

## 8. اللغة والإتاحة

العربية والإنجليزية من قاموس المشروع، RTL/LTR كاملان، والأرقام الغربية `0–9` في اللغتين. لا تمرير أفقي للبطاقة الرئيسية على عرض `360px`. الحالات لا تعتمد على اللون وحده، والأزرار تدعم لوحة المفاتيح وقارئ الشاشة وحالة الانشغال. تعاد استخدام مكونات Baseer المركزية. لا حركة أو مكتبة جديدة مطلوبة لهذا البرنامج.

## 9. مقاييس نجاح المنتج — أهداف قبول وليست قياسات حالية

- إعداد بصيرة في زيارة واحدة، وهدف إتمام خلال `2` دقيقة عند وجود اتصال معتمد مسبقاً، يستثنى انتظار اعتماد المزود الخارجي.
- `0` خطوات تفعيل مهارة منفردة في الرحلة المعتادة بعد الإعداد.
- `0` طلبات مزود عند فتح الصفحة/تحديثها/تغيير الفلاتر دون طلب تحليل صريح.
- الطلب المطابق المتزامن ينتج استدعاء مزود واحداً على الأكثر؛ التفسير الصالح يعاد استخدامه بلا تكلفة مزود جديدة.
- أسباب الفشل القابلة للمعالجة تعرض إجراءً مناسباً لصاحب الصلاحية، دون أسرار أو مصطلحات خادم في الواجهة الأساسية.
- لا وصول لشركة أخرى ولا تغيير مالي أو نشر تلقائي؛ تثبت باختبارات سلبية إلزامية.

## 10. حدود هذا الإصدار

لا إكمال صوري للمهارات المخططة بتبديل status، ولا تدريب ذاتي أو RAG عام، ولا استبدال مزود تلقائي بغير مزود معتمد، ولا تعديل ميزانية أو صلاحية تلقائياً. المرحلة الاستباقية تتطلب عقد أحداث وتكلفة وتفويض مستقل، وتبقى معطلة حتى اكتماله.
