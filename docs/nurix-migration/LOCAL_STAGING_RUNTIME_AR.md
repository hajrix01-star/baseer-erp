# تشغيل بوابة مراجعة ترحيل نوركس محليًا

هذه الوثيقة تخص قاعدة `baseer_migration_staging` المحلية فقط، ولا تصلح للإنتاج أو لقاعدة تطبيق مشتركة.

1. انسخ `apps/api/.env.nurix-migration-staging.example` إلى `apps/api/.env.nurix-migration-staging`، وأدخل مستخدم قاعدة التدريج فقط. الملف الفعلي متجاهل من Git ولا يوضع فيه سر في التوثيق.
2. ابنِ contracts ثم API ثم الواجهة.
3. شغّل الـAPI بمتغير `BASEER_LOCAL_ENV_PROFILE=nurix-migration-staging`؛ يبقى ملف `.env.baseer-test` هو الافتراضي ولا يتغير. عند تشغيل الواجهة على منفذ مستقل، اضبط `BASEER_CORS_ALLOWED_ORIGINS=http://127.0.0.1:5194` (أو أصل الواجهة الفعلي فقط). لا تضع `*`.
4. تحقق من `/v1/health/ready` قبل فتح الواجهة، ثم سجل الدخول بمالك tenant الترحيل فقط.

قبل التشغيل يجب إنشاء أو تفعيل **مالك staging مستقل** لهذا المستأجر. لا تنسخ مستخدمًا أو password hash من قاعدة اختبار أو إنتاج، ولا تستخدم حسابًا مشتركًا. ينشأ الحساب بدعوة أو كلمة مرور مؤقتة تُسلّم خارج السجل، ثم يفعّل MFA/كلمة مرور دائمة وفق سياسة بصير.

حواجز التشغيل:

- لا تشغيل إذا كانت البصمة أو RLS أو ترحيلات Prisma لا تطابق سجل التدريج.
- لا يمنح هذا الملف صلاحية اعتماد القرارات أو إدخال الموردين تلقائيًا. إنشاء الموردين المبدئيين لا يتم إلا بطلب واضح من مالك المستأجر، وبعد اعتماد خرائط الشركات والحسابات والفئات؛ ولا يشمل مستندات مالية أو أرصدة.
- لا تستخدم ملف بيئة الاختبار لعرض بيانات الترحيل، ولا تستخدم ملف بيئة الترحيل في الإنتاج.
