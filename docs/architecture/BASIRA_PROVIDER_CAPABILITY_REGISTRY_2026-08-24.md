# سجل قدرات مزوّدي بصيرة والنماذج — 24 أغسطس 2026

## القرار

لا يصبح أي مفتاح API أو اسم نموذج مساراً لإرسال بيانات ERP. تملك Baseer سجل
قدرات خادمياً واحداً (`ai-provider-capability-registry.ts`) يعرّف زوج
`provider + model` المؤهل، والمهارات التي يستطيع تشغيلها، وملف حدّ التوكن
المحلي. لا توجد خانة اسم نموذج حر في واجهة المالك.

## النطاق المعتمد الآن

| البند | الحالة |
| --- | --- |
| OpenAI Compatible / `gpt-5-mini` | متاح للإعداد والتجربة المقيدة |
| محوّل OpenAI Responses | مطبق ومحدود بلا أدوات أو SQL أو صلاحيات كتابة |
| عدّاد التوكن المحلي | `gpt-tokenizer@4.0.0/gpt-5-mini`، قبل الخروج |
| السعر | إصدار سعر غير قابل للتعديل في `AiModelPriceRevision` |
| المهارات المسموحة | محلل مركز القرار، محلل الأداء التسويقي |
| Anthropic وGoogle | غير قابلين للإعداد أو التفعيل حالياً |

### المسارات المهيأة والمقفلة

تظهر المسارات الآتية في شاشة المالك كسجلّات **مخطط لها**، وليست حقول مفاتيح
ولا إعدادات حية:

| المزوّد والنموذج المرجعي | وضعه | لماذا لا يفتح بعد؟ |
| --- | --- | --- |
| Google Gemini / `gemini-3.7-flash` | مقفل | قرار الخصوصية والمنطقة، محول Gemini، عداد، سعر، تقييم عربي، وفحص اتصال |
| Alibaba DashScope Qwen / `qwen3.7-flash` | مقفل | نفس البوابة، ولا يكفي توافق OpenAI الشكلي |
| DeepSeek / `deepseek-v4-flash` | مقفل | نفس البوابة، مع مراجعة سعره المتغير بحسب نافذة التسعير |

اختيرت المعرفات من صفحات المزود الرسمية وقت التوثيق: [Gemini models](https://ai.google.dev/gemini-api/docs/models)، [DashScope model catalogue](https://help.aliyun.com/zh/model-studio/models)، و[DeepSeek models and pricing](https://api-docs.deepseek.com/quick_start/pricing/). لا تعني هذه الإحالات أن النموذج أصبح مسموحاً؛ يتغير اسم النموذج أو سعره أحياناً، ولذلك يبقى الإدخال مقفلاً إلى أن تمر البوابة كاملة.

لا يعني ظهور enum لمزوّد مستقبلي في العقود أنه قابل للتشغيل. ترفض الخدمة كل
زوج غير موجود في السجل قبل تشفير المفتاح، وعند الفحص والتفعيل. كما يرفض وقت
التشغيل أي ملف قديم لا يطابق قدرة حية للمهارة المطلوبة.

## لماذا لا يكون التحويل بين أي ذكاء فورياً؟

المزوّد والنموذج يؤثران في أربعة أمور تشغيلية لا يمكن تخمينها: طريقة النداء
والبنية المنظمة، عدّاد التوكن، سعر الحجز، وتقييم المخرجات العربية. لذلك لا
يكفي تغيير المفتاح. مع ذلك لا تعني إضافة نموذج جديد إعادة بناء بصيرة؛ إنها
إضافة إصدار محدود إلى سجل موحّد وفق البوابة أدناه.

## بوابة إضافة نموذج أو مزوّد

1. قرار خصوصية/منطقة/تكلفة وملكية مفتاح واضح.
2. محوّل خادمي محدد للمزوّد، بلا fallback ولا صلاحيات أدوات واسعة.
3. عدّاد محلي متحقق للنموذج وحدود إدخال وإخراج محافظة.
4. إصدار سعر جديد موثق من المصدر الرسمي في migration، مع تاريخ سريان.
5. تحديد المهارات المسموحة فقط، ثم تشغيل تقييمات عربية لكل مهارة وسياسة.
6. إضافة القدرة بحالة `AVAILABLE` بعد اجتياز اللجنة؛ قبل ذلك لا تصل إليها
   الواجهة ولا يقبلها الخادم.
7. تجربة محدودة ومراقبة الإيصالات والتكلفة؛ لا يتحول إلى بديل تلقائي للنموذج
   الحالي.

المسارات الثلاثة المقفلة تملك الآن نوع مزوّد صريحاً في Prisma، سجل قدرة
بالنموذج المرجعي، وبوابات فتح ظاهرة في واجهة المالك. لا تملك API key أو
endpoint أو adapter أو سعر مخزناً، وبالتالي لا يوجد مسار خروج شبكي لها.

تبديل ملف معتمد ينشئ مسودة، ثم فحص اتصال، ثم تفعيل صريح. التفسيرات السابقة
تبقى مرتبطة بمزوّدها ونموذجها وملف قدراتها في الإيصالات؛ ولا يعاد تفسيرها
تلقائياً.

## ضمانات الاختبار

يشغّل `npm run verify:basira-provider-capabilities` اختباراً مستقلاً يثبت أن
النموذج المعتمد وحده قابل للإعداد، وأن النموذج الحر أو مزوداً بلا محوّل
مرفوضان، وأن كل مهارة لا تعمل إلا داخل نطاقها المعتمد.
