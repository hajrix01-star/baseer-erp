# ADR-OPS-003 — مطالبة تحديث إصدار واجهة Baseer مركزياً

**الحالة:** Active — 2026-09-05

## السياق

قد تبقى جلسة ERP مفتوحة أثناء نشر إصدار جديد. الملفات ذات أسماء hash لا تضمن أن المستخدم سيعيد تحميل `index.html`، لذلك قد تستمر واجهة قديمة في العمل.

## القرار

تضيف عملية بناء الويب علامة إصدار غير سرية إلى `index.html`. يقرأ مكوّن React مركزي هذه العلامة عند البداية، ثم يفحص HTML دوريًا بطلب `no-store` مع معامل cache-busting. عند اختلاف العلامة يظهر `BaseerDialog` صغير مع خيار تحديث الصفحة؛ لا يعيد التحميل تلقائيًا ولا يستخدم `alert` أو نافذة نظام أو Service Worker.

## البدائل المرفوضة

- **إعادة تحميل تلقائية:** قد تقطع نموذجًا أو عملية مالية غير محفوظة.
- **Service Worker مخصص للإصدار:** يزيد طبقة cache وحالات ترحيل غير ضرورية للهدف.
- **polling API جديد:** يوسع API وتشغيله من أجل معلومة build عامة يمكن أن تحملها الصفحة نفسها.

## الأثر والتراجع

القراءة عامة فقط ولا تتضمن أسرارًا أو تغيير جلسة. التراجع يحذف المكوّن وتحويل HTML في commit واحد؛ لا بيانات أو نشر خادم خاص به.
