# قرار منع تعطل مصدر السياق — 2026-08-21

## الحادث

كانت شاشة **مركز القرار والسياق** تعرض رسالة تحميل عامة رغم أن بقية قراءات القرار ناجحة. السبب الفعلي كان مسار `GET /v1/decision-intelligence/context/sources/health`:

- تعريف مصدر باحث السياق يجمع نوعين من البيانات: هوية المصدر التي تحفظ في `DecisionContextSource`، وإعدادات موصل وقت التشغيل مثل `allowedHosts` و`adapter`.
- عملية التسجيل نشرت كامل التعريف عبر spread إلى Prisma.
- جدول `DecisionContextSource` لا يملك — ولا ينبغي أن يملك — حقلي `allowedHosts` أو `adapter`؛ لذلك رمى Prisma `Unknown argument allowedHosts` وأعاد المسار 500 آمناً.

هذا ليس خللاً في بيانات المستخدم، ولا في المبيعات، ولا في تكرار قاعدة البيانات.

## القرار الدائم

1. تبقى إعدادات النقل والأمان (`allowedHosts`، نوع الـadapter، ومفاتيح متغيرات البيئة) مملوكة للكود فقط، ولا تحفظ في جدول مصادر القرار.
2. الدالة `sourceRecord` هي البوابة الوحيدة لتحويل تعريف باحث السياق إلى سجل `DecisionContextSource`. لا يسمح بتمرير تعريف الموصل كاملاً أو استخدام spread في عملية الحفظ.
3. يسجل اختبار سياسة السياق أن السجل الدائم لا يحتوي إلا على `sourceCode` و`displayNameAr` و`sourceUrl` و`scheduleCode`؛ إضافة إعداد تشغيل جديد إلى التعريف لا يجوز أن تعطل التسجيل أو تظهر كعمود قاعدة بيانات مفترض.
4. يسجل مرشح أخطاء API الآن ملخص الخطأ مع `correlationId` في الخادم، ويبقى رد العميل آمناً. كما يسجل interceptor حالة HTTP التي ستخرج فعلياً عند الاستثناء (500 بدلاً من 200 قبل مرشح الأخطاء).
5. لا تعالج هذه المشكلة بحذف بيانات أو إنشاء قاعدة جديدة. قبل أي تنظيف محتمل، يُقارن عدد السجلات بعدد المفاتيح المميزة (`tenantId + sourceCode`) داخل سياق المستأجر. التكرار الوحيد المقبول هو صفر.

## طريقة التشخيص المعتمدة لاحقاً

1. أعد إنتاج المشكلة من الشاشة المطلوبة.
2. طابق رسالة العميل مع `correlationId` في سجل API؛ لا تستنتج السبب من الرسالة العربية العامة.
3. تحقق من endpoint الذي فشل وحالة HTTP الحقيقية.
4. افحص تعريف Prisma ومهاجراته قبل تعديل أي بيانات.
5. أصلح حدود التحويل بين تعريفات الكود ونموذج قاعدة البيانات، ثم ابنِ API والويب وشغّل `npm run verify:decision-intelligence-foundation`.
6. أعد تحميل الشاشة وتحقق من عدم وجود رسالة خطأ ومن أن حالة جودة البيانات المعروضة متسقة مع التغطية.

## فحص قاعدة بيانات الاختبار في الحادث

عند الإغلاق، كانت قاعدة `baseer_erp_test` هي قاعدة Baseer الوحيدة في العنقود المحلي، ولم توجد مفاتيح مصادر مكررة داخل المستأجر المفحوص. ظهرت أربعة مصادر مميزة (مصدران للسياق العام ومصدران للبحث)، ولم توجد أقفال مجدول متروكة. لا يتضمن هذا القرار أي حذف أو دمج سجلات.
