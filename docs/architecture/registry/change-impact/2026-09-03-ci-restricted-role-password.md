# بطاقة الأثر — إصلاح إعداد دور CI المقيد

- **المعرف:** `BASEER-IMPACT-2026-09-03-CI-RESTRICTED-ROLE-PASSWORD`
- **التصنيف:** `ARCHITECTURAL` تحت `BASEER-ARCH v1.0` لأن التغيير يمس سلسلة التحقق والإصدار، لا عقد التطبيق أو بياناته.
- **الهدف:** إصلاح فشل GitHub CI عند تعيين كلمة مرور دور قاعدة الاختبار المقيد، كي تعود سلسلة المرشح والصور immutable قابلة للإثبات.
- **النطاق:** `scripts/prepare-ci-restricted-role.mjs` وسجل الحوكمة فقط.
- **خارج النطاق:** لا API أو واجهة أو Prisma schema أو migration أو بيانات حية أو إعداد Hostinger أو DNS.

## G0–G4

- **G0:** الفشل المثبت في CI للمرشح `4de05fd7` هو PostgreSQL `42601` عند `ALTER ROLE ... PASSWORD $1`. معيار القبول: ينجح إعداد الدور المقيد بلا كشف لكلمة المرور، ويبقى غير superuser ومن دون `BYPASSRLS`.
- **G1:** هذا مسار بناء CI لقاعدة PostgreSQL مؤقتة واحدة؛ لا يغير سعة الإنتاج أو حجم بياناته أو تشغيله.
- **G2:** لا يتغير مصدر حقيقة أعمال أو عقد API. يبقى إنشاء الدور والتحقق من امتيازاته داخل اتصال admin المؤقت في CI؛ دور التطبيق الناتج هو المقيد نفسه.
- **G3:** لا مكتبة جديدة. المسار المباشر هو استخدام `format('%I', ...)` و`format('%L', ...)` داخل PostgreSQL لتكوين أمر utility آمن لأن هذا النوع من الأوامر لا يدعم bind parameters.
- **G4:** لا أثر مرئي أو تغيير لغة/RTL أو مكوّنات.
