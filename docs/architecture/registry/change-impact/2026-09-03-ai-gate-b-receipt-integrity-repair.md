# بطاقة الأثر — إصلاح قيد سجلات مهارات الذكاء

- **المعرف:** `BASEER-IMPACT-2026-09-03-AI-GATE-B-RECEIPT-INTEGRITY-REPAIR`
- **التصنيف:** `CONTROLLED` تحت `BASEER-ARCH v1.0` وبطاقتي `marketing-decision-reports` و`platform-data-contracts`؛ التغيير قيد قاعدة بيانات تشغيلي يخص مصدر تدقيق الذكاء، بلا عقد API أو تجربة مستخدم جديدة.
- **المشكلة المثبتة:** قاعدة الاختبار تسجل ترحيل Gate B الأصلي كمطبق، لكن تعريف القيد الحي لا يتحقق من `skillKey` و`skillVersion` و`policyVersion`. لذلك يُقبل سجل مهارة ناقص ويُفشل فحص الإصدار.
- **القرار:** لا نحرر الترحيل المطبق. نضيف ترحيلاً لاحقاً يعيد إنشاء القيد نفسه بشرط صريح يمنع حالات NULL الجزئية ومفتاح المهارة الفارغ، مع إبقاء سجلات Gate A القديمة التي تكون حقول المهارة الثلاثة فيها فارغة جميعاً.

## البوابات والأثر

- **G0:** قبول السجل يتطلب إما حقول مهارة ثلاثية فارغة، أو مفتاحاً غير فارغ وإصدار مهارة وإصدار سياسة موجبة. السجل الجزئي أو المفتاح الفارغ مرفوضان من PostgreSQL.
- **G1:** ترحيل metadata فقط؛ لا قراءة واسعة ولا أثر سعة أو واجهة أو طلبات API.
- **G2:** يبقى تدقيق تنفيذ الذكاء ومصدر الحقيقة في الخادم وقاعدة البيانات؛ لا منطق تحقق عميل أو فتح صلاحيات.
- **G3–G4:** لا اعتماد أو مكوّن أو حركة جديدة.
- **G5–G7:** يطبق الترحيل حصراً على `baseer_erp_test` المحلية، ثم ينجح `verify:ai-gate-b-db` ويُعاد CI لإصدار صورة immutable. لا يطبق على Hostinger قبل نجاح الصور ومراجعة التسليم.

## التراجع

التراجع قبل النشر هو revert للـcommit وترحيل مقابل يعيد القيد السابق فقط إذا لزم. لا تحذف سجلات أو تعدلها يدوياً، ولا يمس هذا القرار Noorix أو DNS أو قاعدة إنتاجية حية.
