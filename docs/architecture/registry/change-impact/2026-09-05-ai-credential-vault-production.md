# BASEER-IMPACT-2026-09-05-AI-CREDENTIAL-VAULT-PRODUCTION

- **Registry:** `BASEER-ARCH v1.0`
- **Classification:** `ARCHITECTURAL`
- **Owner modules:** `platform-data-contracts`, `platform-identity-administration`, `marketing-decision-reports`
- **Existing decision:** `AI_PLATFORM_AND_COMPANY_IDENTITY_FOUNDATION_2026-08-15.md`; this is an operational correction, not a replacement ADR.

## G0 — الهدف والنطاق

يعالج هذا التغيير فشل حفظ إعداد مزود بصيرة في private-online عندما لا تصل
`AI_CREDENTIAL_ENCRYPTION_KEY` إلى حاوية API. يقبل المالك مفتاح OpenAI مرة
واحدة؛ تشفّره الخزنة خادمياً قبل أي كتابة، ولا يعاد المفتاح إلى المتصفح أو
السجلات أو الاستجابة.

النطاق: عقد Compose، قالب البيئة، preflight للنشر، وخطأ مالك دقيق وآمن عند
غياب خدمة تشفير الاعتماد. خارج النطاق: تغيير مفتاح OpenAI، schema أو migration
أو نموذج AI أو الأسعار أو الصلاحيات أو بيانات الشركات أو Noorix.

**معايير القبول:**

1. يرفض Compose/preflight بيئة private-online التي لا تحتوي مفتاح تشفير Base64
   صالحاً من 32 بايت.
2. يحصل API على المتغير بالاسم الذي تستخدمه `AiCredentialVault`.
3. يبقى الخطأ آمناً؛ لا تظهر قيمة سرية، لكن يرى المالك إجراءً صحيحاً بدلاً من
   رسالة حفظ عامة.
4. يبقى حفظ الإعداد idempotent، وتبقى كتابة الغلاف المشفر والتدقيق كما هي.

## G1 — السعة والاستمرارية

الرحلة الحرجة طلب إعداد واحد للمالك؛ لا تضيف قراءة أو جدولاً أو مهمة خلفية.
المفتاح سر تشغيلي ثابت لكل بيئة ويبقى في ملف بيئة الخادم فقط. فقدانه أو تغييره
بعد حفظ إعداد يجعل الغلاف السابق غير قابل للفك، لذلك لا توجد rotation تلقائية
ضمن هذه الشريحة. التراجع هو revert للـcommit مع إبقاء السر في بيئة الخادم؛ لا
يؤثر ذلك في بيانات الأعمال أو الأحجام أو التزامن.

## G2 — الحدود والعقود

- `AiCredentialVault` هو المالك الوحيد لتشفير وفك مفتاح المزود؛ لا ينتقل السر
  إلى عقد الويب أو السجل أو JSON التدقيق.
- Compose يمرر `AI_CREDENTIAL_ENCRYPTION_KEY` كمتغير مطلوب؛ preflight يتحقق من
  وجوده وصيغته فقط ولا يطبعه.
- غياب/فساد المفتاح حالة اعتماد تشغيلي غير متاح، لا فشل صامت أو حفظ جزئي.
- نموذج السعر والمعرف والصلاحية والمعاملة وقفل idempotency الحالية غير متأثرة.

## G3/G4 — التقنية والتجربة

لا مكتبة أو رصة جديدة. يستخدم الحل Docker Compose وNode crypto وNest وواجهة
الأخطاء الحالية. تظهر رسالة عربية/إنجليزية مخصصة للمالك على شاشة بصيرة؛ لا
مكوّن جديد ولا تغيير مسار أو سلوك جوال. التحقق: فحص preflight سلبي/إيجابي،
typecheck API/Web، وفحص عقود النشر/المعمارية.

## بوابات التنفيذ

- **G0–G4:** مكتملة للتنفيذ؛ المسار المباشر هو إصلاح عقد النشر نفسه بدلاً من
  تخزين مفتاح OpenAI في env أو إضعاف التشفير.
- **G5:** تعديل محدود واختبارات فشل/نجاح إعداد البيئة.
- **G8:** لا نشر حتى يراجع التسليم المرشح ويُضاف السر الحقيقي على Hostinger
  خارج المستودع.
