# بطاقة أثر — مرشح الفترة، إشعار الإصدار، وأيام الإغلاق المتعددة

**المعرف:** `BASEER-IMPACT-2026-09-05-FINANCE-PERIOD-RELEASE-PROMPT-DAY-OFF-BATCH`
**المرجع:** `BASEER-ARCH v1.0`
**التصنيف:** `ARCHITECTURAL`
**المالك:** Finance & Accounting، مع Web Platform للواجهة المركزية
**آخر تحقق قبل البناء:** `7cf16c3b`

## الهدف والنطاق

1. تحويل قائمة الالتزامات الدورية إلى سجل متجاوب قابل للقراءة، لا بطاقات مضغوطة على الجوال.
2. إظهار نافذة Baseer مركزية صغيرة عندما تكتشف الواجهة إصدارًا منشورًا أحدث، مع اختيار صريح لتحديث الصفحة.
3. جعل الخزائن تقرأ فترة الفلتر الحالية افتراضيًا (الشهر الحالي من اليوم الأول حتى تاريخ الأعمال)، مع إظهار رصيد الافتتاح وحركة الفترة ورصيد الإقفال بوضوح.
4. تمكين إغلاق نطاق متصل من أيام العمل بنفس السبب، مع سبب `EID`، في معاملة خادمية واحدة وسجل تدقيق لكل يوم.

## حدود الحقيقة والعقود

- `TreasuryService` وحده يحسب رصيد الافتتاح والإقفال وحركة الفترة من أرصدة دفتر الأستاذ اليومية/الشهرية؛ React لا يصفر أو يجمع رصيدًا.
- رصيد الافتتاح هو الرصيد الفعلي قبل بداية الفلتر؛ «الصفر من أول الشهر» يطبق على عدادات الوارد/الصادر وصافي حركة الفترة، لا على مسح رصيد تاريخي حقيقي.
- عقد `operational-calendar` يضاف إليه أمر نطاق صريح محدود (من/إلى شاملان، حد أقصى 31 يومًا) مع idempotency واحد ومعاملة واحدة. يرفض النطاق كله إن احتوى إغلاق مبيعات مرحّلًا أو فترة غير مفتوحة؛ لا توجد كتابة جزئية.
- كل يوم مغلق يبقى صف `FinanceOperationalDay` وتدقيقه الخاص. لا قيد أو خزينة أو مبلغ جديد ينشأ من الإغلاق.
- إشعار الإصدار قراءة عامة فقط: تبني Vite علامة إصدار في `index.html`، وتتحقق الواجهة دوريًا من HTML الجديد بـ`no-store` ثم تعرض `BaseerDialog`؛ لا Service Worker أو تنبيه نظام أو بيانات جلسة جديدة.

## قرارات G0–G4

- **المسار المباشر:** إعادة استخدام `BaseerPeriodFilter` و`BaseerDatePicker` و`BaseerCombobox` و`BaseerDialog`؛ لا حزمة جديدة ولا تقويم/نافذة محلية.
- **السعة:** أمر الأيام يغطي 1–31 يومًا فقط، وينفذ معاملة واحدة مع أقفال استشارية مرتبة لكل يوم؛ لا تحميل سجل تاريخي إلى المتصفح. فشل يوم واحد يوقف المعاملة كاملة.
- **الرقابة المحاسبية:** لا تعديل قيود أو أرصدة ولا تصفير اصطناعي. إقفال يوم ذو مبيعات POSTED يرفض مع توجيه لعكسها أولًا، كما في أمر اليوم الواحد الحالي.
- **اللغات/الإتاحة:** نصوص عربية وإنجليزية، RTL/LTR، تركيز الحوار المركزي، وإتاحة لوحة المفاتيح للاختيار والنطاق.
- **التراجع:** commit واحد يعيد الواجهة والعقد؛ لا migration ولا بيانات حية أو أسرار أو تغيير DNS.

## معايير القبول والتحقق

- الاستعلام الافتراضي للخزائن يرسل أول يوم من الشهر الحالي إلى تاريخ الأعمال، ولا تعرض الواجهة رصيدًا غير مرتبط بالفترة بلا تسمية.
- يعرض كل سجل خزينة الافتتاح، الوارد، الصادر، وصافي/إقفال الفترة من API؛ اختبار خادمي يثبت ذلك.
- إغلاق 2–31 يومًا لنطاق صحيح ينشئ أيامًا مغلقة متسقة؛ التكرار يعيد الإيصال نفسه؛ تعارض مبيعات/فترة لا يكتب أي يوم.
- يظهر سبب `EID` في الواجهة والسجل؛ selector مركزي وليس native select.
- عند اختلاف علامة الإصدار المنشور، تظهر نافذة Baseer واحدة مع زر إعادة تحميل، ولا تظهر عند الفشل الشبكي أو نفس الإصدار.
- تحقق نوع API/contracts/web، اختبارات finance المركزة، E2E جوال/سطح مكتب، وحراس architecture/dead-code/financial/localization قبل التسليم.
