# أثر تغيير كتالوج الصلاحيات واعتماداته — 2026-09-06

## التصنيف

`ARCHITECTURAL` — مصدر صلاحيات الأدوار وحدود الوصول الخادمية تتغير. المالك: Platform Identity & Administration، مع علاقات قراءة مقيدة إلى Finance وOperations وHR.

## القرار

- يبقى `ADMINISTRATION_PERMISSION_CATALOG` المصدر الوحيد للقدرات المعتمدة.
- يعرّف المصدر نفسه فرع العرض لكل قدرة وقائمة الاعتمادات اللازمة لها؛ لا تستنتج الواجهة صلاحيةً أمنية من الاسم أو من القسم.
- عند إنشاء أو تعديل دور، يوسّع الخادم الاختيار إلى اعتماداته بصورة انتقالية قبل حفظه. لذلك لا يصل دور محفوظ إلى تركيبة ناقصة مثل حركة مبيعات تحتاج قراءة الخزائن.
- تعرض الواجهة كل قدرة حالية ضمن قسم وفرع واضحين، وتضيف الاعتمادات تلقائياً وتمنع إزالة اعتماد ما دام مطلوباً.
- لا توجد migration ولا كتابة تلقائية على الأدوار القائمة؛ تُطبع الأدوار الحالية عند حفظ تعديلها فقط. ذلك يمنع توسعة وصول صامتة لأدوار لم يراجعها مالكها.

## خريطة الأثر

| المسار | المسؤولية |
|---|---|
| `apps/api/src/administration/administration-permissions.ts` | تعريف الفروع والاعتمادات والتحقق الانتقالي |
| `apps/api/src/administration/administration.service.ts` | تطبيع الحفظ وإخراج بيانات العرض |
| `packages/contracts/src/administration.ts` | عقد بيانات الفروع والاعتمادات |
| `apps/web/src/administration-roles-panel.tsx` | اختيار تلقائي وعرض كامل للكتالوج |

## حدود ثابتة

- التفويض النهائي وإضافة الاعتماد يتمان في الخادم؛ المتصفح يشرح الاختيار فقط.
- لا تتغير القيود أو المبالغ أو مصدر الحقيقة المالي.
- لا تمنح الاعتمادات صلاحية كتابة مالية إضافية؛ الاعتمادات الحالية هي قراءات مرجعية لازمة لرحلات الإدخال حيث ثبتت في المسارات الخادمية.
