# بطاقة الأثر — حارس قراءات العمليات

- **المعرف:** `BASEER-IMPACT-2026-09-03-OPERATIONS-READ-AUTHORIZATION-GUARD`
- **التصنيف:** `ARCHITECTURAL` تحت `BASEER-ARCH v1.0` لأنه يثبت حدود التفويض في مسار عمليات مشترك، مع أن التنفيذ لا يغير التطبيق.
- **الهدف:** مواءمة حارس اتساق الصلاحيات مع عقد controller الحالي: مساحة التنفيذ تطلب مجموعة القراءات اللازمة، بينما ملخصها المحدود لا يطلب وصول الكتالوج الذي لا يقرأه.
- **النطاق:** `scripts/check-authorization-consistency.mjs` وسجل الحوكمة فقط.
- **خارج النطاق:** لا تغيير في controller أو service أو catalogue الصلاحيات أو schema أو البيانات أو Hostinger/DNS.

## G0–G4

- **G0:** فشل CI المثبت كان assertion بصيغة قدرة منفردة رغم أن `workspace` يعتمد خمس قراءات مستقلة. معيار القبول: يفشل الحارس إن غابت أي قراءة لازمة أو استبدلت بـ`operations.catalog.manage`، ويفشل إن طلب `workspaceSummary` وصول كتالوج لا يقرأه.
- **G1:** فحص ساكن فقط، لا حمل أو بيانات أو أثر سعة.
- **G2:** مصدر الحقيقة يبقى `OperationsExecutionController` و`CompanyContextService`. لا تغير صلاحيات، بل يتحقق الحارس من أضيق صلاحيات القراءة الموجودة.
- **G3/G4:** لا مكتبة أو واجهة أو عقد API جديد.

## التحقق والتراجع

- **التحقق المطلوب:** ينجح `npm run check:authorization-consistency` محليًا ثم ضمن CI الكامل.
- **التراجع:** عكس commit الحارس؛ لا أثر على البيانات أو الإنتاج.
