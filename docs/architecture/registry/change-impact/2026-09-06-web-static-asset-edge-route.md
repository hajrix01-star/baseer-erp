# BASEER-IMPACT-2026-09-06-WEB-STATIC-ASSET-EDGE-ROUTE

- **Registry:** `BASEER-ARCH v1.0`
- **Classification:** `ARCHITECTURAL` (حد بوابة الإنتاج وملفات الواجهة العامة)
- **Decision:** `ADR-OPS-004-WEB-STATIC-ASSET-NAMESPACE.md`

## G0 — العقد والنطاق

**المشكلة المثبتة:** `GET /` يمر عبر Caddy ويعيد `200`، بينما ملفا JavaScript وCSS
المشار إليهما من نفس الصفحة تحت `/assets/*` يعيدان `404` مباشرة من nginx المشترك
من دون `Via: Caddy`. لا علاقة للمشكلة بـGoogle أو API أو قاعدة البيانات.

**القبول:** يحمّل `index.html` كل موارده من `/baseer-static/*`، وتوجد تلك الموارد
داخل حزمة الإنتاج، ويجتاز التطبيق الفحص الحي بعد النشر من الصفحة إلى JavaScript
وCSS. لا تعديل لـHostinger المشترك أو Noorix أو DNS أو أسرار أو بيانات حية.

## G1 — السعة والاستمرارية

لا تتغير كمية البيانات أو التزامن أو مسارات قاعدة البيانات. الرحلة الحرجة هي
تحميل shell الواجهة: صفحة واحدة وملف JavaScript وCSS بصمتين. الهدف أن يعيد كل
مورد `200` خلال مهلة الفحص الحالية؛ وإذا فشل المورد لا يعد نشر الواجهة سليماً.

## G2–G4 — المعمارية والتقنية والتجربة

المسار المباشر هو `assetsDir` في Vite بلا حزمة أو طبقة جديدة. لا توجد أرقام أعمال
أو حسابات في المتصفح. لا يتغير RTL/LTR أو مكونات التصميم أو رحلة المستخدم؛ يتبدل
فقط عنوان الملفات التي تطلبها الصفحة. يضاف حارس بناء بعد build ليثبت المسار ووجود
كل ملف مشار إليه.

## G5–G8 — دليل التنفيذ المطلوب

1. build للعقود والواجهة مع حارس ملفات الإنتاج.
2. فحص `git diff --check` وفحوص الواجهة المتأثرة.
3. PR أخضر ثم merge إلى `main` والنشر immutable القائم.
4. بعد النشر: `GET /` ثم كل JS/CSS المشار إليها من الصفحة يعيد `200` مع `Via: Caddy`.

**التراجع:** commit واحد؛ لا يستعمل ما دام edge يحجز `/assets/*`.
