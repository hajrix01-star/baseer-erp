# ADR-MKT-002 — الصفحات العامة القانونية لـGoogle OAuth

**الحالة:** Accepted for implementation — `2026-09-05`
**المرجع:** `BASEER-ARCH v1.0` / `BASEER-IMPACT-2026-09-05-GOOGLE-OAUTH-PUBLIC-LEGAL-PAGES`
**المالكون:** Marketing, Reports & Decision Intelligence؛ Platform Data & Operations

## السياق

يتطلب مسار اعتماد Google OAuth لهوية Baseer المنشورة صفحات خصوصية وشروط
استخدام قابلة للوصول علناً من نطاق Baseer. لا يجوز أن تجعل هذه الحاجة صفحة
عامة تسجل دخول المستخدم، أو تستدعي API محمية، أو تعرض أسرار Google أو بيانات
الشركات.

## القرار

1. يملك تطبيق الويب صفحتين ثابتتين مستقلتين على `/privacy` و`/terms` قبل
   مسار جلسة ERP. لا تقرآن `localStorage` أو الجلسة ولا تطلبان API.
2. تستخدم الصفحتان `BaseerBrand` وبطاقات التصميم المركزية القائمة؛ لا تعتمد
   مكتبة أو خطاً أو صورة أو analytics خارجياً.
3. ينشر النص العربي والإنجليزي من مصدر React واحد، مع تبديل لغة محلي غير دائم
   وRTL/LTR وإتاحة لوحة المفاتيح والجوال.
4. النص يصف حدود المنتج المعتمدة فقط: Google Business اختيار صريح، Ads قراءة
   فقط، وعدم نقل tokens القديمة أو نشر رد آلي بلا موافقة. لا يدّعي اعتماداً
   قانونياً أو تحققاً من Google قبل حصوله فعلاً.
5. لا يرسل طلب التحقق في Google ولا ينشر الصفحتين خارجياً ضمن هذه الشريحة.
   تتطلب مرحلة النشر جهة دعم قانونية معتمدة، وروابط حية على النطاق، ومراجعة
   مالك قبل الحفظ أو الإرسال.

## البدائل المستبعدة

| البديل | سبب الرفض |
| --- | --- |
| صفحة داخل ERP بعد تسجيل الدخول | لا تحقق متطلب الوصول العام من Google. |
| موقع أو منشئ صفحات خارجي | يضيف ملكية ونطاقاً وتحليلات/خصوصية غير لازمة. |
| نسخ OAuth client أو secret داخل الصفحة | يخرق حد الأسرار ويخلق سطح هجوم عام. |

## التحقق والتراجع

- الاختبار يثبت أن المسارين لا يعرضان نموذج الدخول ولا يستدعيان endpoint.
- يفحص العرض العربي/الإنجليزي وRTL/LTR والروابط ولوحة المفاتيح على سطح المكتب
  والجوال.
- التراجع commit واحد؛ لا توجد بيانات أو schema أو إعداد Google يتغير في هذه
  الشريحة.
