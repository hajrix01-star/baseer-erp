# ADR-OPS-004 — مساحة أسماء ملفات الواجهة العامة

- **الحالة:** Active
- **التاريخ:** 2026-09-06
- **المالك:** platform-data-contracts

## السياق

تبيّن في الإنتاج أن بوابة Hostinger المشتركة تعترض المسار العام `/assets/*`
قبل وصوله إلى Caddy الخاص بـBaseer. صفحة Baseer وواجهة API تمران إلى الحاويات
السليمة، لكن ملفات Vite الافتراضية تحت `/assets/*` تعود `404` من البوابة؛ وهذا
يظهر للمستخدم كشاشة بيضاء.

## القرار

تستخدم واجهة Baseer مساحة أسماء ثابتة خاصة بها هي `/baseer-static/*` لكل ملفات
Vite ذات الاسم المشتق من البصمة. لا يجوز إعادة `/assets/*` كمسار إنتاجي للواجهة
ما دام edge مشتركاً. يثبت حارس البناء أن كل ملف JavaScript وCSS يحيل إليه
`index.html` يبدأ بهذا المسار وموجود داخل `dist` قبل قبول المرشح.

لا تغير هذه القاعدة API أو البيانات أو الجلسات أو أسرار النشر، ولا تضيف مكتبة أو
خدمة أو مرحلة ربط. وهي المسار المباشر والأقل مخاطرة: تغيير نقطة نشر ملفات الواجهة
بدلاً من تعديل قواعد Hostinger المشتركة التي قد تخص تطبيقات أخرى.

## النتائج والتراجع

- تصل ملفات Baseer فقط عبر Caddy وحاوية `web` ضمن المسار غير المتعارض.
- يبقى `index.html` بلا تخزين طويل، بينما تظل الملفات ذات البصمة قابلة للتخزين
  الطويل كالمعتاد.
- التراجع ممكن بـcommit واحد إلى إعداد Vite السابق، لكنه غير مقبول ما دامت
  بوابة edge تحجز `/assets/*`.
