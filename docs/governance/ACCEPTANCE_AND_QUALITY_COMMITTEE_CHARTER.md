# BASEER ERP — لجنة الاستلام والجودة

**الاسم التشغيلي:** لجنة استلام بصير (Baseer Acceptance & Quality Council — BAQC)

**الغرض:** مراجعة مستقلة قبل تسليم أي نطاق، ومراجعات تشخيصية عند طلب المالك. اللجنة لا تبني الميزة التي تستلمها ولا تستبدل قرار المالك.

## اختصاص اللجنة

1. تتحقق من أن النطاق يطابق القرار وخطة البناء، لا مجرد أن الصفحة تعمل.
2. تراجع الدليل القابل لإعادة التشغيل: العقود، قاعدة البيانات، HTTP، الصلاحيات، العزل، الحسابات، والواجهة بحسب نوع النطاق.
3. تصدر قراراً واحداً مسجلاً: **Pass** أو **Conditional pass** أو **Return to build** أو **Blocked**.
4. تسجل المخالفات حسب P0/P1/P2، وشرط الإغلاق والمسؤول عنها.
5. لا تعطي موافقة إنتاج أو ترحيل أو أتمتة خارجية تلقائياً؛ لهذه قرارات وبوابات مستقلة.
6. تراجع كل أمر طباعة أو تصدير: مستند المحتوى فقط، هوية الشركة وشعارها عند توفره، الفترة/المرشحات، مصدر البيانات ووقت إنشائها، واتساق الأرقام مع اللقطة الخادمية.
7. تثبت لكل رقم ظاهر للمستخدم مصدره ونوعه: المال يأتي حصراً من قراءة خادمية متصالحة مع السجل المحاسبي وشجرة الحسابات؛ الرقم التشغيلي أو الخارجي يأتي من مصدره الرسمي الموسوم ولا يُعرض كرقم مالي.

## مسؤولية بناء سير العمل التالي

بعد كل استلام أو مراجعة تشخيصية، تصدر اللجنة **خطة الخطوة التالية المسموح بها** تتضمن:

1. النطاق التالي المقترح ولماذا هو الأعلى قيمة أو الأكثر أماناً الآن.
2. ما الذي يجب إغلاقه أولاً من P0/P1 أو قبول المالك.
3. الاعتماديات، مصدر الحقيقة، الصلاحيات، وعقد القراءة أو الكتابة المطلوب قبل بدء البناء.
4. تكوين لجنة الاستلام المطلوب لذلك النطاق وأدلة القبول التي ستثبت اكتماله.
5. البدائل التي تستحق دراسة قبل الالتزام.

اللجنة **توصي ولا تغيّر الأولوية تلقائياً**. يصبح المقترح نطاقاً نشطاً فقط عند تسجيله في `CURRENT_DELIVERY_AUTHORITY.md` وخطة البناء، أو بقرار مالك صريح.

| --- | --- | --- | --- |
| BAQC-01 | **منسق الاستلام والحوكمة** | يحدد نطاق الفحص، يراجع خريطة البناء والوثائق وسجل الأدلة، ويصدر القرار المجمع. | كل استلام ومراجعة. |
| BAQC-02 | **مراجع المنتج وسير العمل** | يقارن رحلة المستخدم بالقرار وبمرجع نوركس عند وجوده؛ يراجع الحالات الناقصة، التسميات، وألا تتحول الواجهة إلى مصدر حقيقة. | كل موديول أعمال وواجهة جديدة. |

| BAQC-05 | **مراجع الواجهة وإتاحة الاستخدام** | مكونات بصير المركزية، RTL/LTR، الجوال والكمبيوتر، لوحة المفاتيح وfocus، رسائل الخطأ، الخطوط والأرقام والفلترة، ونموذج الطباعة الذي يطبع المحتوى لا واجهة التطبيق. | كل Native UI أو تغيير تصميم أو قالب طباعة. |
| BAQC-06 | **مهندس الاختبار والإصدار** | يثبت البناء والفحوص، DB/HTTP/E2E المناسبة، ميزانية الطلبات، قابلية التكرار، ويمنع ادعاء نجاح بلا دليل؛ ويتحقق أن التصدير يأتي من لقطة خادمية ويُسجّل كأثر تدقيقي. | كل انتقال إلى Verification أو تسليم أو تصدير جديد. |
| BAQC-07 | **مدقق الذكاء والتكاملات** | عزل سياق الشركة، مصدر الحقائق والاقتباسات، prompt injection، التكلفة، kill switch، حفظ البيانات، وقيود الأتمتة. | فقط للذكاء، OCR، البريد، Telegram، Google أو أي موصل خارجي. |
| BAQC-08 | **مراجع البدائل والتحسين** | يسأل قبل الاستلام: هل هذا أفضل حل مناسب الآن؟ ما البديل التقني أو التشغيلي أو التصميمي الأقوى؟ لماذا لم نختره؟ وما شرط إعادة التقييم؟ يوثق الدليل والقرار دون مطاردة «الأحدث» بلا فائدة. | كل نطاق؛ مراجعة موسعة إلزامية للتغييرات المعمارية، المالية، الذكاء، التكاملات أو الاعتماديات الجديدة. |
| BAQC-09 | **مدقق نظافة الكود والالتزام بالمعايير** | يتحقق من تطبيق قواعد بصير المتفق عليها: حدود حجم وتعقيد الملفات، الفصل الصحيح للمسؤوليات، إعادة استخدام المكونات والعقود والتنسيق المركزي، منع التكرار وCSS المتضارب، حدود طلبات الواجهة، منع حساب المال في المتصفح، تنسيق الأرقام المركزي، وعدم تجاوز صلاحيات أو مسارات معتمدة. | كل تغيير كود قبل الاستلام؛ مراجعة معمقة عند مكونات مشتركة أو تعديل معماري. |
| BAQC-10 | **مدقق اللغة وبيانات العرض** | يثبت أن كل نص ظاهر للمستخدم يدعم العربية والإنجليزية من قاموس مركزي؛ يراجع RTL/LTR، رسائل الأخطاء والطباعة والتصدير، وأسماء الشركات والبنود والموردين والفئات والتصنيفات. يضمن أن الاسم المعروض قابل للترجمة بينما الكود والمعرّف والرقم المالي ثابتة ولا تتغير بالترجمة. | كل واجهة أو نموذج أو تقرير أو بيانات أساسية جديدة، وإلزامي قبل قبول المالك لأي قسم. |

## المهارات المهنية والتعلم المستمر

كل وكيل يراجع المصادر الأولية أو المرجع الموثوق عند وجود قرار جديد أو تغير محتمل، ثم يسجل الخلاصة والدليل في تقريره. لا يحوّل البحث إلى بناء أو اعتماد تلقائي.

| الوكيل | مهاراته ومراجعته المتخصصة |
| --- | --- |
| BAQC-01 | حوكمة النطاقات، إدارة المخاطر، تسلسل البناء، وتعريف أدلة القبول. |
| BAQC-02 | تحليل سير العمل، مقارنة نوركس والتطبيقات المشابهة، مقابلات احتياج المالك، وسيناريوهات الخطأ الواقعية. |
| BAQC-03 | المحاسبة المزدوجة، الضريبة والالتزامات، إقفال الفترة، ومعايير التقارير المالية المحلية عند الحاجة. |
| BAQC-04 | Nest/TypeScript/PostgreSQL/Prisma، RLS وRBAC، OWASP، المعاملات والتزامن والعقود الخادمية. |
| BAQC-05 | تصميم تطبيقات الأعمال، RTL/LTR، WCAG وإتاحة الاستخدام، الجوال والكمبيوتر، ومكتبة مكونات بصير. |
| BAQC-06 | اختبارات DB وHTTP وE2E، CI، قابلية الإعادة، قياس الأداء وميزانية الواجهة وإصدار آمن. |
| BAQC-07 | أمن الذكاء، التقييمات، tool guardrails، provenance، التكلفة والخصوصية، والموصلات الخارجية. |
| BAQC-08 | مقارنة البدائل والمكتبات والبنى التشغيلية، كلفة التملك، النضج، وقابلية الإلغاء أو الترحيل. |
| BAQC-09 | نظافة الكود، التصميم المعياري، حدود الملفات والطلبات، إعادة الاستخدام، واتساق المكونات والتنسيق. |
| BAQC-10 | الترجمة الاحترافية لتطبيقات الأعمال، إدارة مفاتيح النصوص، أسماء العرض ثنائية اللغة للبيانات الأساسية، RTL/LTR، واختبارات اللغة والطباعة والتصدير. |

**قاعدة البحث:** يبدأ الوكيل بالمصادر الرسمية والكود الفعلي ونوركس عند صلته. لا يعتمد على مدونة أو مثال تسويقي وحده، ولا يوصي بتقنية لمجرد أنها جديدة. يذكر ما تغير، صلته ببصير، وكلفة اعتماده.

**متى يبحثون؟** قبل قرار معماري أو مالي أو AI/تكامل؛ عند ظهور تقنية أو قاعدة متغيرة؛ أو عندما يطلب المالك مقارنة. أما الإصلاحات المحدودة فلا تتوقف على بحث موسع.

## تشكيل الفحص

- **الحد الأدنى:** BAQC-01 + BAQC-02 + BAQC-04 + BAQC-06.
- **فحص البدائل:** BAQC-08 يقدّم سؤال البديل المناسب في كل استلام؛ لا يؤخر إصلاحاً صغيراً، لكنه إلزامي كمراجعة موسعة عند تغيير معماري أو مالي أو مزود أو مكتبة أو نمط واجهة مركزي.
- **نظافة الكود:** BAQC-09 إلزامي في كل استلام برمجي. لا يكتفي بمرور build؛ يراجع الالتزام بالـrulebook، المكونات المركزية، حدود الملفات والطلبات، وعدم وجود منطق أعمال أو تنسيق مكرر في الواجهة.
- **النطاق المالي:** يضاف BAQC-03 ولا يسلّم بدونه.
- **واجهة للمستخدم:** يضاف BAQC-05 وBAQC-10 ولا يسلّم بدونهما.
- **طباعة أو تصدير:** يضاف BAQC-05 + BAQC-06؛ لا تقبل طباعة لقطة شاشة أو تصديراً من تجميع متصفح.
- **ذكاء أو تكامل خارجي:** يضاف BAQC-07 ولا يسلّم بدونه.
- يجوز أن يكون الوكيل خبيراً متخصصاً أو مراجعة مستقلة؛ لا يراجع المنفذ نفسه عمله كدليل وحيد.

## مخرجات الاستلام

كل تقرير يسجل في `QUALITY_EVIDENCE_AND_COMMITTEE_REGISTER.md` ويرتبط بملف تفصيلي عند الحاجة:

```text
النطاق والتاريخ:
أعضاء اللجنة المشاركون:
الدليل المفحوص:
القرار: Pass | Conditional pass | Return to build | Blocked
P0/P1/P2 وشرط الإغلاق:
خطة الخطوة التالية المسموح بها: النطاق | الاعتماديات | أدلة القبول | تكوين اللجنة:
المرحلة المسموح بها لاحقاً:
فحص البدائل: الحل المعتمد | البدائل التي فُحصت | سبب عدم اختيارها | شرط إعادة التقييم:
فحص مصدر الأرقام: الرقم المالي ← journal/tree/read model؛ الرقم التشغيلي أو الخارجي ← مصدره الموسوم/حداثته؛ منع خلطهما أو حسابهما في المتصفح:
فحص الالتزام بالكود: الملفات/المكونات/العقود/الطلبات/التنسيق المركزي | المخالفات | خطة العلاج:
قرار مطلوب من المالك (إن وجد):
```

## قواعد حاكمة

- لا يساوي نجاح TypeScript أو build قبول المنتج.
- لا تعلن اللجنة اكتمالاً مع غياب DB/HTTP/RBAC أو قبول المالك المطلوب.
- النتائج تحفظ كدليل تاريخي ولا تمحى؛ الحالة الحالية فقط تأتي من `CURRENT_DELIVERY_AUTHORITY.md` وسجل التسليم.
- المراجعة التشخيصية لا تغيّر الأولوية. أي تغيير في ترتيب البناء يسجل كقرار مالك صريح.
- لا يوصي BAQC-08 بتبديل تقنية لأن اسمها أحدث؛ يلزم منفعة قابلة للقياس، وكلفة تشغيل مقبولة، وعدم كسر مصدر الحقيقة أو العزل أو خطة البناء.
- BAQC-09 يطبق القواعد المكتوبة في `MODULE_DELIVERY_RULEBOOK.md` و`TECHNICAL_CONTRACTS_AND_QUALITY_STANDARD.md` ومعايير الواجهة؛ أي استثناء يلزم أن يكون محدوداً ومكتوباً مع سبب وتاريخ مراجعة.
- وكالة الذكاء لا تقر فتح مزود أو فعل خارجي؛ تثبت الجاهزية فقط وفق بوابته المعتمدة.
- لا يقبل BAQC-10 لغة إنجليزية في الغلاف فقط: العناوين، الحقول، الخيارات، الحالات، الأخطاء، الأزرار، الطباعة، التصدير والبيانات المرجعية يجب أن تكون ثنائية اللغة أو موسومة صراحة كبيانات ناقصة تحتاج ترجمة.

## العلاقة ببروتوكول التسليم

هذا الميثاق يفعّل قسم **Independent review control** في `DELIVERY_CONTROL_PROTOCOL.md`. بروتوكول التسليم يحدد متى يلزم الاستلام؛ هذه اللجنة تحدد من يفحص ماذا وكيف يوثق القرار.

### Bilingual data acceptance rule
- BAQC-10 rejects any English view that silently renders an Arabic-only master-data name as if it were translated. It must show the verified `nameEn` or a clear translation-pending state, and the owner must complete that data before English acceptance.
