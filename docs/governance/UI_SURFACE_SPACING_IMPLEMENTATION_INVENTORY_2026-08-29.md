# جرد تنفيذ توحيد الأسطح والمسافات

**المرجع:** [تقرير لجنة الواجهة](./UI_SURFACE_AND_SPACING_AUDIT_2026-08-29.md)  
**قرار النطاق المحدث:** تنفذ الأسطح والتبويبات والجداول والمسافات، وتستبدل صور خلفية الـLauncher بمستوى لون هادئ قابل للاختيار.

## 1. طبقات التعديل المركزية

| الطبقة | الموقع | العناصر | إجراء هذه الدفعة |
| --- | --- | --- | --- |
| Foundation | `apps/web/src/styles.css` | ألوان السطح، الحدود، الظلال، مسافات الصفحة والبطاقة والتحكم | إضافة أسماء دلالية متوافقة وربط البطاقة والجدول بها. |
| Card primitive | `styles.css` و`baseer-card.tsx` | `BaseerCard`، default، muted، compact | تثبيت سلم padding ومستويات السطح. |
| Data primitive | `styles.css` و`baseer-data-grid.tsx` | `BaseerDataGrid` و`DataTable` | توحيد سطح الجدول والرأس والصفوف ومسافة القراءة. |
| Tab pattern | `workspace-foundation.css` و`baseer-batch-layout.tsx` | `BaseerWorkspaceTabs` و`BaseerBatchPanel` | rail صلب هادئ ولوحة متصلة بالتبويب النشط. |
| Grid patterns | `workspace-foundation.css` | `baseer-card-grid` و`baseer-workspace` وmetric grids | ربط فجوات الشبكات بسلم القسم. |

## 3. عناصر لا تغيّر آلياً

| العنصر | السبب | شرط تغيير لاحق |
| --- | --- | --- |
| `attendance-pwa.css` | مسار حضور مستقل، لا صفحة ERP مكتبية. | مراجعة تجربة PWA منفصلة. |
| `owner-daily-brief-workspace.css` | تصميم مقصود كـ«ورقة/دفتر». | UI-ADR أو استثناء مسجل قبل التوحيد. |
| `workspace-legacy.css` | يضم أنماطاً تاريخية ووحدات عديدة. | ترحيل مقسم مع اختبار كل مسار؛ لا تعديل شامل بالنص. |
| صورة خلفية الـLauncher | استبدلت بخيارات ألوان مركزية. | يمكن إضافة لون مخصص لاحقاً إذا اقتضى القرار. |

## 4. بوابة القبول

1. TypeScript يمر بنجاح.
2. لا يتغير سلوك النماذج أو الجداول أو التبويبات.
3. اختبار بصري يدوي للمسارات ذات العناصر المعدلة بالعربية/الإنجليزية وعلى سطح المكتب والجوال.
4. تعرض قائمة المظهر ألوان الخلفية المعتمدة وتحفظ الاختيار لكل مستخدم.

## 5. سجل التنفيذ — 2026-08-29

تم تنفيذ الدفعة أولاً مع تثبيت الأسطح؛ ثم حُدّث قرار الخلفية إلى ألوان صلبة مركزية:

- أضيفت توكنات الأسطح والمسافات الدلالية في `styles.css`، ورُبطت بها `BaseerCard` و`BaseerDataTable` ومسافة الصفحة.
- حُوّل `BaseerWorkspaceTabs` و`BaseerBatchPanel` إلى rail ولوحة متصلين من أسطح النظام نفسها.
- نُقلت تبويبات الحضور والكتالوج وبطاقة الصنف إلى rail موحّد، مع توحيد النسخة المكررة من CSS الكتالوج.
- نُقلت حاويات أدوات الرواتب، بطاقات مؤشرات العمليات، رأس لوحة التقارير، ومساحة التسجيل الداخلي إلى سلم المسافات الجديد.
- التحقق المنفذ: `npm run check` مر بنجاح.

## 6. إغلاق المراجعة المستقلة الثانية

عولجت ملاحظات المراجعة المستقلة التالية قبل الإغلاق:

- نقل `BaseerStepper` من مسافات inline إلى مكوّن مركزي له rail ولوحة ومسطرة إجراءات دلالية.
- إزالة إعادة رسم صورة الـLauncher داخل toolbar التقارير؛ صورة الخلفية لم تعد تظهر داخل سطح بيانات التقرير.
- تثبيت أسطح وأعمدة رؤوس الجداول التشغيلية المحلية في مركز القيادة وPOS وإنشاء مسير الرواتب على `--surface-raised` و`--table-header`.
- أصبحت سلة التسجيل الداخلي، بما فيها محرر السطور، تستخدم سطحاً محايداً؛ تبقى قواعد legacy القديمة مغلَّفة بتجاوزات دقيقة كدين CSS غير وظيفي ولا تؤثر في الناتج المرئي.

أغلقت تجربة الخلفية: أزيلت صور الـLauncher من مساحة العمل والرأس، واستبدلت بست درجات محايدة مستوحاة من أنماط تطبيقات الإنتاج: ثلاث نهارية (`#f6f8fa` و`#fff` و`#f4f7f4`) وثلاث ليلية (`#0d1117` و`#22272e` و`#161b22`)، مع زر تطبيق وحفظ. تبقى `.module-page` شفافة عمداً كي يظهر اللون المختار الموحد في الفراغات، لا أي صورة.
