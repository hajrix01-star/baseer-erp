# بصيرة — بوابة التشغيل B وسجل التسليم

التاريخ: 2026-08-16
الحالة: مكتملة ومتحققة محلياً وعلى قاعدة Docker التجريبية. لا مزود حي ولا محادثة للمستخدم.

## ما تم بناؤه

- سجل مهارات مركزي مملوك للكود، بحالات `PLANNED` و`VALIDATED` و`PILOT` و`ACTIVE` و`SUSPENDED`، ومستويات أثر من S1 إلى S4.
- بوابة تشغيل خادمية لا تقبل إلا `moduleKey` و`skillKey` ومفتاح عدم التكرار. تستنتج المستأجر والشركة والمستخدم والصلاحية من الجلسة الحية؛ ولا تثق بالسياق المرسل من المتصفح.
- الصلاحية المستقلة `platform.ai.use`، مع إعادة التحقق عبر `CompanyContext` لكل قائمة مهارات أو طلب تمهيدي.
- إيصال تشغيل قابل للتدقيق يثبت المهارة وإصدارها وإصدار السياسة والمزوّد/الهوية إن وجدا، من دون حفظ prompt أو إجابة أو سر أو بيانات أعمال خامة.
- idempotency + AuditEvent لنفس العملية؛ الإعادة بنفس المفتاح تعيد الإيصال، والمفتاح نفسه مع محتوى مختلف يرفض.
- سجل مزوّدات offline فقط. لا يوجد فكّ للسر، اتصال شبكة، أداة قراءة، RAG، ملف، SQL حر، تنفيذ مالي أو رد Google في هذه المرحلة.
- عقدا API تقنيان فقط: `GET /v1/administration/ai/skills` و`POST /v1/administration/ai/runtime/preflight`. الطلب الثاني يعيد حالة `BLOCKED` عمداً، لتثبت حدود الحماية قبل تفعيل أي مزوّد.

## التحقق

- Prisma schema validation وclient generation نجحا.
- طبقة contracts، فحص TypeScript وbuild للـ API نجحت.
- `npm run check:permissions` و`npm run check:ai-gate-b` نجحا؛ الفحص الأخير يمنع وجود اتصال مزوّد أو فك تشفير في Gate B.
- migration `20260816200000_ai_gate_b_runtime_receipts` طُبق على قاعدة Docker التجريبية `baseer_erp_test` فقط، وحالتها up to date.
- `npm run verify:ai-gate-b-db` يتحقق من الأعمدة الجديدة وRLS/FORCE RLS وسجل Prisma migration.

## ما لا يزال ممنوعاً

لا Chat UI، ولا API key أو مزود حي، ولا conversation/memory، ولا tools، ولا RAG، ولا OCR، ولا نشر مراجعات Google، ولا قيد أو صرف أو تعديل بيانات من بصيرة.

## الخطوة التالية

يكمل مسار المستندات المالية للمشتريات والمصروفات والالتزامات، ثم read models مالية متصالحة مع Journal. عند وجود مصدر قراءة رسمي ومقاييس جاهزة، تفعّل مهارة واحدة على حدة عبر evaluations وقرار مالك منفصل.
