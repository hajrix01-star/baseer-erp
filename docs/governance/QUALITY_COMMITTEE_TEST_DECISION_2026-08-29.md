# قرار لجنة جودة الاختبارات — 2026-08-29

## النطاق

راجعت اللجنة تغطية الاختبارات المالية والأمنية والواجهة والتشغيلية قبل الاستلام. هذا القرار يحدد ما يدخل بوابة القبول الآن وما يبقى بوابة إطلاق مستقلة.

## القرارات المنفذة

1. **منع التكرار المالي المتزامن:** أضيف اختبار إلى `verify:finance-gate-b-db` يرسل عشر طلبات تحويل خزينة متطابقة بالتوازي. لا يمر الاختبار إلا إذا نتج قيد يومية واحد وسجل تدقيق واحد وإيصال idempotency واحد.
2. **سلامة ترحيلات قاعدة الاختبار:** أصبح الفحص السريع يتطلب تحقق checksum لسجل Prisma وحالة `prisma migrate status`، إلى جانب التحقق من عنوان قاعدة الاختبار.
3. **أمن جلسات المنصة:** أضيف `verify:platform-foundation` إلى الفحص الكامل؛ يغطي تدوير refresh token، رفض إعادة استخدامه، إبطال الجلسة، المصادقة وRBAC وعزل الشركات عبر HTTP.
4. **حماية تسجيل الدخول:** مدة قفل محاولات تسجيل الدخول أصبحت ثابتة 15 دقيقة في جميع البيئات، وتتحقق البوابة من `429` و`Retry-After: 900` للهوية ولعنوان الشبكة.

## قرارات مؤجلة عمداً

| البند | السبب | شرط الإغلاق |
|---|---|---|
| استعادة شركة كاملة من نسخة احتياطية | الموجود حالياً discovery/تحقق أرشيف، وليس استعادة بيانات تشغيلية كاملة | عامل restore إلى شركة جديدة فقط، ثم round-trip يطابق بيانات المالية والعلاقات وhashes |
| أداء وتحميل على بيانات كبيرة | لا يوجد benchmark موثوق أو بيئة بيانات حجمية معتمدة | بوابة staging تقيس p95 ومعدل الأخطاء للقراءات والتقارير الحرجة |
| Axe شامل لجميع الصفحات المحمية | الاختبارات الحالية تغطي shell ومسارات محددة، لكن ليس كل سطح تفاعلي | عينة عالية الاستخدام عربية/إنجليزية، سطح مكتب/جوال، ضمن Playwright |

## حالة قاعدة الاختبار الحالية

لا يجوز إخفاء عدم تطابق سجل Prisma عبر تعديل يدوي أو automatic recovery. عند ظهور اختلاف بين migrations المحلية وسجل قاعدة الاختبار، تعالج المشكلة بمراجعة مالك قاعدة البيانات قبل اعتماد الاستلام.
