# ADR-UI-003 — RHF/Zod لسبب إلغاء خدمة HR

**الحالة:** مقبول للتحقق المحلي ودمج المصدر فقط ضمن بوابات المكتبات الحالية

**التاريخ:** 2026-08-22

## القرار

يستخدم بصير `react-hook-form@7.86.0` و`@hookform/resolvers@5.9.1` و
`zod@4.4.3` خلف `BaseerRequiredTextareaForm` في حقل سبب إلغاء خدمة HR
المسودة فقط. ليس هذا نموذجاً مالياً ولا تفويضياً، ولا يغيّر API أو RLS.

يعرض الغلاف رسالة عربية/إنجليزية متسقة، ويعيد التركيز إلى الحقل المخطئ، ولا
يرسل أي طلب قبل تحقق السبب. يبقى الخادم هو مصدر التحقق النهائي للطلب وقواعد
إلغاء الخدمة.

## حدود الأداء والعزل

- يحمل الغلاف كسولاً عند فتح حوار الإلغاء، ولا يدخل مسار خدمات HR أو حزمة
  البدء. حد تفاعل النموذج `100,000 B`؛ القياس الفعلي `32,984 B`.
- لا تستخدم أي قيمة مالية أو `number`/float في هذا الـPilot.
- لا schema خادمية بديلة ولا كشف لرسائل خادم خام؛ قواعد API لا تتغير.
- لا يستعمل الغلاف في إلغاء تكلفة خدمة أو أي تدفق مالي.

## دليل القبول

- TypeScript، build وميزانية الويب تمر: حزمة البدء `243,938 / 250,000 B` وأكبر
  رحلة `84,443 / 85,000 B`.
- Playwright على سطح المكتب والجوال يثبت: رفض النص الفارغ، ظهور الخطأ، عودة
  التركيز، عدم إرسال POST قبل التصحيح، ثم إرسال الطلب بعد إدخال السبب.
- `npm audit --omit=dev --omit=optional` يعيد صفر findings.

## إعادة التقييم

يُعاد تقييم الغلاف قبل استعماله في نموذج متعدد الحقول أو عملية مالية. يوقف أو
يزال إذا كسر الإتاحة/اللغة أو تجاوز حد تفاعل النموذج.
