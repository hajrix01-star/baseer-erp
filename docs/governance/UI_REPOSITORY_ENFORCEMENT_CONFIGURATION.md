# تهيئة فرض حوكمة واجهة بصير

**الحالة:** جاهزة داخل المستودع، ولا تعد قبولاً نهائياً أو بديلاً عن اختبارات
التفاعل والبصر.

## ما يفرضه المستودع الآن

1. `check-ui-governance-registers.mjs` يتحقق من سجل المكونات والاستثناءات.
2. `check-ui-native-control-ratchet.mjs` يقرأ JSX عبر TypeScript AST ويمنع
   زيادة عناصر HTML التفاعلية الأصلية أو إضافتها في مصدر جديد خارج عقد مسجل.
3. `check-ui-inline-style-ratchet.mjs` يقرأ JSX عبر TypeScript AST وCSS عبر
   PostCSS AST. يمنع زيادة `style` المضمّن أو `z-index` في JSX/CSS، ويجعل
   إزالة الدين الفني تمر تلقائياً. لا يعتمد الحارس على regex.
4. تسير هذه الحراس في `verify.yml` قبل بناء الواجهة، مع السجل والميزانية
   واختبارات Playwright/Axe.
5. `CODEOWNERS` يحدد ملكية منصة الواجهة للتوكنات والعقود والسجلات والحراس
   وworkflow نفسه.

## ما لا يستطيع المستودع فرضه وحده

ملف `CODEOWNERS` لا يطلب مراجعة بذاته. قبل اعتباره فعالاً، ينفذ مالك المستودع
في GitHub الآتي:

1. إنشاء الفريقين الفعليين المطابقين لـ`@baseer-erp/ui-platform` و
   `@baseer-erp/engineering`، أو استبدال المعرّفات في `CODEOWNERS` بمعرّفات
   المستخدمين/الفرق الصحيحة في المنظمة. لا يجوز تخمين معرّف من هذا المستودع
   المحلي.
2. تفعيل branch protection أو ruleset لـ`main`/`master`: pull request إلزامي،
   ومراجعة Code Owner مطلوبة، ومنع bypass إلا لمدير الإصدار المصرح، واشتراط
   نجاح workflow **Verify BASEER ERP**.
3. منع تعديل/حذف workflow و`CODEOWNERS` من pull request غير مراجع، وتفعيل
   review حديث بعد أي push جديد إلى الفرع.
4. حفظ visual baselines في خدمة CI/artefact مستقرة بعد تعريف رحلات ذات بيانات
   ثابتة. لا ينشئ هذا المستودع ادعاء snapshot أو نجاح بصري قبل ذلك الدليل.

## بروتوكول تعديل سقف

رفع أو نقل قيد في `UI_NATIVE_CONTROL_RATCHET.json` أو
`UI_INLINE_STYLE_RATCHET.json` يحتاج UI-ADR مقبولاً، سبباً قابلاً للقياس،
وتحديثاً للسجل/الاستثناء عند اللزوم. يجب ألا يرفع نفس التغيير الميزانية أو يضيف
استثناء أداء من دون قياس مستقل، وفق المعيار الحاكم.
