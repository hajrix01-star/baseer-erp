# قرار لجنة مراجعة الموارد البشرية 360° — 2026-08-19

## القرار التنفيذي

حالة كود الموارد البشرية: **مكتمل بشروط نشر معلقة**.

حالة النشر في قاعدة البيانات المحلية الحالية: **No-Go**.

نجحت دورة الموظف والراتب والسلفة والمسير والمخالصة محاسبياً في اختبارات قاعدة البيانات، لكن لا يجوز فتح الوحدة في بيئة مماثلة للقاعدة المحلية قبل تطبيق عزل الصفوف وإعادة التحقق. كما تبقى مسارات عكس بعض العمليات المدفوعة نطاقاً محاسبياً غير منفذ، ولا يجوز تعويضها بتعديل قيود أو جداول يدوياً.

## أعضاء المراجعة ونطاقها

| المسار | ما تمت مراجعته |
| --- | --- |
| الواجهة وتجربة الاستخدام | بنية الصفحات والحوارات، RTL، التحميل الكسول، عدد الطلبات، الصور، حالات الخطأ، النماذج والطباعة |
| API والأمن والعقود | الصلاحيات، عزل الشركة، عقود Zod، idempotency، pagination، cursors، الملفات والمخرجات |
| المحاسبة والبيانات | القيود، التأريخ، الأقفال، السلف والخصومات، المسير، المخالصة، السداد والعكس والسجل المالي |

لم يضف هذا الإغلاق حضوراً أو انصرافاً، ولم يحرر أي قيد تاريخي مرحّل.

## ما أُغلق

1. إضافة FORCE RLS وسياسة المستأجر لكل جداول HR وعددها 28، مع فاحص يطابق Prisma بالترحيلات.
2. مطابقة عقود المخالصات والسلف مع القيم التي يكتبها الخادم، ومنع أخطاء 500 الناتجة عن اختلاف الـenum.
3. أقفال محاسبية موحدة للسلف والخصومات والمسير والمخالصة، مع رفض العمليات المتزامنة بأمان.
4. تأريخ محاسبي متسق: لا اعتماد أو سداد أو عكس بتاريخ يسبق المصدر، ولا إعادة كتابة لتاريخ رأس المسير.
5. عكس append-only للمسير والمخالصة غير المسددين، وإظهار تسويات السلفة الموجبة والسالبة في السجل المالي للموظف.
6. احترام موعد تحصيل السلفة أو الخصم المؤجل في معاينة المسير وإنشائه واعتماده.
7. حجب الراتب والتعويض وحركات الرواتب عن مستخدم `hr.employees.read` ما لم يملك `hr.payroll.read`.
8. ربط cursors بالفلاتر والشركة، وإضافة pagination لأسطر ودفعات تفاصيل المسير.
9. منع الملفات اليتيمة في إعادة إرسال مستند الموظف في المسارات العادية، مع cleanup عند rollback.
10. منع طباعة مسير DRAFT أو REVERSED من الخادم، والتحقق من UUID قبل Prisma.
11. تحويل نظرة HR إلى aggregate واحد بصلاحيات مستقلة وأعداد كاملة من قاعدة البيانات بدلاً من حسابها من أول صفحة.
12. تقليل طلبات ملف الموظف وتحميل تبويباته عند الحاجة، وتحميل الصور lazily مع cache وحد أقصى لأربعة طلبات متزامنة.
13. منع Escape من إغلاق الحوار الداخلي والخارجي معاً، وفصل نجاح الحفظ عن فشل تحديث العرض لمنع تكرار الإنشاء.
14. فصل router الخاص بـHR؛ انخفضت رحلة الخدمات من 126,502 بايت إلى 52,803 بايت، وأصبحت أكبر رحلة JavaScript 76,074 بايت تحت حد 85,000.

## أدلة القبول الناجحة

- فحص وبناء `contracts` و`api` و`web`.
- `check:architecture` و`check:permissions` و`check:web-localization`.
- `check:web-financial-boundaries` و`check:web-dialog-conventions`.
- `check:hr-rls`: تطابق 28/28 جدولاً في كود الترحيل.
- اختبارات منصة المخرجات: 6/6، وتشمل A4 العمودي وكشوف التوقيع الثنائية.
- Web E2E: خمسة ناجحة وواحدة متجاوزة حسب إعداد البيئة.
- `verify:hr-lifecycle`: نجح على قاعدة البيانات ويغطي onboarding، replay، السلفة، التأجيل، المسير، الاعتماد، السداد، العكس، المخالصة، الحركات المالية وتوازن القيود.

## موانع النشر

### P0 — عزل قاعدة البيانات غير مطبق

الترحيلان التاليان pending في القاعدة المحلية:

1. `20260819203000_supplier_due_payment_display_numbers`
2. `20260819204000_hr_tenant_rls`

وبالفحص المباشر كانت جداول HR كلها 28/28 بلا `relrowsecurity` أو policies. لا يطبق ترحيل RLS منفرداً متجاوزاً الترتيب. يلزم تطبيق السلسلة بهوية migrator ثم إعادة تشغيل دورة HR تحت FORCE RLS قبل أي نشر.

### P1 — مسارات التصحيح بعد السداد

لا توجد بعد أوامر منشورة ومتكاملة لعكس:

- إصدار سلفة خاطئ بعد ترحيل قيد صرفها.
- تكلفة خدمة موظف وقيد المصروف/الخروج المرتبط بها.
- دفعات مسير أو مخالصة بعد وجود payment history.

إلى أن تنفذ هذه الأوامر وتختبر، يجب إما استبعاد العمليات من الإطلاق المحاسبي أو تقييد صلاحياتها بقرار مخاطر صريح. يمنع التصحيح اليدوي في قاعدة البيانات.

### P1 مشترك — ميزانية CSS

نجحت ميزانية JavaScript الخاصة بالرحلات، لكن `verify:web-budget` ما زال يفشل لأن CSS الابتدائي العام 88,894 بايت مقابل حد 58,000. قواعد HR الصريحة في الملف العام لا تكفي وحدها لرد الحجم تحت الحد؛ السبب اقتران CSS القديم بين shell وDaily Sales وAdministration والمكونات المركزية. يحتاج ذلك refactor مشتركاً متعدد الوحدات، ولا يُحل برفع الحد شكلياً.

## آثار التحقق المحلية

أنشأت اختبارات دورة HR fixtures معزولة لا يستطيع دور التطبيق حذفها بسبب audit immutability. تنظيفها يتم فقط عبر reset لقاعدة الاختبار أو إجراء DBA مضبوط، وليس من التطبيق. تحذير `pg` الخاص بتزامن `client.query` غير حاجب حالياً لكنه يجب تنظيفه قبل ترقية pg الرئيسية التالية.
