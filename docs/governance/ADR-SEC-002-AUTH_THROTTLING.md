# ADR-SEC-002 — تقييد محاولات المصادقة

**الحالة:** تحقق محلي مكتمل؛ قبول الإنتاج مشروط بنسخة API واحدة أو مخزن
موزّع ذري قبل التوسع الأفقي.

يعتمد API `@nestjs/throttler@6.5.0` (MIT) لتقييد ثلاث نقاط حساسة فقط:

| المسار | حد عنوان الشبكة | حد هوية الدخول | نافذة/حظر |
| --- | --- | --- | --- |
| `POST /auth/sign-in` | 10 | 5 لكل login | 15 دقيقة |
| `POST /auth/owner/activate` | 5 | 3 لكل email | 15 دقيقة |
| `POST /auth/refresh` | 30 | 10 لكل refresh token | 15 دقيقة |

هوية الدخول تُطبع وتُحوّل إلى SHA-256 قبل أن تصبح tracker؛ لا تدخل كلمات
المرور أو رموز التفعيل أو refresh tokens إلى مفتاح التخزين أو السجل. يبقى
الرد متجانساً ولا يكشف وجود حساب. تسترجع استجابة `429` قيمة `Retry-After`
الحقيقية من الحارس، وتظهر القيمة نفسها في عقد API.

التخزين الحالي داخل ذاكرة API. لذا هو مسموح فقط مع **API replica واحدة**؛
إعادة التشغيل تصفر العدادات. قبل replica ثانية يلزم مخزن مشترك ذري، مفاتيح
وTTL موثقة، فحص proxy/IPv4/IPv6، واختبار يثبت الحظر عند عبور النسخ. لا
يغيّر ذلك Bearer auth أو CompanyContext أو RBAC/RLS أو أي حكم مالي.

تمت مراجعة اعتماد التشغيل بواسطة `npm audit --omit=dev --omit=optional`:
صفر ثغرات. يبقى advisory Prisma في صورة build/migrate مسجلاً منفصلاً ولا
تغطيه هذه الخطوة.
