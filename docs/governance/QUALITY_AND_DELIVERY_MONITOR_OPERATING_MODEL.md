# نموذج تشغيل مراقب الجودة ومراقب التسليم

**الحالة:** ساري للتخطيط والتحولات المستقبلية؛ لا يفعّل نطاق أعمال أو تغييراً برمجياً وحده.

**المراجع الحاكمة:** [سلطة التسليم الحالية](CURRENT_DELIVERY_AUTHORITY.md)، [بروتوكول التسليم](DELIVERY_CONTROL_PROTOCOL.md)، [لجنة الاستلام والجودة](ACCEPTANCE_AND_QUALITY_COMMITTEE_CHARTER.md)، و[خطة تحول المنصة](UI_PLATFORM_ADOPTION_AND_DASHBOARD_IMPLEMENTATION_PLAN_2026-08-22.md).

## 1. الغرض

يعمل مراقبا الجودة والتسليم كطبقة إنذار مبكر وتوثيق مستمر بين قرار المالك واستلام BAQC. هدفهما أن لا يبدأ عمل بلا نطاق، وألا ينتقل العمل بلا دليل قابل لإعادة التشغيل.

المراقبان لا يملكان صلاحية تفعيل نطاق، قبول المنتج أو الإنتاج، تثبيت اعتماد، دمج أو نشر، أو تجاوز P0/P1. القرار يبقى للمالك، والاستلام الرسمي يبقى للجنة BAQC.

## 2. التشغيل الحالي

الحالة الراهنة هي **نطاق تمكين عابر معتمد**: `Baseer UI Platform Enablement — Phase 0 baseline and one React Aria Combobox pilot`. هذا ليس نطاق أعمال جديداً، ولا يجيز لوحة مؤشرات أو ترحيلاً واسعاً أو تغييراً مالياً أو إنتاجاً.

يسمح للمراقبين بتوثيق النطاق، إنشاء baseline، مراجعة قرار التبعية، وتنفيذ pilot واحد غير مالي فقط بعد إغلاق بوابات Phase 0. لا يسمح لهما إضافة مكتبة أو بدء ترحيل واجهة ما دام baseline أو قرار الـlockfile أو مراجعة التبعية مفتوحاً.

## 3. الأدوار

| الدور | مهمته | ما يملكه | ما لا يملكه |
| --- | --- | --- | --- |
| مراقب التسليم (DM) | يطابق العمل مع النطاق والمرحلة والتبعيات والخطوة التالية | طلب دليل، وسم المخاطر، واقتراح Pass/Conditional/Return/Blocked | تغيير الأولوية أو منح تفويض أو قبول إنتاج |
| مراقب الجودة (QM) | يتحقق من الأدلة التقنية والأمنية والإتاحة والاختبارات | إيقاف انتقال مرحلة عند غياب دليل أو وجود P0/P1، وتصعيد الخطر | تعديل الكود أو قبول العمل منفرداً |
| منسق العمل | يجمع تقريري DM وQM ويستدعي المختص المناسب | تنظيم التقرير وسجل الأدلة وخطة العلاج | استبدال قرار المالك أو الاستلام المستقل |
| BAQC | يراجع ويصدر قرار الاستلام الرسمي | Pass / Conditional pass / Return to build / Blocked | بناء الميزة التي يستلمها |
| مالك بصير | يحدد الأولوية والنطاق ويقبل المخرج التجاري | تفويض النطاق والاستثناءات والقبول | تجاوز القيود القانونية/الأمنية أو الأدلة المطلوبة |

## 4. متى يستدعى المختصون

| الحالة | المختصون الإلزاميون |
| --- | --- |
| مكتبة واجهة أو مكوّن مركزي | BAQC-05 الإتاحة، BAQC-06 الاختبار والإصدار، BAQC-08 البدائل، BAQC-09 نظافة الكود، BAQC-10 اللغة والبيانات المعروضة |
| API أو صلاحيات أو عزل شركة | BAQC-04 الباكند والبيانات والأمن |
| مبلغ أو تقرير أو KPI مالي | BAQC-03 المالي، إضافة إلى BAQC-04 وBAQC-06 |
| لوحة مؤشرات أو cache أو read model | BAQC-02 المنتج، BAQC-04، BAQC-05، BAQC-06، BAQC-10؛ ويضاف BAQC-03 إن تضمنت مالاً |
| AI أو مزود أو تكامل خارجي | BAQC-07 الذكاء والتكاملات، وقرار خصوصية/مالك صريح |

## 5. دورة المراقبة

```text
تفويض مالك لنطاق واحد
  -> DM يثبت النطاق والمرحلة والتبعيات
  -> QM يثبت بوابات الجودة والمخاطر
  -> المختصون يراجعون ما يخص النطاق
  -> بناء/تحقق بأدلة قابلة للإعادة
  -> DM + QM يرفعان تقريراً موحداً
  -> BAQC يستلم أو يعيد العمل
  -> المالك يقبل المخرج التجاري عند اللزوم
```

لا تبدأ مرحلة التنفيذ ما لم يكن سطر سجل المراقبة كاملاً:

```text
Delivery ID / التاريخ:
النطاق النشط ونوعه: أعمال | تمكين عابر معتمد:
رابط تفويض المالك وتاريخه:
المرحلة: Discovery | Design | Backend | Native UI | Verification | Cutover:
المسموح والمستبعد صراحةً:
العقود ومصدر الحقيقة والشركة/الصلاحية المتأثرة:
التبعيات والإصدار وlockfile والترخيص وخطة الإزالة:
معيار الخروج والبوابة التالية:
المالك التنفيذي وBAQC المطلوب:
الحالة: Proposed | Authorized | In progress | Evidence pending | Returned | Blocked | Accepted:
```

## 6. بوابات مراقب الجودة

1. **البدء:** نطاق ومرحلة معلنان، لا P0/P1 مفتوح، مصدر حقيقة وصلاحية وعقد محددون.
2. **قبل الاعتماد:** سبب ومالك ونسخة دقيقة وترخيص وتبعيات عابرة وخطة إزالة، مع `package-lock.json` محدث وreview أمني.
3. **الأمن:** دليل headers وCSP وtrusted proxy حسب بيئة النشر، ولا tokens أو كلمات مرور أو PII في السجلات. حصص المصادقة وAI تختبر بـ429 و`Retry-After` صحيحين؛ in-memory throttling لا يسمح إلا مع API replica واحدة موثقة.
4. **الواجهة:** typecheck/build/budget، AR/EN وRTL/LTR، keyboard/focus، الجوال، reduced motion وaxe/Playwright. تستورد الشاشات مكوّن Baseer لا المكتبة مباشرة.
5. **البيانات والصلاحيات:** حالات allow وdeny للدور والشركة والمستأجر والجلسة المسحوبة؛ لا تفويض أو حساب مالي في المتصفح. كل KPI مالي له read model خادمي ومصدر وتاريخ `asOf` وتعريف versioned.
6. **النهاية:** ملفات وعقود وأوامر ونتائج وروابط أدلة، ومخاطر مفتوحة ومالكها وشرط الإغلاق، ثم قرار المرحلة التالية فقط.

## 7. بوابات مراقب التسليم

| الانتقال | الدليل المطلوب |
| --- | --- |
| Design إلى تنفيذ | تفويض مالك، سجل اعتماد أو ADR، baseline أخضر من الشجرة المعتمدة، خطة اختبار، لا P0/P1 |
| تنفيذ إلى Verification | ملفات وعقود دقيقة، build وbudget وlockfile، اختبارات normal/empty/error/retry/denied/cross-company، دليل RTL والجوال والإتاحة |
| Verification إلى Accepted | قرار BAQC مسجل وقبول المالك للمسار عند الحاجة؛ لا يعني ذلك إنتاجاً أو Noorix cutover |
| أي انتقال مالي | تطابق الرقم مع read model/دفتر خادمي، مراجعة BAQC-03، وعدم وجود حساب متصفح |

## 8. الإيقاف والتصعيد

**إيقاف فوري / Blocked:** نطاق غير مفوض، تناقض السجلات، P0 أو P1 مفتوح، فشل build أو budget أو دليل غير قابل للإعادة، تسرب tenant/company أو فشل RLS، رقم مالي بلا مصدر خادمي، تبعية بلا lockfile/ترخيص/مراجعة، أو API متعددة النسخ مع throttling ذاكرة.

**إعادة إلى البناء / Return to build:** غياب عقد أو اختبارات رفض أو إتاحة أو AR/EN/RTL، استيراد مباشر للمكتبة في الشاشة، primitive مكرر، أو إزالة القديم قبل تكافؤ المستهلكين.

**تصعيد للمالك:** تغيير الأولوية أو النطاق، استثناء معماري أو budget، SaaS أو egress، قرار CSP/HSTS/proxy، صلاحية حساسة، أو إنتاج/cutover. يسجل الاستثناء في `SCOPE_EXCEPTION_LOG.md` ولا يبدأ التنفيذ قبله.

**P2:** يسجل بمالك وتاريخ إغلاق؛ لا يمنع pilot معزولاً إلا إذا قررت BAQC خلاف ذلك، لكنه يمنع التسليم النهائي إن بقي مؤثراً.
