# ADR-UI-002 — React Aria لمنتقي تاريخ الإجازة

**الحالة:** مقبول للتحقق المحلي ودمج المصدر فقط ضمن الاستثناء الأمني الحالي

**التاريخ:** 2026-08-22
**المالك:** Baseer UI Platform Enablement

## القرار

يعتمد بصير `react-aria-components@1.20.0` مع
`@internationalized/date@3.12.3` خلف `BaseerAriaDatePicker`، كـPilot محدود
لحقول تاريخ بداية/نهاية الإجازة وتاريخ العودة في مساحة «الإجازات والعودة».

لا تستورد شاشة العمل المكتبة مباشرة. يظل عقد بصير هو قيمة Gregorian بصيغة
`YYYY-MM-DD`، وتبقى واجهة API والخادم مصدر التحقق النهائي. اللغة العربية تغير
النص والاتجاه فقط؛ يثبت الغلاف تقويم Gregorian صراحة ولا يبدل تاريخ العمل إلى
هجري أو إلى منطقة المتصفح.

## حدود التجربة

- الاستعمال محصور في نماذج الإجازة والعودة HR، ولا يشمل المالية أو تاريخ
  القيد أو تقارير الفترات.
- لا تغيير في API أو CompanyContext أو RLS أو الصلاحيات أو قواعد الإجازة.
- يحمل المكوّن كسولاً عند فتح النموذج؛ لا يدخل حزمة البدء أو مسار HR الأساسي.
- الحد المستقل لحزمة التفاعل هو `200,000 B` من دون رفع حد حزمة الرحلة العامة.
- لا React Spectrum أو theme أو CSS عالمي أو CDN أو إرسال بيانات خارجي.

## أدلة القبول

- TypeScript وbuild وميزانية الويب تمر؛ DatePicker interaction
  `138,018 / 200,000 B` وحزمة البدء `243,938 / 250,000 B`.
- Playwright يثبت العربية RTL والإنجليزية LTR، سطح المكتب والجوال، فتح
  التقويم، PageDown/Home/Enter، Escape، ووجود أجزاء التاريخ القابلة للوحة
  المفاتيح.
- فحص اعتماد التشغيل `npm audit --omit=dev --omit=optional` يعيد صفر findings.
  يبقى advisory Prisma/deepmerge في build/migrate P1 مفتوحاً، ولذلك لا يجيز هذا
  القرار إصداراً أو إنتاجاً.

## خطة الإزالة وإعادة التقييم

يزال الغلاف والتبعية إذا لم يحافظا على صيغة التاريخ أو فشلا في RTL/الإتاحة أو
تجاوزا الميزانية. يعاد تقييمه قبل أي استعمال خارج HR، وبقرار نطاق جديد قبل أي
تاريخ مالي أو business date.
