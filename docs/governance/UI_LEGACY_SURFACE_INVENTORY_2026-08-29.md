**التاريخ:** 2026-08-29  
**الحالة:** تدقيق شامل؛ لا يصرح هذا السجل بتعديل مرئي.  
**النطاق:** 270 ملف واجهة و41 ملف CSS في تطبيق الويب، مع فحص بحسب أقسام النظام.

## النتيجة التنفيذية

هناك عقدان متوازيان للسطوح:

| العقد | الرموز | السلوك |
| --- | --- | --- |
| القديم | `--surface`, `--canvas`، قيم `#fff`، وشفافية/تدرجات محلية | لا يتبدل مع اختيار أسلوب الحاوية. |
| المعتمد | `--app-canvas`, `--card-surface`, `--surface-raised`, `--surface-subtle`, `--table-header` | يتبدل مع اختيارات الثيم والحاوية. |

اختيار الحاوية في `styles.css` يغير العقد المعتمد فقط. لذلك أي حاوية رئيسية ما زالت تقرأ `--surface` أو `--canvas` تبقى بلون قديم. يتفاقم ذلك لأن `workspace-legacy.css` وملفات الأقسام المحملة كسلاسل lazy تصل بعد `styles.css`.

## عقد التصميم الواجب اعتماده

| الغرض | الرمز |
| --- | --- |
| خلفية مساحة العمل | `--app-canvas` |
| كرت أو حاوية رئيسية وجسم جدول ورسم | `--card-surface` |
| قسم داخلي هادئ أو شريط مرشحات | `--surface-subtle` |
| رأس جدول | `--table-header` |
| حقل إدخال أو popover | `--surface` أو رمز مستقل لسطح التحكم |
| حد | `--border-subtle` |

## معيار القبول

لكل صفحة وتبويبة: الوضع الفاتح والليلي × أساليب الحاوية white/soft/tinted/beige/gray × RTL/LTR. لا تظهر خلفية الصفحة داخل كرت/جدول/رسم، وكل سطح رئيسي يطابق `--card-surface`، مع فرق محدود ومقصود فقط لرأس الجدول والطبقات الداخلية والحالات الدلالية.
