# قرار حوكمة بصيرة وخطة تسليمها

**التاريخ:** 2026-08-24

**الحالة:** معتمد للتنفيذ المرحلي

**المالك:** مالك المنتج، مع لجنة قبول مشتركة بين المنتج والمالية والأمن والمعمارية
**النطاق:** منصة بصيرة المشتركة، لا أي موديول أعمال أو موصل خارجي جديد.

## القرار المختصر

**بصيرة مساعد واحد مركزي** باسم وهوية وسياسة سلامة موحدة على مستوى
المستأجر. لا نبني شخصيات مستقلة، ولا شبكة وكلاء، ولا محادثة عامة تملك
صلاحيات أو وصولاً إلى الجداول.

تظهر بصيرة للمستخدم بحسب المهمة فقط، مثل: «بصيرة تشرح التنبيه» أو «بصيرة
تحلل الحملة». هذا اسم مهارة مقيّدة، وليس شخصية جديدة أو مساعداً مستقلاً.

```text
هوية وسياسة بصيرة المركزية، مرقمة وغير قابلة للتجاوز
                         ↓
سياق شركة منظم ومعتمد ومنعزل
                         ↓
كتالوج مهارات مملوك للكود + تفعيل مقيد لكل شركة
                         ↓
حزمة أدلة خادمية مجمدة أو قراءة رسمية ضيقة
                         ↓
مزود ذكاء مقيد (عند تفعيل Pilot معتمد)
                         ↓
إيصال تنفيذ غير قابل للتعديل + تقييم بشري منظم
```

يبقى محرك الحساب، جودة البيانات، المقارنة، الصلاحيات، والفعل الخارجي خارج
النموذج. النموذج يفسر دليلاً محدوداً أو ينتج مسودة ضمن مهارة مسموحة فقط.

## ما يضبطه هذا القرار

يكمل هذا القرار، ولا يلغي،
[تأسيس منصة الذكاء وهوية الشركة](../architecture/AI_PLATFORM_AND_COMPANY_IDENTITY_FOUNDATION_2026-08-15.md)،
[بوابة جاهزية المهارات](AI_SKILL_READINESS_GATE_DECISION_2026-08-16.md)،
[قرار مركز القرار والسياق](../architecture/DECISION_INTELLIGENCE_AND_BASIRA_FOUNDATION_2026-08-21.md)،
و[تجربة شارح التنبيه](ADR_AI_001_BASIRA_DECISION_ALERT_INTERPRETER_PILOT.md).

عند اختلاف وثيقة سابقة مع هذا القرار في **حوكمة الهوية، سياق الشركة،
التفعيل، الذاكرة أو التعلم**، يتقدم هذا القرار. أما حدود الموديولات ومصادر
الحقيقة وسياسات Google والبريد والمالية فتظل مملوكة لقراراتها الخاصة.

## الحقيقة الحالية والحدود الصادقة

المتاح حالياً هو أساس المنصة: هوية نظام مرقمة، سياق شركة منظم ومعتمد،
كتالوج مهارات مملوك للكود، تفعيل مقيّد لكل شركة، إعداد مزود مشفر، بوابة
تشغيل خادمية، وإيصالات تشغيل وتقييمات append-only. كما توجد تجربتان S2
ضيقتان ومقفلتان خلف بوابات خادم صريحة: شرح تنبيه مركز القرار وشرح حملة
تسويقية. لا يعني وجودها أنها مفعلة؛ يتطلب كل منهما مزوداً معتمداً وتفعيل
الشركة والدليل الجاهز والبوابة البيئية.

لا يعني ذلك أن ما يلي موجود أو مفعل:

- لا توجد ذاكرة جلسة أو محادثة عامة أو RAG.
- لا يوجد تعلم ذاتي أو تدريب تلقائي من المحادثات أو التقييمات.
- لا يوجد حق لبصيرة في النشر أو الدفع أو الترحيل المالي أو إدارة Google أو
  أي فعل خارجي مباشر.

## نموذج الحوكمة المعتمد

### 1. هوية بصيرة المركزية

`AiSystemIdentity` هي المصدر الوحيد للاسم العربي والإنجليزي، اللغة
الافتراضية، النبرة، وقواعد السلامة غير القابلة للتفاوض. يملك مالك المستأجر
فقط إنشاء نسخة جديدة أو تفعيلها. لا يعدل أي تغيير نسخة تاريخية، وكل إيصال
يشير إلى نسخة الهوية المستخدمة.

لا يستطيع سياق الشركة تغيير اسم بصيرة أو إبطال قاعدة سلامة أو إضافة أمر
للنموذج. ولا تضع الواجهة حقلاً لـ«شخصية» أو Prompt حر.

### 2. سياق الشركة المنظم

يستبدل التوسع المستقبلي في `AiCompanyIdentity` النص الحر غير المقيد بسجل
**Basira Company Context** ذي عناصر منظمة ومرقمة. كل عنصر يحتوي، كحد أدنى:

- الشركة والمفتاح/النوع (`TERM`, `PRESENTATION_PREFERENCE`,
  `APPROVED_POLICY_REFERENCE`, `APPROVED_BUSINESS_CONTEXT`).
- القيمة المنظمة أو النص القصير المحدود، اللغة، ونطاق الموديول إن وجد.
- المرجع أو المصدر، من اعتمده، وقت الاعتماد، تاريخ الانتهاء وحالة الإلغاء.
- الإصدار ومعلومة التدقيق؛ التصحيح ينشئ نسخة لاحقة ولا يطمس السابقة.

المسموح هو مصطلح معتمد أو تفضيل عرض مثل «مختصر»، أو مرجع سياسة، أو سياق
ثابت وافق عليه مسؤول الشركة. والممنوع صراحةً: Prompt حر، تعليمات سلامة،
اسم بديل لبصيرة، أسرار، مفاتيح OAuth/API، IBAN، أرقام مالية متغيرة، محتوى
Gmail أو المرفقات، محتوى Google الخام، أو تعليمات تحاول تغيير الصلاحيات.

يُفرض `CompanyContext` وRLS والصلاحية الحية في كل قراءة أو تعديل. لا يوجد
توريث ولا نقل سياق أو ذاكرة بين الشركات.

### 3. كتالوج المهارات والتفعيل

المهارة كود وسياسة وعقد أدوات، وليست نص Prompt قابل للتحرير من العميل. لكل
مهارة مفتاح وإصدار وإصدار سياسة ومستوى أثر ومصادر مسموحة وصلاحيات مطلوبة
وأفعال ممنوعة واختبارات قبول عربية.

تبقى حالات الكتالوج:

`PLANNED → VALIDATED → PILOT → ACTIVE → SUSPENDED`.

ولا تعني حالة الكتالوج أنها متاحة لشركة بعينها. ينشأ سجل
`SkillActivation` مستقل ومؤرخ لكل شركة/مهارة/إصدار، ويحتوي المرحلة، حدود
الاستخدام، الموافق، سبب التفعيل أو الإيقاف، وفترة صلاحيته. لا يُتاح الطلب
إلا إذا كانت حالة الكتالوج وسجل الشركة وبوابة الخادم كلها تسمح به.

الإيقاف الفوري (`kill switch`) يوقف شركة أو مهارة أو مزوداً دون حذف الإيصالات
التاريخية. لا تسمح الواجهة بتغيير القواعد غير القابلة للتفاوض أو منح فعل S4
من خلال تفعيل مهارة.

### 4. الأدلة والإيصالات والتقييم

لا يرسل المتصفح prompt حر أو حقائق محسوبة إلى بصيرة. الخادم وحده ينشئ
قراءة رسمية ضيقة أو `DecisionEvidenceSnapshot` متجمد ويتحقق من بصمته قبل
الاتصال بالمزود. المدخلات النصية القادمة من بريد أو تقييم أو وصف تعامل
بيانات غير موثوقة لا تعليمات.

يمتد `AiExecutionReceipt` تدريجياً ليحمل، من دون أسرار أو النص الخام:

- معرّف حزمة الدليل إن وجدت، و`inputChecksum` و`outputChecksum`.
- مفتاح وإصدار المهارة والسياسة، وهوية بصيرة وسياق الشركة المستخدمين.
- المزوّد والموديل وإصدار الإعداد، حالة التنفيذ، التكلفة/الاستهلاك المسموح
  تسجيله، ومعرّف الارتباط والتوقيت.

الإيصالات append-only؛ لا تعدل إجابة تاريخية أو دليلها. التصحيح أو الإعادة
ينشئان إيصالاً جديداً مرجعياً. لا تحفظ سجلات التدقيق prompt كاملاً أو جواباً
كاملاً أو أي سر.

يُضاف `AiEvaluationFeedback` عام يربط التقييم بإيصال محدد، لا بكائن أعمال
فقط. يسمح بتصنيفات منظمة مثل: `USEFUL`، `NOT_APPLICABLE`،
`DATA_INCOMPLETE`، `UNFAIR_COMPARISON`، `CONTEXT_DIFFERENT`،
`MISLEADING`، مع ملاحظة اختيارية قصيرة. التقييم تحسين منضبط وإشارة تقييم؛
لا يدرّب النموذج تلقائياً ولا يغير سياسة أو مهارة قائمة.

### 5. المزود والخصوصية والتكلفة

حالة تكوين المزود المطلوبة هي:

`DRAFT → VALIDATED → ACTIVE → DISABLED`.

`VALIDATED` يعني نجاح فحص تقني محدود من الخادم دون جعل المهارات متاحة؛
`ACTIVE` يحتاج قرار خصوصية/منطقة/احتفاظ وتكلفة وموافقة صريحة. مفتاح مشفر
محفوظ وحده أو مزود Active وحده لا يكفي لتشغيل مهارة.

كل تشغيل يحتاج كذلك تفعيل مهارة الشركة، الصلاحيات، حد المستخدم، حد المزود
وبوابة بيئة مستقلة. لا تخرج الأسرار للمتصفح أو السجل أو AuditEvent. وتظل
الإجابة صالحة كشرح فقط عند فشل المزوّد: تعرض الواجهة حالة آمنة ولا تخترع
نتيجة.

## الذاكرة والمحادثة: قرار التأجيل

لا نبني الآن Chat عام أو تاريخ محادثات دائم أو retrieval/vector database.

الترتيب المعتمد لاحقاً هو:

1. **جلسة قصيرة العمر**: الشركة والشاشة والفترة الحالية فقط، ولا تملك
   صلاحية أوسع من الطلب الأصلي.
2. **سياق شركة معتمد**: السجل المنظم المذكور أعلاه، مع إصدار ومصدر وإلغاء.
3. **محادثة قابلة للحذف**: فقط بقرار مستقل؛ تشفير، احتفاظ افتراضي 30 يوماً،
   حذف وتصدير، وعزل شركة كامل.
4. **تعلم منضبط**: مجموعات تقييم وحالات اختبار راجعها بشر، ثم إصدار مهارة أو
   سياسة جديدة؛ لا تعلّم تلقائي ولا انتقال معرفة بين الشركات.

لا يدخل في الذاكرة الدائمة محتوى البريد أو مرفقاته، محتوى Google، بيانات
المالية الخام، الحسابات البنكية، الأسرار، أو محادثات مستخدمين غير معتمدة.

## خطة التنفيذ والبوابات

| المرحلة | التسليم | لا تتجاوزها قبل |
| --- | --- | --- |
| G0 — تثبيت القرار | هذا المرجع، مصفوفة الملكية، وسجل فجوات الواقع | اعتماد مالك المنتج والأمن والمعمارية |
| G1 — تقوية السجل | سياق شركة منظم وإصداري، امتداد الإيصال، وتقييم موحد | RLS، تدقيق، منع الحقول والنصوص المحظورة، ترحيل آمن |
| G2 — تفعيل المهارات | `SkillActivation`، مراحل Pilot/Active، حدود، موافقات وkill switch | اختبارات رفض التفعيل غير المخول وإيقاف فوري مدقق |
| G3 — حوكمة الواجهة | شاشة «حوكمة بصيرة»: الهوية، سياق الشركة، المهارات، التفعيل، الإيصالات والتقييمات | صلاحيات مالك/مدير/مدقق صحيحة ولا تظهر أسرار أو prompt حر |
| G4a — حاجز Offline | مجموعات عربية مملوكة للكود للمهارات المنفذة، فحص حقن التعليمات/النقص/السببية، وسجل append-only | لا يبدأ Pilot قبل اجتياز بصمة المجموعة المطابقة؛ صفر اتصال مزود |
| G4b — التقييم والاعتماد الحي | عينات مخرجات بشرية مراجَعة، Shadow محدود، مراجعة الكلفة | جودة موثقة لكل مهارة قبل Pilot أوسع أو `ACTIVE` |
| G5 — ذاكرة الجلسة | سياق طلب مؤقت ومحكوم فقط | عزل الشركة، انتهاء صلاحية، وعدم توسيع الصلاحية |
| G6 — لاحقاً فقط | محادثة دائمة أو ذاكرة/تعلم أوسع | قرار مالك وأمن مستقل، سياسة احتفاظ وحذف وتصدير واختبارات جديدة |

### تطبيق G3: مساحة واحدة للمالك ومدير الشركة

تظهر «حوكمة بصيرة» في صفحة الإدارة نفسها ولا تتفرع إلى واجهتين. يملك مدير الشركة السياق المنظم للشركة الحالية، وتفعيل/إيقاف مهاراتها، وقراءة الإيصالات والتقييمات وإضافتها. عندما يكون المستخدم أيضاً مالك النظام، تظهر له إعدادات مزود الذكاء المركزية في المكان نفسه. تظل المفاتيح والمزود المركزيان نطاقاً tenant-wide ولا ينتقلان إلى صلاحية مدير شركة عادي.

تظل أي مهارة موصل خارجي، وخصوصاً Google أو البريد، خاضعة أيضاً لقرار
الموصل الخاص بها. G1 إلى G4a لا تفعل اتصالاً خارجياً أو أتمتة أو نشر.
مسار تحليل مرفقات البريد S3 السابق الذي كان يتصل بالمزوّد مباشرة يبقى
معطلاً صراحةً إلى أن يهاجر إلى بوابة بصيرة الموحدة؛ لا يستطيع متغير بيئة
إعادة تفعيل هذا المسار الالتفافي.

**تنفيذ G4a:** تظهر «فحص الجاهزية» بجانب كل مهارة. الفحص يقرأ فقط حالات
تقييم عربية ثابتة من الكود، ولا يرسل بيانات شركة أو prompt أو طلباً إلى
المزوّد، ولا يحجز من الميزانية. يسجل `AiSkillEvaluationRun` نتيجته وبصمة
المجموعة؛ التفعيل التجريبي لا يمر إلا عند وجود نتيجة `PASSED` مطابقة لنفس
المهارة والإصدار والسياسة وبصمة المجموعة، مع بقاء بوابة الخادم المستقلة.
لا يساوي هذا فحص جودة جواب النموذج؛ ذلك جزء G4b.

## معايير القبول غير القابلة للتنازل

- لا تظهر شركة أو تستخدم أو تقيم سياقاً أو إيصالاً أو تفعيل مهارة لشركة
  أخرى؛ يثبت ذلك باختبارات RLS وCompanyContext وجلسة مسحوبة.
- لا تستطيع الواجهة أو المستخدم إدخال Prompt حر أو تغيير الاسم المركزي أو
  سياسة السلامة أو الصلاحيات أو الأفعال الممنوعة للمهارة.
- لا ينفذ تشغيل مزود من دون: مزود Active، بوابة خادم، تفعيل الشركة،
  الصلاحية الحية، دليل صالح إن كانت المهارة S2/S3، وحدود الاستخدام.
- لا يفتح التقييم أو الإيصال أو السياق سراً، رقماً مالياً خاماً أو محتوى
  بريد/Google غير مصرح به. لا يسجل `AuditEvent` النص الكامل للطلب أو الجواب.
- يعاد الطلب بالمفتاح نفسه بلا تنفيذ ثانٍ، ويُرفض مفتاح مكرر بحمولة مختلفة.
- تبقى الأدلة والإيصالات والتقييمات التاريخية قابلة للتدقيق بعد تغير
  المهارة أو الهوية أو السياق أو إيقاف المزود.
- تفشل المخرجات الآلية بأمان عند نقص الدليل أو فشل المزوّد أو انتهاء الحد؛
  ولا تصبح البيانات الناقصة صفراً ولا يتحول ارتباط زمني إلى سببية.
- تجتاز كل مهارة Pilot أمثلة عربية متوازنة وحالات نقص/تعارض بيانات واختبارات
  حقن التعليمات قبل أي توسع إلى `ACTIVE`.

## لجنة القبول وسجل القرار

تراجع كل بوابة لجنة تضم: مالك المنتج، معماري النظام، مسؤول أمن وخصوصية
الذكاء، مالك مصدر الحقيقة المتأثر (مالية/تسويق/وثائق)، ومراجع مستقل.
وتسجل اللجنة: النسخة، نطاق العينة، نتائج الاختبار، المخاطر المتبقية، قرار
القبول أو الرفض، وسبب أي استثناء.

لا تصبح حالة `ACTIVE` دليلاً على صحة قرار أعمال أو تفويض فعل خارجي؛ هي فقط
إتاحة مهارة محددة ضمن حدودها الموثقة.
