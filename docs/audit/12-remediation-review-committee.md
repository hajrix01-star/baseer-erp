# لجنة مراجعة الإصلاحات — تحقق مستقل وتوصيات

## التفويض والحكم العام

راجعت اللجنة الأدلة الحالية من ثلاثة مسارات مستقلة: التشغيل/التخزين، الواجهة/CI، وERP/الأمن/الأداء. النتيجة: **أغلب الملاحظات الجوهرية حقيقية، لكن بعض صياغة بوابة الإطلاق كانت أوسع من اللازم لتطبيق شخصي على خادم واحد.**

- التخزين المحلي على المضيف مناسب، ولا حاجة إلى S3 أو منصة مراقبة كبيرة أو Redis في هذه المرحلة.
- ما يلزم هو bind mount دائم، نسخة مستقلة، وتنبيه خفيف مثبت، لا SaaS أو إعادة تصميم.
- Hajri Tax يمكن أن تبقى ظاهرة؛ العيب المؤكد هو صفحة fallback الفارغة، ويكفي علاجها بصفحة «قيد البناء» بلا أفعال.
- أثر Playwright المحلي الحالي يقول `passed`، لذا صُحح التقرير السابق. لكنه بلا SHA أو تقرير حالات، فلا يثبت مرشح إصدار.
- لم يظهر خلل مالي أو رصيد مخزون فاسد مؤكد؛ قيود المخزون والتقارير وrate limiting هي تحسينات صلابة مع اختبارات مطلوبة، لا دليل حادث قائم.

## توصية اللجنة: بوابة إطلاق مبسطة للخادم الشخصي

لا تطلق قبل إغلاق البنود **1–11**، مع الشرط التالي للبند 6–8: إن كانت وظائف الملفات (الشعار أو HR) ضمن الإطلاق، فهي إلزامية؛ إن أوقفتها صراحة من الواجهة والخادم يمكن تأجيلها، لكن لا تبقها ظاهرة وتفشل. كذلك يلزم قبل الإطلاق حد تاريخ/صفحة مبدئي للتقارير وحد route-level للعمليات المكلفة (من 12 و13)؛ لا يلزم انتظار التحسين الكامل أو Redis.

البنود **12–16** تبدأ بعد ذلك مباشرة. لا يوصى بتأجيل حد نطاق التقارير أو rate limit للعمليات المكلفة إذا كانت لديك بيانات فعلية كبيرة أو مستخدمون متزامنون؛ أما Redis وGrafana وإعادة هيكلة واسعة فلا تعد متطلبات إطلاق لخادم API واحد.

البندان **17–18** تحسينات لاحقة ما لم يكشف اختبار أمني أو حمل واقعي عن سبب لتقديمهما.

## معايير قبول عملية مختصرة

1. CI أخضر لمرشح SHA نظيف، مع build وlocalization وbudget وdependency checks.
2. Hajri تعرض رسالة بناء واضحة، وBackup لا يقود إلى overview مضلل.
3. رفع شعار وملف HR ثم restart وتنزيل والتحقق من SHA-256؛ الملفات غير المفحوصة لا تنزّل.
4. استعادة DB والـbind mount على بيئة معزولة، مع مصالحة سجلات الملفات والتقارير الأساسية.
5. healthcheck وreadiness check وتنبيه واحد للمالك مثبتة.
6. E2E desktop/mobile وHTTP متعدد الأدوار وRLS/migrations ناجحة ومرفقة بالـSHA.

## ما تغير بعد الفحص

صححت اللجنة الادعاء السابق بشأن فشل آخر أثر Playwright: المحتوى الحالي لـ`apps/web/test-results/.last-run.json` يسجل `passed`. لا يغير ذلك بوابة الإطلاق لأن الأثر لا يحتوي على هوية commit أو عدد الحالات أو تقرير CI، لكنه يحول التوصيف الصحيح من «فشل حالي» إلى «نجاح محلي غير كافٍ كشهادة».
