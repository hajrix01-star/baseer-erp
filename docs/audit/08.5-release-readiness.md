# المرحلة 8.5 — جاهزية الإطلاق

## الخلاصة

القرار المحافظ هو **NO-GO**. البنية المالية ومنطق الصلاحيات يبدوان قويين من الفحص الساكن والاختبارات المحددة، لكن مرشح الإطلاق الحالي لا يملك شهادة تحقق قابلة للتكرار، ويفشل فحصَي التعريب وميزانية الويب، وتوجد فجوات إطلاق فعلية في تخزين الملفات، والنسخ الاحتياطي، والمراقبة، وعزل صفحتين غير مكتملتين.

## نطاق الوظائف الفعلي

يعرض سجل الصفحات 51 صفحة مرئية موزعة على Command (4)، Decision (6)، Marketing (5)، Inbound Evidence (3)، Operations (10)، Finance (5)، HR (7)، Reports (5)، وAdministration (6). يسجل الباكند 46 controller و310 مسارات HTTP، ويحتوي مخطط Prisma الحالي على 149 نموذجًا و116 migration. تفاصيل الخريطة في [02-codebase-map.md](02-codebase-map.md).

| الوحدة/الوظيفة | التصنيف | دليل الحالة | ملاحظة الإطلاق |
|---|---|---|---|
| الهوية: الدخول، تجديد الجلسة، تبديل الشركة، الإبطال | مكتملة لكن تحتاج تحقق | `apps/api/src/identity/*`؛ اختبارات الصلاحيات نجحت؛ لم تُنفذ اختبارات HTTP الحالية | لا إطلاق قبل نجاح دورة الدخول/التجديد/الخروج على مرشح نظيف |

## مسارات الأعمال الحرجة

| المسار | ما تحقق | الحالة الحالية |
|---|---|---|
| الدخول ← إصدار access/refresh ← اختيار الشركة ← الخروج | مراجعة الكود والتوقيت الآمن وتدوير refresh؛ فحص permissions نجح | غير قابل للتحقق تشغيليًا بسبب عدم تشغيل HTTP/DB، ومتغيرات CI القديمة تزيد الخطر |
| إنشاء مستخدم ← تعيين دور ← منع/سماح الوصول | 124 فحص permission نجحت؛ controllers تفرض رموزًا صريحة | يحتاج E2E أفقي/رأسي بأكثر من مستخدم وشركة |
| إدخال بيع/شراء ← قيد يومية ← تقرير/ضريبة | قيود توازن وتحصين immutable/reversal واختبارات policy محددة ناجحة | يحتاج قاعدة بيانات فعلية، وترحيلًا حاليًا، ومطابقة UI/API |
| طلب شراء/استلام ← حركة مخزون ← رصيد | أقفال ومعاملة ومنع الرصيد السالب في الخدمة | يحتاج اختبار تزامن؛ لا توجد CHECK DB كدفاع أخير |
| موظف ← استحقاقات/خصومات ← اعتماد راتب/دفع/عكس | مراجعة الخدمات وRLS واختبار EOS | يحتاج E2E وDB؛ رفع المستندات محجوب تشغيليًا |
| تشغيل تقرير ← snapshot ← تنزيل XLSX/CSV/PDF | اختبارات policy/output-platform نجحت | لم يُشغّل HTTP الحالي؛ التقارير الكبيرة قد تحمل كامل المدة في الذاكرة |
| رفع مستند HR/شعار/دليل Gmail | حدود حجم، magic MIME، تشفير، quarantine في الكود | **فاشل للإنتاج حاليًا**: قرار المالك هو تخزين أولي على المضيف نفسه عبر bind mount دائم؛ يلزم تنفيذه بمفاتيح وفاحص واختبار restart/restore |
| نسخ احتياطي ← استعادة ← تحقق ← rollback | runbooks موجودة وأثر rehearsal قديم وصناعي لـ12 جدولًا | **غير صالح كشهادة إطلاق** للمخطط الحالي ذي 149 نموذجًا ولا يشمل blobs |

## متطلبات الإنتاج التشغيلية

- HTTPS وCORS وheaders: Caddy يفرض TLS وHSTS وCSP وسياسات أمنية، والنمط المتوقع same-origin. **ناجح ساكنًا**.
- إدارة الأسرار: لا توجد قيم متتبعة مكشوفة، لكن أسماء أسرار CI لا تطابق أسماء runtime، ومفاتيح تشفير الملفات غير موثقة في مرشح compose. **فاشل**.
- رفع الملفات وحجم الطلب: هناك حدود حجم وفحص نوع وتشفير، لكن التخزين دائمًا غير موصول و`read_only` للـAPI. **فاشل**.
- Rate limiting: موجود للهوية وAI جزئيًا؛ لا يغطي التقارير والتصدير والرفع والتكاملات المكلفة بصورة موحدة. **فاشل جزئيًا**.
- الإدارة: API يفرض صلاحيات إدارة/مالك، لكن واجهة الصفحة الوهمية مرئية. **فاشل من ناحية عزل الوظيفة غير المكتملة**.
- السجلات والمراقبة والتنبيهات: JSON/health/metrics موجودة داخل العملية، ولا يوجد collector/alert receiver موثق أو مركب. **فاشل**.
- النسخ الاحتياطي والاستعادة: runbooks موجودة، ولا توجد شهادة حديثة كاملة للمخطط والملفات. التخزين الأولي على المضيف نفسه لا يحمي من فقد المضيف؛ يلزم نسخ مشفر على وسيط مستقل أو قبول خطر موثق. **فاشل**.
- migrations والرجوع: 116 migration وrunbooks موجودة؛ لا توجد rehearsal حالية أو rollback مثبت لهذا المرشح. **غير قابل للتحقق**.

## الاستنتاج

توجد نواة ERP قابلة للإصلاح وليست حالة إعادة بناء، لكن المخاطر الحالية تمس قابلية حفظ ملفات العمل واستعادتها، إمكانية مراقبة الأعطال، صلاحية مرشح CI، وتجربة المستخدم في صفحات معلنة وغير منفذة. لذلك لا يجوز طرح هذا commit للإنتاج قبل إغلاق شروط الحجب في [08.5-release-gate.md](08.5-release-gate.md).
